# Как написать эффективный CLAUDE.md

<!-- doc-map: reader=maintainer; zone=ide-and-skills -->

> Полный гайд на английском в [claude-md-guide.md](../en/claude-md-guide.md). Здесь приводится сокращённая версия.

## Золотые правила

1. **Краткость** — ≤200 строк, иначе CLAUDE.md перестанут читать
2. **Конкретные ограничения** — "max 400 lines per file" вместо "файлы должны быть короткими"
3. **Команды для копи-паста** — не пересказывай CLI-help, дай конкретные строки
4. **Hard vs Warning vs Instruction** — пометь каждое правило по уровню enforcement
5. **Без сценариев "если"** — пиши имеющиеся правила, не гипотетические

## Потолок — это бюджет, а не стена

У CLAUDE.md TAUSIK статическая часть ограничена 4096 байтами: файл грузится в контекст
каждый ход, и килобайт сверху — это примерно 250 токенов на ход, то есть 25 тысяч на смену
из ста ходов. Предел держит `tests/test_claude_md_size.py`.

**ЗАМЕР смены #277: свободно было 13 байт.** Ни один новый указатель не влезал, и потолок
молча превратился в запрет на любое дополнение — худший вид предела, потому что он не
отказывает, а просто не оставляет места, и следующий автор об этом узнаёт из падения теста.

Правило допуска, которое вернуло запас: **строка имеет право стоять в CLAUDE.md, только
если агент без неё сделает не то.** Справочная проза этого не меняет — справку несут
`--help` и сообщения об ошибках, и агент читает их в момент применения. Исключение —
заявление, которого требует стандарт: заявление о соответствии SENAR обязано стоять там,
где его увидит читатель, и его держит отдельный тест.

Убрано по этому правилу (246 байт, запас 13 → 254):

| Что | Почему не имеет права стоять |
|---|---|
| строка стека | каждое её утверждение сказано там, где применяется |
| список типов памяти | закрытый перечень, который CLI проверяет сам и сам называет в ошибке |
| блок из пяти команд | четыре строки повторяли ограничение выше, пятая есть в справочнике CLI |
| второй адрес контракта | один адрес называется один раз; полное описание — в Reference |

Ни одно жёсткое ограничение при этом не снято: список выделенных правил до и после
совпадает, девятнадцать в девятнадцать.

## Структура

```
# Project Name (1 line)

# Стек / Точка входа / БД / Тесты (≤5 lines)

## Принципы (≤10 строк)

## Ограничения (жёсткие, hard-enforced)

## Архитектура (краткое описание + где смотреть детали)

## Компакция (что обязано пережить сжатие контекста: задача и slug, scope и
## квитанция verify, замеры сессии, отменённые правила, запреты владельца,
## открытые развилки — шаблон bootstrap несёт готовый блок)

## Команды (только те, где `--help` пошлёт не туда — иначе указатель)

## Current State (DYNAMIC block, авто-обновляется)
```
