# Doctor — Health Check

`doctor` — единая команда, проверяющая подвижные части TAUSIK-инсталляции: venv, БД, MCP-серверы, скиллы, дрейф развёртывания, конфиг, гейты, сессию и гигиену бэклога. Она **не** автофиксит — говорит, что не так и как исправить.

Часть проверок выполняется, только если проверяемое установлено (конфиги Kilo и OpenCode), поэтому число строк в выводе зависит от вашей раскладки. В таблице ниже перечислены все проверки, которые могут появиться.

## Запуск

```bash
.tausik/tausik doctor
```

Или через MCP: `tausik_doctor` (без параметров). MCP-вариант возвращает те же данные структурированным объектом.

## Что проверяется

| Группа | Проверка | Pass-критерий |
|-------|----------|---------------|
| **venv** | Python virtualenv | `.tausik/venv/` существует и `python -V` запускается |
| **venv** | stdlib only | Сторонние пакеты не утекли в venv |
| **DB** | SQLite файл | `.tausik/tausik.db` существует, открывается |
| **DB** | Schema migration | Применена последняя миграция (соответствует `backend_migrations.py`) |
| **DB** | FTS5 индексы | Все FTS-таблицы присутствуют и query'абельны |
| **MCP** | Project server | `.claude/mcp/project/server.py` существует |
| **MCP** | Server can start | `python server.py --probe` возвращает success |
| **Skills** | Deployment | Skills присутствуют в `.claude/skills/` (количество) |
| **Skills** | Critical skills | core skills `start`, `end`, `task`, `plan`, `checkpoint`, `commit`, `explore`, `review`, `test`, `ship`, `debug` все на месте |
| **Drift** | Bootstrap freshness | Файлы в `.claude/` соответствуют генераторам в `harness/`/`bootstrap/`. Drift = устаревшая сгенерированная копия. |
| **Config** | Knobs | `session_max_minutes`, `session_warn_threshold_minutes`, `session_idle_threshold_minutes`, `session_capacity_calls`, `verify_cache_ttl_seconds` |
| **Gates** | Registered gates | Stack-detected + universal gates count |
| **Session** | Active vs wall | Если сессия открыта: `Xm active / Ym wall` (gap-based) |
| **Backlog** | Epic reachability | Каждая открытая задача (planning/active/blocked/review) достижима из эпика. Задача без story не видна ни `tausik roadmap`, ни `task list --epic` — то есть выпадает из подсчёта объёма релиза молча. WARN, не FAIL: standalone-задача законна. Закрытые задачи не считаются. |
| **Backlog** | Deferred AC | Ни одна закрытая задача внутри **ещё открытого** эпика не оставила критерий приёмки с пометкой `DEFERRED`. У такого критерия нет ни владельца, ни срока, а эпик может закрыться поверх него. Гасится либо выполнением критерия, либо передачей его задаче-владельцу с записью об этом: `tausik task log <slug> "AC-N CARRIED BY <owning-slug>"`. Область намеренно сужена до открытых эпиков — критерий, отложенный в давно отгруженном эпике, это история, а не работа. |
| **Hooks** | Commit hooks | Отличает ТРИ состояния `core.hooksPath`, а не два. Путь разрешает `pre-commit` — OK, значение печатается. Путь НЕ ЗАДАН — тоже OK, и намеренно: [hooks.md](hooks.md) предписывает такое состояние для CI-раннеров без mypy, а красное там научило бы читателя пропускать строку на каждой машине CI. Путь ЗАДАН, но `pre-commit` по нему не разрешается — WARN: git трактует ненайденный хук как отсутствующий, не исполняет ничего и МОЛЧИТ, поэтому `memory_route` (block), mypy и переиндекс RAG проходят мимо каждого коммита, пока `gates status` показывает гейты `[ON]`. Проверка ИЩЕТ файл хука, но не запускает его: диагностика, исполняющая то, что диагностирует, есть побочный эффект. |
| **Hooks** | Enforcement coverage | По каждому хосту — механизм реального времени, который bootstrap ФАКТИЧЕСКИ развернул в его профиле: команды хуков в `settings.json`, плагины в `plugins/`. Считается с диска, а не по таблице «какое правило где должно принуждаться». Замер смены #230: у claude и qwen по 23 команды хуков, у opencode 1 плагин, у cursor и kilo — ничего. Разрыв НЕ является предупреждением: он объявлен, и файл правил каждого хоста теперь открывается фразой о том, проверки перед вами или инструкции. WARN — это ПРОТИВОРЕЧИЕ: файл правил заявляет автоматическое принуждение, а в профиле механизма нет (это заявление несёт каждый файл, сгенерированный до 1.9, а такие файлы сохраняются как есть, и обычный перезапуск bootstrap их не заменит), либо файл отрицает принуждение, которое в профиле есть. Файл, который не говорит ни того, ни другого, не краснеет: молчание не является ложным утверждением. |
| **Session** | Session model | Какая модель ведёт открытую смену и КАКОЙ ИСТОЧНИК это сказал. Разрешается цепочкой: `TAUSIK_AGENT_MODEL` → переменные хоста (`CLAUDE_MODEL`, `ANTHROPIC_MODEL`, `OPENAI_MODEL`, `CURSOR_MODEL`) → провайдер хоста (`get_active_model`, у Claude Code читает расшифровку) → отсутствие. Замер смены #231: это не срабатывало НИ РАЗУ — 0 из 231 смены несли имя модели и 0 из 1560 задач несли пиннинг, потому что единственным источником было окружение, а Claude Code ни одной из этих переменных не экспортирует; в итоге пиннинг модели (RENAR 10.13), стоимость по моделям и метрики по моделям оставались пустыми. WARN, когда у открытой смены модели нет, с указанием `TAUSIK_AGENT_MODEL` как способа её объявить; отдельная формулировка — для смены, открытой раньше, чем появился источник. Модель НИКОГДА не выводится из имени хоста: Claude Code, направленный на другой endpoint, работает на модели того endpoint'а. |
| **Session** | Agent route | Как в этой смене обращались к фреймворку: вызовы через инструменты MCP против вызовов через оболочку, с долей MCP в процентах. Замер до появления этой строки (смена #233, 4011 команд оболочки): у 1216 из 1530 вызовов CLI MCP-двойник БЫЛ, и всё равно шла оболочка — 79.5%, — тогда как `MCP-first` заявлен жёстким ограничением и не считался никем. ПОРОГА НЕТ намеренно: у 20.5% вызовов CLI двойника не существует, цепочку (`verify && task done`) поверхность MCP выразить не может, а длинный многострочный аргумент действительно проще передать через `"$(cat file)"`. Предупреждение, срабатывающее на этом, читатель научится пропускать, а пропущенное предупреждение отнимает внимание у следующего настоящего. Строка сообщает; судит читатель. |
| **Drift** | CLAUDE.md drift | Секции, которые ваш `CLAUDE.md` несёт под **собственным** заголовком шаблона, всё ещё совпадают с шаблоном. Заголовок, которого в файле нет, — это кастомизация, а не дрейф: перевести, переименовать или убрать секцию есть намеренный выбор. Отсутствие секции всё же считается дрейфом, когда файл в остальном *и есть* документ шаблона (больше половины секций на месте), — так что проект, чей конфиг требует директиву, которой в `CLAUDE.md` нет, ловится как и раньше. Ремедиация называет разошедшиеся секции и никогда не советует перезапустить bootstrap, который затёр бы написанное вручную. |
| **Config** | Trust tier | Различает ТРИ состояния, а не два. Ничто не ослабляет enforcement — OK. Ключ проектного уровня ПЫТАЛСЯ ослабить и снят на чтении — WARN с именем ключа и применённым вместо него значением. Ключ, который ДОВЕРЕННЫЙ тир (`~/.tausik/config.json`, `$TAUSIK_MANAGED_CONFIG`) держит слабее дефолта фреймворка, — WARN с именем тира, путём до файла и причиной, записанной рядом с ключом. Третье состояние печаталось как первое: резолвер меряет кандидата ПО доверенным тирам, поэтому тир никогда не слабее самого себя, и строка OK читалась как «ослабления нет», пока пользовательский тир обходил подписанную квитанцию QG-2 во всех проектах машины разом. WARN и никогда FAIL: доверенный тир — слово владельца машины, и doctor обязан здесь видимостью, а не приговором. См. [config-trust-tiers.md](config-trust-tiers.md). |
| **Config** | Verify-First profile | `auto_verify` не включается молча на интерактивной машине. |
| **IDE** | Kilo / OpenCode config | Появляется, только если профиль этой IDE установлен: конфиг разбирается и его MCP-секция `tausik-project` резолвится. |

## Пример вывода

```
TAUSIK doctor — health check
========================================
  OK    Python venv               .tausik/venv
  OK    Project DB                .tausik/tausik.db (3136 KB)
  OK    MCP server (project)      .claude/mcp/project/server.py
  OK    Core skills               13 deployed (all critical present)
  WARN  Bootstrap drift           1 script(s) differ — restart MCP server or re-bootstrap
  OK    Config knobs              max=180m warn=150m idle=10m capacity=200 cache_ttl=600s
  OK    Quality gates             6 registered
  OK    Session                   10m active / 10m wall
========================================
WARN OK with 1 warning(s).
```

## Уровни статуса

| Уровень | Значение |
|-------|---------|
| `OK` | Проверка прошла |
| `WARN` | Не блокирует — работа продолжается, но рекомендуется починить |
| `FAIL` | Блокирует — TAUSIK не работает корректно до починки |

Exit code отражает худший уровень: `0` для OK/WARN, `1` для FAIL.

## Типичные починки

| Симптом | Починка |
|---------|---------|
| `FAIL Python venv` | `python -m venv .tausik/venv` (или ребутстрэп) |
| `FAIL Project DB` | Запустите `.tausik/tausik init`, чтобы создать БД |
| `WARN Bootstrap drift` | `python .tausik-lib/bootstrap/bootstrap.py --refresh` и рестарт MCP-сервера |
| `FAIL MCP server` | Ребутстрэп; убедитесь, что `.claude/mcp/` сгенерирован |
| `WARN Core skills` | `tausik skill list`; `tausik skill activate <name>` для отсутствующих core skills |
| `WARN Backlog hygiene` | `tausik task move <slug> <story>` для каждой названной задачи — либо создайте story под них, если они образуют связную группу |
| `WARN Commit hooks` | `git config core.hooksPath scripts/hooks` (dev-репозиторий) или `.tausik-lib/scripts/hooks` (проект-потребитель); либо `git config --unset core.hooksPath`, если хуки выключаются намеренно |
| `WARN Enforcement coverage` | Названный файл правил противоречит профилю своего хоста. Удалите этот файл и выполните `python .tausik-lib/bootstrap/bootstrap.py --ide all` — файлы правил сохраняются при наличии, поэтому устаревшая фраза переживает обычный перезапуск |
| `WARN Session model` | Выставьте `TAUSIK_AGENT_MODEL` в идентификатор модели, реально ведущей смену, — либо, если строка говорит, что модель уже доступна, закройте смену и откройте новую: модель записывается один раз, при открытии |

## Negative — что Doctor НЕ делает

- **Не** автофиксит. Каждая строка показывает, что не так; команду fix запускаете вы.
- **Не** валидирует корректность vendor skill'ов — только наличие.
- **Не** запускает quality gates (используйте `tausik gates status` / `tausik verify`).
