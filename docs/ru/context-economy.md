# Экономия контекста в 1.11

[English](../en/context-economy.md) | **Русский**

<!-- doc-map: reader=maintainer; zone=reference -->

TAUSIK разделяет короткий неизменный контракт и контекст конкретной задачи.
Новые проекты получают `context_tier: minimal`; существующие файлы правил не
перезаписываются без явной регенерации или ручной правки владельца.

Замер в этом репозитории 01.10.2026:

| Повторяемый источник | Было | Стало | Изменение |
|---|---:|---:|---:|
| Статическая часть корневого `AGENTS.md` | 17 078 Б | 4 602 Б | -73,1% |
| Контекст Claude SessionStart | 8 670 Б | 1 059 Б | -87,8% |
| Генерируемые правила (`standard` → измеренный `minimal`) | 15 533 Б | около 6 000 Б | около -61% |

Пакет задачи загружается один раз при начале работы. В нём есть цель, все AC,
нумерованные шаги плана, stack, scope путей и инструментов, rollback, бюджет вызовов, assurance route,
активные решения, нерешённые риски и выбранная память. Каждая запись памяти
несёт ограниченный inline-контент, revision, source hash и provenance; она не
заменяется одним идентификатором. Точный канонический размер UTF-8 включает
метаданные, а граница бюджета включительна.

Каждый start и resume полного профиля строит и проверяет пакет, включая обычные
CLI- и MCP-вызовы. `--package` выбирает структурированный ответ, но не включает
сам enforcement:

```bash
.tausik/tausik task start <slug> --package
```

Для MCP используется `tausik_task_start(slug=..., package=true)`. Раньше
успешный путь состоял из `task_start`, затем `task_show(package)`: два ответа
модели и два вызова инструмента. Теперь это один ответ и один вызов. QG-0,
снимок, revision compare-and-swap, byte-проверка, активация, сохранение пакета и
привязка lease выполняются в одной транзакции. Устойчивый победитель изменения
контракта или выбранной памяти между снимком и commit возвращает
`REVISION_CONFLICT`; одна повторная попытка строит пакет из победившего
состояния. Переполнение возвращает
`PACKAGE_TOO_LARGE` с размером, лимитом и подсказкой по декомпозиции. Оба отказа
оставляют задачу и lease без изменений.

Для восстановления или последующего обновления контекста используйте
`tausik_task_show` с `mode=package`; CLI:

```bash
.tausik/tausik task show <slug> --package --max-bytes 16384
```

Отпечаток меняется при изменении задачи, stack, scope путей/инструментов, риска,
плана, активных решений или revision выбранной памяти. Он привязан только к
execution lease потока, который выбрал задачу; co-active потоки сохраняют
независимые привязки. Устаревший отпечаток блокирует обычные мутации. MCP
`tausik_task_start` и CLI `task start` служат recovery-маршрутами: атомарно
перестраивают пакет и перепривязывают ровно один ещё живой lease; неудачная
привязка откатывает переход задачи. Связанные с задачей MCP- и CLI-мутации
обязаны назвать задачу своего потока. Renewal отказывает непривязанному lease,
пока есть активная работа, и сохраняет актуальную привязку при замене истёкшего
lease.
Привязанный к задаче lease не разрешает проектную pooled-верификацию
(`--tasks`, `--story`, `--epic` и MCP-маршруты cohort/hierarchy): для неё нужен
project-level lease, поэтому одна задача не может неявно разрешить записи от
имени других задач. CLI-классификация покрывает прямые и Python-entrypoint,
обычные shell-префиксы, включая `env` с отдельным значением опции, и обе формы
`--flag value` / `--flag=value`. CLI отклоняет сокращения длинных опций, поэтому
hook и argparse используют одну точную грамматику. Мутации review cohort
подчиняются тому же правилу project-level lease в CLI и MCP.
Сохранённый inline-контент читается и при недоступном relevance retrieval; при
чтении заново проверяются metadata, byte
count и fingerprint. Заменённые решения исключаются. Только complex-строка,
помеченная миграцией как legacy, получает compatibility defaults; новая complex
задача обязана явно объявить scope, rollback, assurance и call budget.

Нативные записи Codex `turn_context` в этой среде не содержат схем инструментов
или явного сигнала `tools_deferred`. Поэтому отложенная загрузка схем имеет
статус **unknown**; экономия от неё не заявляется.

Проект контролирует поверхность, которую объявляет его MCP-сервер. 02.10.2026
свежий stdio-процесс замерен до и после включения существующего проектного флага
`mcp.compact_tool_list`. В обоих замерах использован одинаковый ответ `tools/list`
из 147 инструментов в minified UTF-8 JSON; размер исходников и устаревший уже
запущенный MCP не учитывались.

| Источник в eager-контексте проекта | До | После | Изменение |
|---|---:|---:|---:|
| `AGENTS.md` | 7 518 Б | 7 518 Б | 0 Б |
| Канонический каталог skills (15 имён и описаний) | 1 249 Б | 1 249 Б | 0 Б |
| Имена MCP | 3 974 Б | 3 974 Б | 0 Б |
| Описания MCP | 17 722 Б | 11 897 Б | -5 825 Б |
| Схемы MCP | 32 134 Б | 17 145 Б | -14 989 Б |
| Структура MCP JSON | 736 Б | 736 Б | 0 Б |
| **Всего eager** | **63 333 Б** | **42 519 Б** | **-32,9%** |

Строки не пересекаются: фрагменты полей MCP и структура JSON складываются в
сериализованный список, `AGENTS.md` и каталог skills учтены по одному разу.
89 315 Б тел skills доступны по требованию и показаны отдельно, поэтому не
входят в eager-итог. Имена и короткие описания неядерных инструментов остаются
видимы; полные описания и схемы добираются по точному имени через
`tausik_tool_schema(name=...)`. Операции сессии, задачи, проверки, памяти,
поиска, doctor и восстановления сохраняют полные eager-определения. Этот
детерминированный замер сервера не меняет статус unknown для нативного учёта
схем Codex.

**Пустой `properties: {}` — дефект, если инструменту нужны аргументы.** На
Cursor и похожих хостах это читается как «параметров нет» и гоняет агента в
цикл `--help`. Неядерные инструменты нельзя «чинить» жадной отправкой всех
полных схем: это раздувает поверхность на каждый ход (~17× names-only против
full). Исправление — непустой stub (`additionalProperties: true`) плюс
`tausik_tool_schema(name=...)` по требованию; рост ограничивает храповик
`mcp_surface`.

Один вызов следует из общего навыка Codex, Claude и GLM. Экономия живой квоты
и повторов GLM остаётся незамеренной до release acceptance run; число
сэкономленных вызовов не пересчитывается в токены или лимит подписки. Сценарии
повторов и границы замера записаны в
[исследовании compound workflow 1.11](research/compound-workflow-111.md).

## Cursor: чужие MCP едят тот же план

В Cursor каждый включённый MCP-сервер (проектный `.cursor/mcp.json`, user MCP
или плагины) добавляет инструменты в advertise на ход. Стоимость сидит на
**том же** бюджете подписки Cursor, что и TAUSIK. Для сфокусированной работы
memory-only отключите лишний MCP в Settings → MCP или урежьте проектный файл —
не только `~/.cursor/mcp.json`. `tausik doctor` предупреждает о non-TAUSIK
серверах. TAUSIK не умеет мерить расход чужих MCP.

Метод раундов и правила честности playbook memory-only:
[базовый замер Cursor](cursor-economy-baseline.md).
