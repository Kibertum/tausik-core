# Две линии: где идёт разработка и что видит потребитель

Решение #267 (29.08): **GitLab — линия разработки, GitHub — зеркало релизов.**
Оно заменило формулировку от 25.08 («GitHub становится основным местом
разработки»), которая пять сессий подряд не исполнялась: ветки жили в GitLab,
и решение приведено к практике, а не практика к решению.

Эта страница существует потому, что до неё процедура публикации жила ТОЛЬКО в
решениях. Решение, которое исполняется памятью агента, а не механизмом, не
исполняется — и пять сессий тому подтверждение.

EN mirror: [`../en/publishing.md`](../en/publishing.md).

## Кто есть кто

| Линия | Что это | Что там лежит |
|---|---|---|
| `origin` — GitLab | Линия разработки | Полная история: ветки, волны, вся бухгалтерия проекта. Сюда идёт каждый push, и по каждому push собирается CI (быстрая лента на стадии `test`, полная — на `test-full`). |
| `github` — GitHub | Зеркало релизов | Только выпуски, СПЛЮЩЕННЫМИ снимками. Замер #189: 16 коммитов против 405 у `origin/main`. Общей истории у линий нет — `git merge-base` пуст, корни разные. |

Из этого следует одно практическое правило, которое стоит помнить дословно:
**`git push github v1-9-wave` — не синхронизация, а перенос 431 коммита
приватного архива в публичную линию.** Публикация есть акт над ДЕРЕВОМ, а не
над коммитом (решение #260).

## Порядок выкладки

1. Релиз собирается и закрывается на линии разработки (GitLab).
2. Публикация идёт **fast-forward-ребёнком** поверх подтверждённой публичной
   головы, построенным `commit-tree` над деревом релиза. Force запрещён
   файрволом и не является запасным вариантом.
3. Авторство внешних вкладов сохраняется: 1.9 ложится на `main` мержем
   `release/1.9` либо squash-ом с `Co-Authored-By` автора PR #5 — иначе
   авторство стирается.

## Предусловие: что публикуется вместе с деревом

Публикация выносит наружу ВСЁ отслеживаемое дерево, включая `tausik/` — папку
собственной бухгалтерии проекта. Поэтому перед выкладкой проверяется не «а не
забыли ли мы чего», а конкретные классы утечки, и проверяется машиной.

Замер смены #233 по 4208 отслеживаемым файлам (не по памяти сессии #180):

| Класс | Было (#180) | Сейчас | Статус |
|---|---|---|---|
| Локальный путь с именем пользователя | 12 файлов | **0** | вычищено, удерживается храповиком |
| Имена чужих проектов | 44 файла | **0** | вычищено, удерживается храповиком |
| Внутренний хост `gitlab.yumash.ru` | 17 файлов | 5 файлов, 8 вхождений | объявленный остаток, рост краснеет |
| Путь среды разработки вида `D:\Work` | не измерялся | 39 файлов, 81 вхождение | объявленный остаток, рост краснеет |

Два первых класса удерживаются на нуле: их возврат в отслеживаемый файл делает
`tests/test_publication_lines.py` красным. Два последних НЕ вычищены — они
слабее (раскрывают раскладку каталогов и адрес внутреннего сервера, а не
личность) и живут в основном в собственной бухгалтерии проекта. Их количество
зафиксировано, и рост тоже краснеет: разрыв объявлен, а не закрыт молча.

Файл, который ОПИСЫВАЕТ утечку — эта страница, задача о ней, решение, сам
тест, — утечкой не является. Иначе проверка запретила бы писать о проблеме,
что дороже самой проблемы.

## Чего эта страница не решает

Расхождение тегов между линиями. Замер #189: у одноимённых тегов РАЗНЫЕ
коммиты (`v1.8.0` — `623fb4ee` на GitHub против `3866702f` на origin), плюс
теги, существующие только на одной стороне. Это отдельная открытая задача
`tags-diverged-between-the-public-and-the-private-line`, и до её закрытия имя
тега не является общим адресом между линиями.
