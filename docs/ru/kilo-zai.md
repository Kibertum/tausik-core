# z.ai GLM в TAUSIK (Claude Code и Kilo)

<!-- doc-map: reader=user; zone=ide-and-skills -->

TAUSIK считает **z.ai GLM** семейством моделей, а программу, которая его запускает,
отдельным хостом. Профили маршрутизации переносимы как данные; enforcement и
доказательства расхода зависят от хоста. Поэтому Claude Code и Kilo проверяются
отдельно.

- **Хост** (ось-1) = Claude Code / Kilo / Cursor / Qwen — ему принадлежат каталог
  bootstrap, конфиг MCP и детекция активной модели.
- **Семейство моделей** (ось-2) = Claude vs z.ai GLM — чистые данные.
  Переключение/добавление GLM-моделей **не требует изменений кода**.

Anthropic-совместимый эндпоинт не делает транскрипт, гейты, квоту и стоимость другого
хоста идентичными Claude Code. TAUSIK заявляет только измеренные поверхности каждого
хоста.

> **Подписка, а не per-token.** Тариф z.ai **GLM Coding Plan** (от ~$10/мес) —
> это фиксированная подписка с квотами, а не поштучная оплата API. Тот же дух,
> что и Claude Code на плане Max/Pro: вы работаете по подписке, а не по метрам
> токенов.

### Доказательства расхода Kilo в 1.11

Kilo 7.8.1 предоставляет документированную локальную SQLite-базу сессий. TAUSIK
читает её только для чтения через `tausik metrics tokens --host kilo --json` или
MCP `tausik_metrics({"host":"kilo"})`. Обе поверхности используют одну реализацию,
устраняют повторы после resume и сверяют пять раздельных счётчиков Kilo с итогами
сессии. В очищенный проектный кэш не попадают промпты, ключи и исходные пути.

Отчёт фиксирует наблюдаемые версии Kilo, провайдера и модели. Квота подписки,
атрибуция к задаче и цена остаются неизвестными: источник их не отдаёт. Адаптер
сверен на реальных сессиях Kilo. Намеренный GLM-smoke дошёл до Kilo Gateway, но
завершился до генерации с HTTP 402; отчёт поэтому показывает одну ошибочную GLM-запись
и ноль завершённых GLM-ответов. Живая совместимость ждёт кредитов или настроенной
подписки z.ai.

---

## 1. GLM под Claude Code (рекомендуется — подписка, полные гейты)

Оставьте **Claude Code** хостом и направьте его на z.ai. Так как хост не меняется,
**все enforcement-гейты SENAR продолжают срабатывать** (QG-0 «нет кода без
задачи», QG-2 verify, scope / secret / firewall) — GLM просто становится мозгом.

Задайте две переменные окружения (профиль shell или хранилище секретов IDE —
**никогда** не коммитьте их):

```bash
export ANTHROPIC_BASE_URL="https://api.z.ai/api/anthropic"
export ANTHROPIC_AUTH_TOKEN="<ваш-ключ-z.ai>"   # ключ z.ai GLM Coding Plan
```

Запустите Claude Code. Теперь он рассуждает через GLM на вашей z.ai-подписке;
TAUSIK читает `model: glm-*` из транскрипта и маршрутизирует в рамках семейства
GLM (`model_profiles`, семейство `glm`). Чтобы рекомендовать GLM-тиры с первого
сообщения, задайте `"default_family": "glm"` в `.tausik/config.json` (см. §4).

> **Гигиена секретов:** ключ z.ai — это учётные данные. Держите его в профиле
> shell или хранилище секретов IDE — не в `.tausik/config.json`, `.kilo/` или
> чём-либо под git.

> **Проверьте биллинг перед тем, как полагаться на него (smoke-test).** z.ai
> продаёт Coding Plan против эндпоинта `/api/coding/paas/v4`; убедитесь, что квота
> Coding Plan реально списывается через Anthropic-совместимый эндпоинт
> `/api/anthropic` (отправьте один запрос, проверьте дашборд z.ai) — чтобы расход
> шёл с подписки, а не с pay-as-you-go кошелька. z.ai документирует Coding Plan
> для Claude Code, но зафиксируйте это заранее.

Kilo настраивает провайдера через собственную поверхность хоста; нельзя выводить
его активного провайдера из переменных Claude Code. Разделы ниже описывают
bootstrap и определение модели именно для Kilo.

## 2. Bootstrap TAUSIK для Kilo

```bash
python .tausik-lib/bootstrap/bootstrap.py --ide kilo
```

Записывает MCP-стансу TAUSIK в **оба** известных пути конфига Kilo (робастно к
версиям Kilo — Decision #120):

- `.kilo/kilo.jsonc` (актуальные доки kilo.ai)
- `.kilocode/mcp.json` (более старые сборки Cline-наследия)

Оба содержат одну и ту же запись `mcp`:

```json
{
  "mcp": {
    "tausik-project": {
      "type": "local",
      "command": [
        "<абс-путь>/.tausik/venv/Scripts/python.exe",
        "<абс-путь>/.kilo/mcp/project/server.py",
        "--project",
        "<абс-путь-проекта>"
      ],
      "enabled": true
    }
  }
}
```

Пути **абсолютные** (с прямой чертой). Измерено на живом хосте: Kilo Code 7.8.3
не раскрывает `${workspaceFolder}` в командах MCP — литерал не встречается ни
разу в его `kilo.exe` (процесс, который порождает серверы), поэтому прежний
генератор писал станзу, которая парсилась, но не могла заспавниться. Абсолютные
пути — прецедент Codex: переименование папки проекта требует повторного
bootstrap, а `tausik doctor` выполняет живую initialize-пробу по команде из
конфига, так что конфиг, который хост не может загрузить, будет сообщён, а не
предположен. Существующие серверы и другие ключи **сливаются**, а не
перезаписываются. Повторный запуск идемпотентен.

**Перезапустите Kilo** после bootstrap, чтобы он подхватил новый MCP-конфиг.

### Если ваша сборка Kilo не читает ни один из путей по умолчанию

Переопределите цель(и) в `.tausik/config.json`:

```json
{ "kilo": { "config_paths": ["kilo.jsonc"] } }
```

(пути относительны корню проекта; список полностью заменяет значения по умолчанию.)

## 3. Гейт QG-0 в реальном времени (плагин Kilo)

Тот же bootstrap кладёт **плагин-гейт** в `.kilo/plugins/tausik-gates.js`.
Kilo автоматически загружает этот каталог, так что файл и есть регистрация. Это
порт QG-0-плагина OpenCode (тот же вопрос к CLI, тот же кэш, те же политики):

- Перед каждым `write`/`edit`/`apply_patch` он спрашивает TAUSIK CLI, есть ли
  активная задача, и **отказывает в записи без неё** (SENAR Rule 1).
- `bash` сознательно не гейтится — иначе блокировалась бы сама команда
  `tausik task start`. Rule 2 (scope) и секрет-скан здесь тоже не исполняются;
  у OpenCode-плагина то же самое, а строка enforcement coverage в
  `tausik doctor` — истина по каждому хосту.
- Вердикт CLI кэшируется по подписи TAUSIK БД (плюс небольшой TTL), и кэш
  может ошибаться только в сторону строгости: `task done` двигает WAL, так что
  закэшированное «разрешено» его не переживёт.
- Если CLI недоступен, гейт **открыто деградирует (fail-open loudly)** —
  каждая пропущенная запись печатает предупреждение `DEGRADED`, и записывается
  строка supervision-деградации. `TAUSIK_HOOK_FAIL_SECURE=1` переворачивает
  политику в блок; `TAUSIK_SKIP_HOOKS=1` выключает гейт (записывается как
  bypass).

Честный статус: гейт проверен юнит-тестами, исполняющими хук под Node
(`tests/test_host_gate_plugins.py`, оба хоста параметризованы), и `tausik
doctor` сообщает `kilo: 2 plugins` — но живой отказ внутри запущенной сессии
Kilo ещё нужно наблюдать одним рестартом хоста. До тех пор гейт развёрнут и
доказан на уровне харнесса, но не наблюдался вживую.

## 4. Сообщите TAUSIK активную GLM-модель

У Kilo нет JSONL-транскрипта в стиле Claude, поэтому второй плагин, который
кладёт TAUSIK, — `tausik-observe.js` — записывает модель, которую хост реально
исполняет: на каждом событии чата он сохраняет `{providerID, modelID}` хоста в
`.tausik/runtime/active_model.json` (только id моделей — без ключей и без
содержимого переписки). Вся цепочка, по порядку:

1. `.tausik/runtime/active_model.json` — пишется вживую плагином-наблюдателем,
   так что модель, выбранная в UI Kilo (z.ai, Ollama, LM Studio, что угодно),
   — это то, что видит TAUSIK;
2. переменная окружения `KILO_MODEL` — напр. `export KILO_MODEL=glm-4.7`;
3. поле `model` в `.kilo/kilo.jsonc` (JSONC-комментарии допустимы),
   `.kilocode/kilo.json` или `~/.config/kilo/kilo.jsonc`.

Каждое значение проходит одну и ту же токен-валидацию до записи, а схема v73
записывает вместе с сессией, КАКОЙ источник его назвал (`provider:kilo`, имя
env-переменной, …) — строка «Session model» в `tausik doctor` называет его.
Когда не отвечает ничто, ничто не выдумывается: у doctor остаётся его
предупреждение, и модель никогда не угадывается из имени хоста.

С записанной моделью `task start` показывает рекомендации GLM и корректные
вердикты «слабее/мощнее». Без неё рекомендации откатываются к
`model_profiles.default_family` (ниже), затем к Claude.

Честный статус: наблюдатель и вся цепочка проверены юнит-тестами
(`tests/test_kilo_observe_plugin.py`, `tests/test_providers.py` — включая
переменную `TAUSIK_AGENT_MODEL`, которую получает bash-инструмент), но живая
запись chat-события и shell-env инъекция внутри запущенной сессии Kilo ещё
нуждаются в одном рестарте хоста.

## 5. Переключение/добавление GLM-моделей — без кода

Значения по умолчанию из `scripts/model_profiles.py`:

| Ранг capability | GLM-модель |
|-----------------|------------|
| лёгкая (`haiku`) | `glm-4.5-air` |
| средняя (`sonnet`) | `glm-4.7` |
| сильная (`opus`) | `glm-4.7` |
| флагман (`fable`) | `glm-4.7` |

Переопределите/расширьте любой ранг — и закрепите GLM как семейство по умолчанию
— в `.tausik/config.json`:

```json
{
  "model_profiles": {
    "default_family": "glm",
    "families": {
      "glm": {
        "opus":  { "model": "glm-5.2", "display": "GLM-5.2" },
        "fable": { "model": "glm-5.2", "display": "GLM-5.2" }
      }
    }
  }
}
```

`default_family: "glm"` заставляет `task start` рекомендовать GLM-модели ещё до
детекции через транскрипт/`KILO_MODEL` — идеально, когда вы работаете только в
Kilo + z.ai.

Локальные семейства — тоже без кода. id моделей нормализуются до каждого
поиска: снимаются provider-префикс (`zai-coding-plan/glm-4.7`,
`ollama2/glm-4.5-air`) и хвостовой суффикс контекстного окна (`glm-4.7 [200k]`),
так что та же поставляемая таблица отвечает и для них. Имя, которого в таблице
нет, — тег, входящий в сам id (ollama-тег `:latest`), или чисто локальное имя —
одна запись в конфиге:

```json
{
  "model_profiles": {
    "families": {
      "glm": {
        "haiku": { "model": "ollama/glm-4.5-air:latest", "display": "GLM-4.5-Air (локальная)" }
      }
    }
  }
}
```

## 6. Permission-политика на уровне хоста (вторая точка расширения)

Схема конфига Kilo (`$schema: https://app.kilo.ai/config.json`) принимает ключ
`permission`: по-операционные `ask` / `allow` / `deny`, а операции
правильной формы (`edit`, `bash`, …) — объекты `{шаблон: действие}`. С
2026-10-08 `bootstrap --ide kilo` пишет управляемую политику рядом с
MCP-станзой — те же правила, которые TAUSIK заявляет прозой, теперь
отклоняет сам хост:

| Операция | Шаблон / охват | Действие | Почему |
|---|---|---|---|
| `edit` | `.tausik/tausik.db` | **deny** | БД принадлежит сервисному слою; прямая правка ломает то, что читают все инструменты |
| `edit` | `.kilo/plugins/*` | **deny** | артефакты принуждения управляются bootstrap; ручная правка — дрейф по определению |
| `bash` | `git push*` | **ask** | публикация покидает машину только со слова владельца (SENAR Rule 7) |
| `bash` | `sqlite3*` | **ask** | никакого сырого SQLite против БД проекта |
| `external_directory` | — | **deny** | агент работает внутри проекта (границы области, Rule 2) |

Семантика слияния — как у станзы `mcp`: ваши ключи и правила сохраняются,
управляемые ключи переписываются идемпотентно и выигрывают у пользовательского
значения на том же шаблоне (правило governance, которое вы можете назвать, —
то, которое файл обязан держать). Глобальный строковый
`permission: "ask"|"allow"|"deny"`, заданный вами, не трогается — строка не
несёт шаблонов, а ваш глобальный выбор ваш. Отключение:
`.tausik/config.json` → `{"kilo": {"permission_policy": false}}`.

Строка enforcement-coverage в `tausik doctor` считает это третьей формой —
`kilo: 2 plugins и 5 permission rules` — читая развёрнутый конфиг, а не список
намерений.

## Как это собирается вместе

```
Kilo Code (аддон/CLI)  ──MCP──▶  сервер tausik-project  (.kilo/kilo.jsonc | .kilocode/mcp.json)
        │
        ├── QG-0-плагин-гейт        (.kilo/plugins/tausik-gates.js) — отказ в записи без активной задачи
        │
        ├── плагин-наблюдатель      (.kilo/plugins/tausik-observe.js) — пишет .tausik/runtime/active_model.json
        │
        └── model: glm-4.7  ──▶  model_profiles (family=glm) ──▶ ранг маршрутизации → glm-модель + вердикт
```

Runtime — это Kilo; модель — это GLM. Они не знают друг о друге — именно это
разделение превращает «TAUSIK в Kilo на любой модели z.ai» в задачу настройки,
а не написания кода.
