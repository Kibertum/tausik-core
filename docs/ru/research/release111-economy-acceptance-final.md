# Приёмка экономики TAUSIK 1.11

Дата: 2026-10-02. Вердикт: **HOLD**.

Нельзя выпускать 1.11 с утверждением «TAUSIK больше не расходует недельный
лимит как пылесос». Доказано уменьшение повторяемого project-controlled prefix,
но ещё не доказано снижение стоимости принятой задачи при сохранённом качестве.

| Критерий | Факт | Вердикт |
|---|---:|---|
| Повторяемый prefix | 63 333 → 42 519 UTF-8 байт, −32,9% на той же поверхности из 147 tools | PASS |
| Три deterministic replay | retrieval и progress/close эквивалентны; verification rounds 18→19 теряют 80-pass preflight evidence | FAIL |
| Natural accepted tasks | замороженный cohort 99/50/46, median 50; два новых полных окна 58 и 61 rounds, третьего пока нет | FAIL |
| Default lane | 12 791 passed, 34 skipped, 143 deselected, 112,91 с | PASS |
| Slow lane | 143 passed, 12 826 deselected, 120,90 с | PASS |
| Запрещённые подмены | paid/synthetic run не запускался; baseline не реконструировался; model medians не объявлены причинным эффектом | PASS |

## Что отделяет от выпуска

1. `r111-verification-cycle-replay` должен либо сохранить оба результата одной
   compound-операцией, либо остаться явным отказом без заявления об экономии.
2. Нужны минимум три естественные принятые задачи после recovery wave со всеми
   попытками и median не выше 40 response rounds. Текущие 58 и 61 уже показывают,
   что одного уменьшения payload недостаточно: требуется сокращать сами возвраты
   модели и repair loops.

До выполнения обоих условий допустимое заявление 1.11 ограничено: «повторяемый
prefix уменьшен на 32,9%, package/start/verify payload ограничены, полные
default/slow проверки сохранены». Заявление о ≥30% экономии недельного лимита
или стоимости принятой задачи недопустимо.
