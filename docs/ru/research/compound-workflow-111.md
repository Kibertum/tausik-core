# Compound workflow 1.11: меньше ходов при тех же воротах

Дата замера: 2026-10-01. Предмет — число границ «модель получила ответ и
решила следующий шаг», отдельно от внутренних действий сервиса и токенов.

## Что уже было у Claude

`session_open` уже объединяет пять последовательных секций: старт/текущую
сессию, compact status, handoff, active/blocked tasks и self-check. Каждая
секция имеет watchdog и собственную ошибку; весь ответ ограничен 8 КБ. Этот
контракт принят как образец. Новый параллельный dashboard API не нужен.

`task_done` уже принимает AC evidence inline и возвращает структурированные
gates, cache status и blocking failures. CLI `task done --verify` использует
тот же verification service и single-use handle. Разделять или переписывать
эти пути ради экономии ходов не требуется.

## Изменённый путь старта

| Сценарий | До | После |
|---|---:|---:|
| Успешный старт + task context | 2 ответа модели / 2 tool calls | 1 / 1 |
| QG-0 отказ, затем исправленный успешный старт | 3 / 3 | 2 / 2 |
| Старт успешен, context projection упал, затем восстановлен | 3 / 3 | 2 / 2 |

После: `task_start(package=true)` сначала проходит неизменённый QG-0 и
активирует задачу, затем строит существующий bounded context package. Пакет
сохраняет полные goal и AC, fingerprint, overflow и omissions. Память не
дублируется в стартовом сообщении и пакете.

Если проекция падает после commit активации, результат содержит
`started=true`, `ok=false`, тип ошибки и точную recovery command. Откатывать
успешную активацию из-за read-only projection нельзя: это скрыло бы
совершившийся переход состояния. Ошибка до активации, включая QG-0, как и
раньше, прерывает вызов.

## Что именно доказано

Число вызовов следует из алгоритма общего skill и поэтому одинаково для
Codex, Claude Code и Kilo/GLM, когда хост исполняет этот skill и использует
актуальную схему MCP либо CLI. Это не замер токенов. На Codex и GLM нет
сопоставимого live quota counter, позволяющего честно перевести один
устранённый ход в процент недельного лимита.

При transport timeout до получения результата состояние неизвестно: агент
должен сначала проверить активную задачу, а не слепо повторять mutation. Такой
retry не считается экономией compound route. Живой cross-host прогон Codex,
Claude и Kilo/GLM остаётся release-level acceptance gate; до него заявляется
только проверенное сокращение workflow 2→1, без обещания квоты.

Verification reuse не менялся: cache key включает покрытые файлы и gate
signature, live files перепроверяются, а security-sensitive scope cache не
использует. `verify` и `task_done` остаются отдельными фазами стандартного
навыка, чтобы результат проверки был видим до необратимого закрытия.
