Спецификация: `docs/en/verification-cohort-contract.md` (SPEC
`verification-cohort-contract`, ARCH, 1.0-draft). Ниже — русское зеркало
ключевых правил и измеренного доказательства.

## Правила (кратко)

- Identity когорты: SHA-256 по канонической сериализации — сортированное
  членство, фингерпринты задач со статусами участников, union scope,
  content-digest объединённого скоупа (только контент, без mtime),
  сигнатура гейтов, состояние репозитория. Список выбранных тестов
  ВЫВЕДЕН из identity: evidence выбора существует только после прогона, а
  identity минтуется до него — накормить его честно было невозможно, и
  строка-плейсхолдер не могла инвалидировать ничего.
- Один прогон гейтов на объединённый скоуп; исполнение делегируется в
  `run_verify_for_task` — все кэш-гарды однозадачной линии наследуются.
- Инвалидатор отменяет ПЕРЕИСПОЛЬЗОВАНИЕ зелёного доказательства, но НЕ
  исполнение: прогон РАСШИРЯЕТСЯ на полный лейн, предшественник помечается
  `invalidated`, новая когорта записывается, вывод называет причину
  (membership-drift / task-edits / member-status-drift /
  gate-signature-drift / security-sensitive-scope /
  uncertain-dependency-mapping). Только missing-evidence — честный отказ:
  когорта с удалённой задачей сформироваться не может. Отказывается только
  ЗЕЛЁНОЕ доказательство: красный предшественник с новой identity —
  следующая попытка, а не тупик. Security-sensitive скоуп отказывает
  на любой когорте — свежей так же, как дрейфовавшей.
- Красное продолжение: прошлые фейлы ∪ тесты, затронутые дельтой
  (`required_after_red`, чистая функция). Честное состояние: функция чистая
  и покрыта тестами, но в живом пути она ПОКА не подключена — после
  красного пул-прогон исполняет полный лейн; подключение — отдельная
  работа, не заявление этого контракта.
- `story/epic done --verify-handle` закрывают участников и родителя ОДНОЙ
  транзакцией на точном рецепте; дрейф делает handle просроченным, частичное
  закрытие откатывается целиком. Пул-handle гасится ТОЛЬКО через story/epic
  done: он одноразовый, погашение через `task done` тратило бы рецепт всей
  когорты на одного участника (клауза «task done принимает любой» удалена
  из SPEC §5).
- Гранулярность доказательства (v75): единица записи — cohort-union-scope,
  `covered_by` называет всех участников, `inputs_digest` несёт files_hash
  делегированного прогона (или content-digest identity). Per-test
  провенанс — заявленный non-goal: пул и есть один прогон.
- Однозадачный `verify --task` и его handle не изменились; пул — opt-in.

## Измеренное доказательство (сессия #295)

- Базовая линия (позадачные прогоны, записаны): **34 исполнения / 1492.1 с**
  на 7 задач (в среднем 4.9 прогона на задачу).
- Пул (`verify --tasks`, все семь): **1 исполнение по union-скопу из 44
  файлов, 314.6 с вместе с подготовкой. Экономия: 34 → 1 исполнение
  (34×), 1492.1 → 314.6 с (4.7×), ~19.6 мин.**
- Красный путь тоже живой: прогоны #3587/#3588 ушли в красный на
  подготовительных гейтах, #3589 после исправления — зелёный.

Когда остаются нужны позадачные affected-тесты: закрытие одной задачи,
security-чувствительные скоупы, неопределённый маппинг зависимостей. Пул —
когда ≥2 review-ready задач делят линию, прежде всего релизные истории.
