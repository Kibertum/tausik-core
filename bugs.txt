TAUSIK BUGS ENCOUNTERED DURING TAUX DEVELOPMENT
Updated: 2026-11-20

TB-001  Complex imported task cannot start because package metadata is incomplete
Status: FIXED AND LOCALLY VERIFIED
Observed: `task start taux-foundation-adr --package` returned PACKAGE_INVALID for
call_budget and assurance_impact. The v84 one-shot migration supports legacy rows,
but a task imported after that migration was not marked for normalization.
Workaround used: explicitly set task planning metadata without changing goal/AC/scope.
Root cause: portable export omits the internal compatibility marker and state import
did not reconstruct it for an incomplete pre-v84 complex package.
Fix: import marks only incomplete complex task contracts as legacy; the existing
start normalization applies compatibility defaults. New API/CLI tasks remain strict.
TauX prevention: imported state must be versioned and normalized transactionally;
unknown assurance stays explicit and cannot silently become PASS.

TB-002  PowerShell cannot safely pass ordinary authored handoff JSON
Status: FIXED AND LOCALLY VERIFIED
Observed: JSON containing spaces was split into multiple argv values and argparse
returned `unrecognized arguments`. JSON with escaped Unicode spaces worked only as
an unsuitable workaround.
Root cause: `session handoff` accepted only one positional JSON argument.
Fix: retain positional compatibility and add UTF-8 `--json-file`/`--stdin` inputs;
require exactly one input and an object-shaped payload.
TauX prevention: structured APIs are primary; CLI accepts file/stdin for structured
payloads and never requires shell-specific quoting for correctness.

TB-003  update-claudemd implicitly selects and updates AGENTS.md
Status: FIXED AND LOCALLY VERIFIED
Observed: in a non-Claude TauX checkout, `update-claudemd` searched for its marker
inside manually maintained AGENTS.md and reported a skipped update.
Root cause: resolver preferred the active IDE rules file and fell back to AGENTS.md;
sibling synchronization was enabled by default.
Fix: the Claude-named command resolves only explicit Claude projections; AGENTS.md
sibling writes require explicit `claudemd.sibling_dynamic=true` opt-in.
TauX prevention: canonical continuity is host-neutral. CLAUDE.md, AGENTS.md and other
host files are optional projections with explicit targets and ownership.

TB-004  Installed workflow skills describe CLAUDE.md as universal context storage

CLAUDE.md even when the active host is Codex/Kilo and no Claude projection exists.

refresh a host projection only when that adapter and target are explicitly configured.

usage was described as leaking severely. No per-process trace was captured before

- No orphaned pytest workers from this soak; multiple RAG MCP servers from OTHER

deadline/cancellation, bounded queues/caches/output, finally-based teardown and
observable resource metrics. A child timeout must terminate and reap owned children;

TB-007  Supplementary author self-review cannot be recorded on an L3-routed task

higher-level requirement; the resolver, not record insertion, decides sufficiency.

not offered as an L3 substitute; refusal again discards useful lower-level evidence
instead of retaining it with `satisfies_route=false`.

TB-008  L3 cohort readiness rejects the documented numbered AC evidence format
Status: FIXED AND LOCALLY VERIFIED
Observed: task logs using the documented forms `AC verified: 1. ... 2. ...` and
`AC verified: 1. ✓ ...` were parsed as human evidence but `review cohort-open`
still returned `no numbered AC evidence logged`. The readiness query in
`verify_hierarchy.py` checks only `message LIKE '%AC-%'`, so it requires a literal

Workaround: log the same honest matrix with explicit `AC-1:` through `AC-N:` labels.
Required fix: use the shared AC evidence parser/read model for review readiness, or
make the public logging contract require and generate the same canonical markers;
add parity tests for CLI/MCP examples, multiline notes and explicit GAP entries.
TauX prevention: one versioned evidence parser and schema serve logging, review
packets and closure. Readiness never relies on a second substring heuristic.

TB-009  Normal L3 review has no usable mechanically read-only Codex path
Status: FIXED IN CORE (pending consumer upgrade / host config.review.l3_host)
Observed: the registered `tausik-external-reviewer` subagent correctly refused
round 1 because its host exposed write-capable tools despite the role declaring a
read-only review. A same-family `codex exec --sandbox read-only --ephemeral` round
then started with `approval: never` and `sandbox: read-only`, but the local Codex
authorization policy rejected every repository read (`Get-Content`, `rg`, and
`cmd /c type`) as `blocked by policy`. The reviewer could inspect only the issued
packet, so round 2 remained red and the bounded cohort exhausted both rounds without
ever obtaining an independent file review.
Core fix: `review_l3_preflight` + `review cohort-infrastructure-blocked` (schema
v90) preserve round budget; open/status carry `delegation`/`l3_capability`;
enforced `review.l3_host` blocks `cohort-record`. Docs: `docs/en|ru/codex-l3-readonly.md`.
Tests: `test_review_l3_preflight.py`, `test_codex_l3_readonly_conformance.py`.
Required fix prompt: add a Codex-specific L3 conformance test that launches the
documented external reviewer with the exact production policy stack and proves
both sides of least privilege: repository reads and search succeed, while writes,
processes outside the allowlist, network mutation, and task-state mutation fail.
The dispatcher must preflight that capability before opening or consuming a cohort
round; an infrastructure refusal must not burn one of the two defect-repair rounds.
Carry `Author model: <id>` into the generated delegation automatically, return a
distinct `review_infrastructure_blocked` receipt, and document the supported Codex
CLI flags/policy interaction. Add Windows PowerShell coverage because this failure
occurred only after process creation and was not detected by route selection.
TauX prevention: provider capability negotiation is executable and fail-closed.
Read-only means an explicit capability set that is smoke-tested before review; an
unavailable provider preserves the review budget and cannot be confused with a
product finding. Host adapters are first-class and Codex is the initial reference.
2026-11-21 repeat after AC-7 repair: a fresh generation-2 cohort packet was
issued, but the registered same-family external reviewer again refused before
reading any file because its context still exposed write-capable tools. This
confirms that the failure is capability enforcement, not a stale packet or the
previous AC-7 gap. No reviewer verdict was fabricated and no third workaround
was attempted in the TauX task.
2026-11-21 workflow-core repeat: the existing isolated L3 reviewer failed twice
before returning any file evidence because the platform classified both the
original and neutrally reworded read-only correctness request as possible cyber
risk. This is an infrastructure refusal, not a product finding or PASS; the same
scope was routed to an available read-only L2 reviewer while L3 remains unsatisfied.
2026-11-21 preview-install repeat: the dedicated external-reviewer role again
stopped before reading any file. Its host could not mechanically enforce read-only,
and the invocation lacked infrastructure-issued cohort_id, round and immutable
packet_digest. The bounded product packet already had verify #78, full tests,
cross-platform package probes, checksum verification and a clean independent L2.
Owner workaround for TauX development: record an explicit, task-scoped assurance
exception against this infrastructure failure; do not label it an L3 PASS and do
not repeat the broken ceremony. Continue the product dependency route on the
existing product evidence while retaining the exception in task history.

TB-010  Node test evidence with spaces cannot be resolved by the task gate
Status: FIXED AND LOCALLY VERIFIED
Observed: a green Node test whose declared title contains spaces could not be
accepted as task evidence: the JavaScript test resolver treated only the first
token as the test name and failed to match the actual `test("...")` declaration.
The same test was executed successfully by the pinned Node 26 runner and the
task-scoped verification was green; closure required an explicit
`AC-1: ✓ green verification_run #<id> for this task` log instead.
Required fix: parse structured Node test output or preserve the complete quoted
test identifier; add coverage for spaces, punctuation and nested test names.
Fix: `find_test_refs` keeps quoted `path::"title with spaces"` as one token and
re-joins unquoted multi-word titles; `TEST_REF_RE` accepts those forms;
`_named_test_defined` strips citation quotes before matching `test("…")`.
Partial first-word citations still fail closed against the full title.
TauX prevention: evidence references use typed stable IDs, while human-readable
test titles remain display metadata and are never reparsed as identifiers.

TB-011  Planned backlog task cannot start with its persisted assurance package
Status: FIXED AND LOCALLY VERIFIED
Observed: `task start taux-workflow-core` rejected the route-created task with
`PACKAGE_INVALID: missing or incomplete fields: call_budget, assurance_impact`.
The task already contained an `assurance_impact` object, but only blast radius and
reversibility were persisted; the route/backlog handoff did not populate the full
start-time contract or a call budget. A planned task therefore was not executable
without an ad hoc metadata repair.
Required fix: validate and normalize generated/imported task packages when the
route is built, report the exact missing assurance keys, and add a fixture proving
every route-selected task can enter `active` without owner intervention.
Fix: incomplete complex packages from `task_add_complete` and state import get
`task_package_legacy=1` so start normalizes; `PACKAGE_INVALID` lists each missing
`assurance_impact.*` key; plain API `complexity=complex` without the marker stays
strict.
TauX prevention: lifecycle creation and transition share one versioned schema;
an entity advertised as startable is already valid for the start transition.

TB-012  Task closure ignores its non-downgradable L3 hard floor
Status: FIXED AND LOCALLY VERIFIED
Observed: `taux-workflow-core` declared `assurance.depth=L3`, `hard_floor=L3`
and residual L3 evidence gaps. Four honest L2 records were refused because only
L3 could satisfy the route, and TB-009 had already established that the external
reviewer could not read the files. Nevertheless `task done taux-workflow-core
--ac-verified` returned completed without any L3 record or owner exception.
The product AC, verify #63, final independent L2 PASS and Node26 suite were green,
but the required assurance level was not met and is not claimed here.
Required fix: task closure must atomically resolve the current review route and
refuse when a hard-floor receipt is absent; lower review records must remain
recordable with `satisfies_route=false`; add a regression spanning route, record,
infrastructure-blocked review and task-done so those surfaces cannot disagree.
TauX prevention: closure validates typed current evidence against every mandatory
obligation in one transaction; an unavailable provider preserves an explicit gap
and cannot silently downgrade or satisfy it.

TB-013  Honest repair review cannot be recorded when route predicts one invocation
Status: FIXED AND LOCALLY VERIFIED
Observed: `taux-crash-resume` required one fresh L2 reviewer invocation. The first
independent review correctly returned FAIL with actionable findings; after repair,
the same fresh reviewer performed the necessary second read-only pass and returned
PASS. `review record --type L2 --reviewer-invocations 2` refused the evidence because
the route predicted exactly one invocation, and also required model identity flags
that the task/reviewer handoff did not provide automatically. Recording `1` would
misstate the actual review history, so no receipt was fabricated.
Required fix: treat the route invocation count as a minimum/default budget rather
than an equality constraint once findings require repair, or model explicit review
rounds with FAIL/PASS receipts. Carry recognized author/reviewer identity from the
session and delegated reviewer automatically. Add a regression for one failing L2
round followed by a passing repair round and require both rounds to remain visible.
TauX prevention: verification history is append-only and correction-preserving;
failed observations remain linked to the repaired result and honest extra evidence
cannot be rejected merely because the optimistic route estimated fewer attempts.

TB-014  Generated package lock is treated as an authored oversized source file
Status: FIXED AND LOCALLY VERIFIED
Observed: scoped verify #73 failed before tests because the generated npm
`package-lock.json` has 1,349 lines and the generic 500-line source limit was
applied without a generated-file exception. The repository contract explicitly
allows justified generation exceptions, and the lock must remain generated and
complete; splitting or hand-editing it would be incorrect. The repeated scope

install, TypeScript build and full Node suite validate the lock-derived graph.
Required fix: classify standard deterministic lockfiles as generated evidence,
check their parser/integrity instead of authored-source line count, and keep them
visible in task scope without blocking downstream tests.
TauX prevention: file policies are type-aware; generated manifests receive
integrity/provenance checks while authored modules receive maintainability limits.
