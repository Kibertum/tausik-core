ПЕРЕНОС ЧУЖИХ РЕШЕНИЙ В НАШ ПУТЬ, А НЕ ПЯТЬ ПУНКТОВ СВЕРХУ. Источники разбора: Anthropic «Effective context engineering for AI agents» и «Scaling Managed Agents: decoupling the brain from the hands»; 12-factor agents (факторы 5, 6, 8, 12); LangGraph (чекпойнт на каждом шаге, thread_id, ветвление от прошлого чекпойнта); Letta/MemGPT (правимые агентом блоки памяти, sleep-time compute); официальная практика Claude Code (новая задача — новый контекст, /compact с инструкцией, /rewind не покрывает Bash).  ЦЕЛЕВАЯ АРХИТЕКТУРА — ТРИ СЛОЯ ВМЕСТО ОДНОГО ПОНЯТИЯ «СЕССИЯ»: 1. ЖУРНАЛ — долговечная допрашиваемая запись «что произошло». Всё остальное (статус, счётчики, сессия, отчёты) есть ПРОЕКЦИЯ журнала, а не параллельное состояние (фактор 5). 2. КОНТЕКСТ — политика харнесса, а не привычка человека: ядро памяти всегда в окне, архив достаётся по релевантности, результаты инструментов чистятся, компакция инструктируется, порядок инъекции стабилен ради кэша. 3. ЕДИНИЦА РАБОТЫ — ЗАДАЧА. Одна задача = один журнал = одно контекстное окно = один коммит. Сессия-день становится производным отчётом о пробеге активности, а не тем, что открывают и закрывают.  ПУТЬ АГЕНТА ПЕРЕСОБИРАЕТСЯ ПОД LAUNCH/PAUSE/RESUME (фактор 6): task start собирает контекст политикой и пишет событие запуска; всякий шаг попадает в журнал, и ничто не живёт только в окне; пауза не требует ритуала, потому что агент — скот, а не питомец, и его можно убить в любой момент; resume пересобирает контекст из журнала БЕЗ рукописного промпта; task done несёт квитанцию, коммит и проход консолидации памяти.  ПРИЁМКА ЭПИКА — УЧЕНИЕ С ХОЛОДНЫМ СТАРТОМ: агент убивается посреди задачи, поднимается новый с одним словом «продолжай» и доезжает. Всё, что не доехало, заводится дефектом того, что задача записывает о себе. Пока непрерывность подпирается рукописным вводным промптом, она не проверена ни разу.  ПОРЯДОК ЖЁСТКИЙ: сначала проверка уходит с критического пути (CI на ветке), потому что непрерывная работа без работающего CI есть непрерывная НЕПРОВЕРЕННАЯ работа.
