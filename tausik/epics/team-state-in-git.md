Цель релиза 1.8, переформулированная после разговора с владельцем. Изначальная формулировка была «глобальный по ОС shared brain», но она смешивала две РАЗНЫЕ оси: (1) меж-проектные личные знания (Shared Brain на Notion, ~/.tausik-brain — уже построен, эпик shared-brain=done) и (2) состояние КОНКРЕТНОГО проекта для команды. Команде нужна вторая ось, и она НЕ про Notion.  ПРОБЛЕМА. Весь каталог .tausik/ в .gitignore — значит тиммейт после git clone не видит НИЧЕГО: ни задач, ни решений, ни памяти проекта, ни плана. БД бинарная (SQLite) — её нельзя ни прочитать в diff, ни смёржить. Плюс стейт сейчас branch-BLIND: переключение ветки не меняет .tausik/.  АРХИТЕКТУРА (согласована с владельцем). Стейт-в-ветке: durable-состояние проекта лежит git-native текстовыми файлами В РЕПОЗИТОРИИ, по файлу на сущность (md+frontmatter). Git — канонический источник правды, БД — пересобираемый рабочий кэш (быстрый FTS). Слияние стейта = git merge веток: решение, принятое на feature-A, приезжает в main ровно тогда, когда приезжает код feature-A. Внешний стор (Notion/сервер) для этого структурно непригоден — он branch-agnostic и расцепляет стейт с кодом (стейт начинает врать про несуществующий код; памятка #229).  ДВА ЭТАЖА. Этаж 1 (этот эпик): durable, сцеплён с кодом — задачи/план/логи/эпики/стори + решения/память. Этаж 2 (ОТЛОЖЕН явно): живая координация «кто над чем сейчас, до мержа» — не строится, пока не докажет боль; решается git-ом (claimed_by + пуш), не сервером.  ОБЪЁМ (выбор владельца): в git едут tasks+task_logs+epics+stories и decisions+memory+memory_edges. НЕ едут: verification_runs/gate_runs/reviews (аудит, быстро устаревает), sessions/usage (эфемерное, шумит в diff).  НЕСУЩИЙ РИСК: решения и память адресуются локальными автоинкрементами (#171, #307) — на двух ветках оба создадут «#308» → коллизия при мерже. Разделяемым сущностям обязательна стабильная идентичность (слаг/uuid). С этого всё начинается.  Этаж 2 (живая координация) и Notion/Obsidian-виды — вне этого эпика. Obsidian при желании — просто читатель поверх git-native md, не механизм синхронизации.
