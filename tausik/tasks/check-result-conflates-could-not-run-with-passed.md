## Goal

ПЕРВАЯ ЗАДАЧА 1.9 — на ней стоит всё остальное. У нас нет типа результата проверки: есть строки, сентинелы и соглашения. _SCOPED_SKIP_SENTINEL, _NO_IMPL_SENTINEL, SKIP от отсутствия отображения, SKIP от отсутствия инструмента, тихий возврат к умолчанию при отвергнутой команде гейта — всё это разные события, читающиеся как одно, и ни одно не краснеет.

СОБСТВЕННЫЙ ПРОТОКОЛ, а не гипотеза: гейт pytest вырождался в no-op вне корня тестов, и SKIP был неотличим от честного (тикет #8, внешний репортёр); гейт memory-route у потребителя не находил себя и МОЛЧА не запускался; детектор соседних MCP отдавал ноль, означавший «не умею считать»; отвергнутая команда гейта не краснела, а откатывалась к умолчанию (память #: gotcha 1.8). Один корень: результат имеет два значения там, где событий три.

ЧТО ДЕЛАЕТСЯ: результат проверки становится ТИПОМ с тремя исходами — выполнилось и прошло, выполнилось и не прошло, НЕ СМОГЛО ВЫПОЛНИТЬСЯ. Третий исход несёт ПРИЧИНУ и по умолчанию блокирует, а не пропускает. Это ровно SENAR 1.4 §8.6(e): отсутствие отрицательной находки не есть положительный вердикт. Квитанция перестаёт подписывать пустоту.

НЕГАТИВНОЕ ОГРАНИЧЕНИЕ: «законный пропуск» обязан остаться выразимым — изменение, которому честно не соответствует ни один тест, есть нормальный случай и не блокирует. Различие между ним и невозможностью выполниться и есть весь предмет задачи; свести оба к блокировке значит заменить одну неразличимость другой.

## Acceptance Criteria

AC1. ИСХОД ПРОВЕРКИ ЕСТЬ ТИП, А НЕ ПАРА БУЛЕВЫХ. Существует тип с четырьмя явно названными исходами: PASSED, FAILED, NOT_APPLICABLE, COULD_NOT_RUN. Ось задачи трёхзначна («выполнилось и вот вердикт» / «не выполнялось»), но ветвь невыполнения делится по законности, иначе негативное ограничение goal невыполнимо. Утверждается ВЫЗОВОМ конструктора каждого исхода, не разбором исходника.

AC2. COULD_NOT_RUN НЕВЫРАЗИМ БЕЗ ПРИЧИНЫ. Исход несёт машиночитаемый код причины и человекочитаемое объяснение; попытка сконструировать COULD_NOT_RUN без причины ОТВЕРГАЕТСЯ на конструкции, а не позже. Двусторонне: с причиной конструируется, без — отказ.

AC3. COULD_NOT_RUN БЛОКИРУЕТ ПО УМОЛЧАНИЮ. Гейт severity=block, вернувший COULD_NOT_RUN, даёт run_gates(...) -> all_passed=False. Это SENAR 1.4 §8.6(e): отсутствие отрицательной находки не есть положительный вердикт.

AC4. ЗАКОННЫЙ ПРОПУСК ОСТАЁТСЯ ВЫРАЗИМЫМ И НЕ БЛОКИРУЕТ. Изменение, которому честно не соответствует ни один тест, даёт NOT_APPLICABLE и all_passed=True. Двусторонне с AC3: один и тот же гейт на «нечего проверять» проходит, на «не смог выполниться» блокирует. Свести оба к блокировке — заменить одну неразличимость другой.

AC5. ЖИВОЙ ПРИМЕР #182 МЕНЯЕТ ИСХОД. verify --task по slow-помеченному тестовому файлу (tests/test_skill_cli_help.py, 5 deselected) даёт COULD_NOT_RUN, а НЕ FAILED. Замерено до кода: verification_run #1807 = [FAIL] (block) при нуле упавших и нуле запущенных тестов.

AC6. ОТКАЗ НАЗЫВАЕТ СРЕДСТВО. Текст COULD_NOT_RUN для случая AC5 содержит TAUSIK_VERIFY_FULL=1. Ожидаемый текст берётся ИЗ ПРОДУКТА, а не переписывается литералом в тест. Флаг --full НЕ упоминать: его не существует (pyproject.toml:34 обещает несуществующее — отдельный дефект, отдельная задача, pyproject.toml здесь НЕ правится).

AC7. КОД ВЫХОДА PYTEST РАЗЛИЧАЕТСЯ, А НЕ СХЛОПЫВАЕТСЯ. exit 5 (EXIT_NOTESTSCOLLECTED) отображается в COULD_NOT_RUN; exit 1 остаётся FAILED. Замерено: python -m pytest tests/test_skill_cli_help.py -q даёт ровно exit=5. Сегодня gate_command_runner.py:329 схлопывает всякий ненулевой код в False. Двусторонне: 5 -> COULD_NOT_RUN И 1 -> FAILED.

AC8. СТРОКОВЫЕ СЕНТИНЕЛЫ ПЕРЕСТАЮТ БЫТЬ КАНАЛОМ РЕЗУЛЬТАТА. _SCOPED_SKIP_SENTINEL и _NO_IMPL_SENTINEL больше не едут в поле output. Гейт без реализации и без команды (сегодня gate_runner.py:159 -> passed=True) даёт COULD_NOT_RUN и БЛОКИРУЕТ — это ровно «не смогло выполниться, записано как прошло» из заголовка. Отсутствие отображения test-файла при непустых relevant_files даёт NOT_APPLICABLE.

AC9. КВИТАНЦИЯ ХРАНИТ ИСХОД И ПРИЧИНУ. gate_runs пишет исход и причину, а не только (passed, skipped): сегодня в схеме нет колонки причины и три состояния кодируются двумя булевыми. Строка, прочитанная обратно из БД, восстанавливает ТОТ ЖЕ исход и ту же причину — утверждается круговым прогоном, не чтением DDL.

AC10. СВОДКА НЕ ПОДПИСЫВАЕТ ПУСТОТУ. gate_verdict/summarize_results не описывают не выполнившуюся проверку как PASS; verification_runs.summary для гейта с COULD_NOT_RUN не содержит для него PASS. Утверждать содержание И то, что вердикт пришёл с нужного слоя, а не только префикс.

AC11. СТРАЖИ ПРОВЕРЕНЫ МУТАЦИЕЙ — по одной мутации на класс обещания (AC3 блокировка, AC4 незаблокировка, AC7 различение кодов). Файл после каждой восстанавливается побайтово со сверкой sha256.

AC12. ШИРОКАЯ ЛЕНТА НЕ КРАСНЕЕТ. python -m pytest tests/ -q -m '' -o faulthandler_timeout=300 не приобретает новых падений относительно базовой линии сессии #183. Существующие потребители исхода (project_cli_receipt.py:80, project_cli_task.py:148) продолжают читать результат.
