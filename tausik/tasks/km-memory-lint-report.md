## Goal

Шаг 5 из 6 (решение #143, эпик shared-knowledge).

Проверки: отсутствие topic_uuid; висячий алиас (резолвится в несуществующий topic_uuid); подозрение на дубль темы; дельта backtick-ссылок; превышение размера темы. Плюс механизм построчного lint_ignore (DOCER выпустил .DOCER_exclude именно поэтому).

ДЕЛЬТА, А НЕ НАЛИЧИЕ. Проверка backtick-ссылок формулируется так: токен флагуется, только если он резолвился на created_at_sha И не резолвится на HEAD. Наивная проверка «упомянутого файла нет в дереве» — известная ловушка: прямой эксперимент (mex #79) дал 18 ложных срабатываний на 6 корректных документах и обнулил оценку. Записи типа gotcha у нас ПЛОТНЕЕ обычного README по инлайн-коду: ключи конфигурации, CIDR, глобы, голые расширения, фрагменты shell, имена переменных окружения — всё в бэктиках. Дельта убивает весь этот класс ложных срабатываний, потому что такие токены не резолвились и на момент записи.

Дубль темы — ТОЛЬКО предупреждение, вопреки первоначальному плану блокировать сразу. Переслияние это задокументированная патология: агенты переиспользуют ранее НЕВЕРНЫЕ результаты с возросшей уверенностью, потому что память создаёт видимость прецедента. Публичного бенчмарка для настройки порога не существует, а ложное слияние обнаружить постфактум труднее, чем дубль.

НЕ строить LLM-судью устаревания: потолок 55.2% на STALE benchmark у лучшей модели, специализированные фреймворки памяти ниже 10%, а пер-PR LLM-судейство отключают по стоимости и задержке. Детерминированное правило (дельта по дереву git) выигрывает.

Критерий приёмки: tausik memory lint отрабатывает по реальным 227 строкам, и число ложных срабатываний по каждой проверке ЗАПИСАНО в журнал задачи (это вход для шага 6).

Негативный сценарий: недоступность git не должна ронять lint — проверка дельты деградирует до «неизвестно» и отчёт это явно сообщает (конвенция #226).

## Acceptance Criteria

1. tausik memory lint отрабатывает по реальным 227 строкам и НИ ОДНА проверка не блокирует (все — предупреждения).
2. Число ложных срабатываний по КАЖДОЙ проверке записано в журнал задачи (вход для шага 6).
3. Проверка backtick-ссылок работает по ДЕЛЬТЕ (токен резолвился на created_at_sha и не резолвится на HEAD), а не по наличию файла; поддержан построчный lint_ignore.
4. Недоступность git не роняет lint — проверка дельты деградирует до «неизвестно» и отчёт это явно сообщает (конвенция #226).
