## Goal

Измерить, даёт ли графовая навигация по зависимостям то, чего чанковый поиск не даёт принципиально, — на нашем собственном репозитории и на наших вопросах.

## Acceptance Criteria

1. ПОРОГ ПРОВАЛА ОБЪЯВЛЕН ДО РАБОТЫ: граф обязан дать прирост на вопросах о скрытых зависимостях, иначе не интегрируем. Число прироста называется до замера, а не подгоняется под результат.
2. Вопросный набор строится на СВОЁМ репозитории: 7100 тестов и scripts/ с настоящими связями дают ground truth вида «кто вызывает X», «что сломается, если сменить сигнатуру Y».
3. Сравниваются три конфигурации: только FTS5-гибрид; FTS5 плюс внешний граф, поставленный рядом как MCP; и оценка стоимости своего минимального графа на stdlib ast только для Python.
3а [УТОЧНЕНО В СЕССИИ #178 ПО ЗАПРОСУ ВЛАДЕЛЬЦА]. «Внешний граф» из пункта 3 перестал быть абстракцией — эталон сравнения назван поимённо, вместе с замером его живости через GitHub API 25.08.2026: LadybugDB/ladybug (1644 звезды, push в день замера, развивается именно под память агента) — ЕДИНСТВЕННЫЙ живой кандидат; kuzudb/kuzu (4026 звёзд) АРХИВИРОВАН 2025-10-10 после покупки компании Apple, и именно его цифры (9 мс против 3-4 с у Neo4j, разрыв 374x) цитируют все обзоры; indradb/indradb (2459 звёзд) не архивирован, но молчит двенадцать месяцев и из Python работает только через gRPC к отдельному процессу. Замер идёт против Ladybug; два других называются в отчёте как мёртвые, а не умалчиваются.
4. Замер использует harness из задачи memory-retrieval-has-no-published-benchmark — второй измеритель НЕ пишется.
5. Названа причина, почему это не закрывается расширением контекста: рост окна не решает задачу навигации, он лишь дороже её обходит.
6. НЕГАТИВНЫЙ сценарий: интеграция чужого графа означает внешний вклад в контекст агента БЕЗ подписи — это прямо противоречит нашей дисциплине цепочки поставок. Вопрос разбирается в замере, а не откладывается на интеграцию.
7. НЕГАТИВНЫЙ сценарий: свой граф на ast — вечная ловушка поддержки парсера, и только для одного языка. Цена поддержки оценивается до выбора, а не после.
8 [НОВЫЙ, СЕССИЯ #178]. НЕГАТИВНЫЙ, О ЦЕНЕ ОСНОВАНИЯ. Отчёт обязан назвать риск поставщика ЧИСЛОМ, а не оговоркой: движок с четырьмя тысячами звёзд закрылся за год после покупки. Слой памяти есть ядро продукта; ставить его на внешний компилируемый движок — принять ровно тот риск, который дорожная карта уже назвала, отказываясь догонять claude-mem. Если по итогам замера Ladybug выигрывает, вывод «интегрируем» НЕ следует автоматически — цена основания взвешивается отдельно и записывается.
9 [НОВЫЙ, СЕССИЯ #178]. ПОЛОЖИТЕЛЬНЫЙ, О ТОМ, ЧТО БЕРЁТСЯ ДАЖЕ ПРИ ПРОВАЛЕ ГИПОТЕЗЫ. Проверить, покрывает ли рекурсивный CTE самого SQLite те многошаговые обходы, ради которых зовут графовый движок. Если да — форма запроса берётся без единой зависимости, и это результат, а не утешительный приз: эпик artifact-graph уже положил артефакты и рёбра В ТУ ЖЕ БД задачей ag-artifacts-and-edges-with-provenance.
