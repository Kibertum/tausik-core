## Goal

НЕСУЩАЯ задача эпика: без неё слияние стейта двух веток невозможно. Сейчас decisions и memory адресуются локальными автоинкрементными id (#171, #307). Двое инженеров на своих ветках оба создадут «#308» → коллизия/дубль при git merge. Задачи уже адресуются слагами (машинно-независимо) — надо дать то же решениям и памяти.

Объём: (1) добавить стабильный идентификатор (слаг ИЛИ uuid — выбрать в state-git-spec) сущностям decisions, memory; связи memory_edges должны ссылаться на этот стабильный id, а не на автоинкремент. (2) Миграция существующих строк: сгенерировать стабильные id для всех текущих 171 решения и 307 записей памяти детерминированно (напр. из содержания/даты), сохранив ВСЕ существующие ссылки [[name]] и memory_edges. (3) Обратная совместимость: код и MCP, показывающие «#171», должны продолжать работать во время перехода — либо старый int-id остаётся вторичным ключом, либо явный перевод. (4) Не сломать FTS и существующие запросы.

Риск: миграция идентичности живых данных необратима грубым откатом — нужен бэкап БД до миграции и обратный тест (после миграции все прежние ссылки и рёбра графа памяти разрешаются). Дифференциальный прогон: до/после миграции граф памяти изоморфен (те же узлы, те же рёбра, только id стабильные).

## Acceptance Criteria

1. v42 migration adds NULLABLE slug TEXT to decisions and memory; SCHEMA_VERSION bumped to 42; registered in backend_migrations.py; schema-migration parity check green. 2. make_slug(text) is deterministic kebab-case (lower, ASCII-fold, ws→-, ~60 char cap) with machine-stable dedup (-2/-3 suffix by id ASC). 3. postseed backfill under flag v42_slugs_backfilled: memory.slug from title, decisions.slug from decision's FIRST line, ordered by id ASC; UNIQUE index on both slug columns created AFTER backfill; re-running the postseed is a no-op (idempotent — no new dupes, slugs unchanged). 4. Negative/boundary FALLBACK: an empty/non-printable memory title and an empty decision body yield a deterministic id/date-derived slug, NOT a crash and NOT a NULL that breaks the UNIQUE index. 5. Negative/collision: two rows with identical title/first-line get distinct slugs deterministically (by id ASC). 6. Forward inserts in backend_crud.py + service_knowledge.py assign slug on INSERT for new memory and decisions. 7. Graph isomorphism: memory_edges resolve to the same node set and edge set before and after backfill (same graph, stable ids). 8. FTS still works; existing #171/#307 int-id display and references unchanged (int id stays PK). 9. Differential run on a COPY of the live DB: all 171 decisions + 308 memories get unique stable slugs, every existing edge resolves. 10. Full scoped verify green.

## Plan

## Rollback

Migration is additive: two nullable columns + two unique indexes. The migration runner auto-backs up the live DB (tausik.db.bak.v42) before applying. Crude rollback: restore the .bak.v42 backup, or DROP the slug columns/indexes — slug data is not load-bearing for DB operation until export/import is wired (a later task). No data is destroyed; int PK and all existing rows/edges are untouched.
