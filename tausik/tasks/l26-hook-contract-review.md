## Goal

НЕСУЩАЯ ДЫРА. Хуки навешены только на Write|Edit (bootstrap_hooks.py:28,41,51,64); Bash получает лишь bash_firewall и git_push_gate, а они не знают про запись файлов. Значит python -c с open(w), sed -i, cat heredoc обходят и QG-0 (нет кода без задачи), и scope-ACL целиком. NotebookEdit тоже не покрыт. ВАЖНЫЙ КОНТЕКСТ 2026: набор хук-событий Claude Code расширился примерно до 30 (PermissionRequest, PermissionDenied с retry, PostToolUseFailure, SubagentStart/Stop, PreCompact/PostCompact, TaskCreated/TaskCompleted, WorktreeCreate/Remove) — контракт писался, когда событий было мало, и дыра может закрываться штатно. Задача: ревизия доступных событий, затем либо закрыть Bash-запись, либо ЯВНО задокументировать границу принуждения. Второе допустимо, молчание — нет. Смежное: scope_write_gate.py:165-166 — одна активная задача без scope_paths снимает ACL глобально; :137-148 fail-open по умолчанию при sqlite3.Error.

## Acceptance Criteria

AC1. Проведена ревизия актуального набора хук-событий Claude Code (~30 событий) и зафиксирована в docs/ru: перечислено, какие события покрывают запись файлов и покрывается ли Bash/NotebookEdit-запись штатно.
AC2. Дыра либо закрыта, либо ЯВНО задокументирована. Закрытие проверяется тестом fails-then-passes: при отсутствии активной задачи попытка записи файла в project root через Bash-heredoc (или python -c open(w), sed -i) возвращает BLOCKED так же, как Write. Документирование границы — явная запись в docs/ru/agent-contract.md, что Bash-запись не покрывается QG-0/scope; молчание недопустимо.
AC3. scope_write_gate.py:165-166 больше не снимает ACL глобально при одной активной задаче без scope_paths — покрыто unit-тестом на этот случай.
AC4. fail-open по умолчанию при sqlite3.Error (scope_write_gate.py:137-148) заменён на явное решение (fail-closed либо залогированный fail-open с видимым сигналом), покрытое тестом.
AC5. Ужесточение не даёт ложных срабатываний на пути вне project root (запись в scratchpad/сообщение коммита не блокируется) — тест на внешний путь.
