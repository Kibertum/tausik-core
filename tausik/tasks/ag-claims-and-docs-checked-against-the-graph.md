## Goal

САМЫЙ СИЛЬНЫЙ РЫЧАГ КАЧЕСТВА, и он бьёт по главной болезни этого проекта. Ревью находит «утверждение шире кода» ДЕВЯТЬ сессий подряд. Не потому что код небрежен — он проходит все гейты, — а потому что докстринг и CHANGELOG пишутся в момент, когда намерение шире реализации, и построчно с кодом их потом никто не сверяет.

ДВА ЖИВЫХ ПРИМЕРА ИЗ ОДНОЙ СЕССИИ #157, ОБА МЕХАНИЧЕСКИ ПРОВЕРЯЕМЫ ГРАФОМ:
1. Докстринг ссылался на _record_with_mirror ПОСЛЕ того, как функция была удалена. Запрос: «утверждение упоминает символ, которого нет».
2. CHANGELOG заявлял «единственная воронка записи в Notion», а воронок было три. Запрос: «утверждение заявляет охват, которого рёбра не показывают».
Ни то, ни другое не требует понимания текста — только сверки ИМЁН с графом.

ОБОБЩЕНИЕ ГЕЙТОВ ДОКУМЕНТАЦИИ. Сейчас под каждый вид пишется отдельный рукописный тест: test_doctor_doc_covers_every_check ловит недокументированную проверку доктора. С рёбрами «документирует» это ОДИН общий гейт «каждый символ вида X имеет документирующее ребро», и он покрывает разом проверки доктора, команды CLI, ключи конфига, гейты качества. Существующие рукописные тесты обязаны быть ЗАМЕНЕНЫ им, а не дополнены — иначе получим два механизма на одну задачу.

ГРАНИЦА ЧЕСТНОСТИ, НАЗВАТЬ ЯВНО: это НЕ проверка смысла. Гейт ловит мёртвые ссылки и заявленный охват, но не поймает утверждение, которое верно по именам и ложно по существу. Обещать большее — повторить ровно ту ошибку, против которой задача заведена.

НЕГАТИВНЫЙ СЦЕНАРИЙ: (а) утверждение, упоминающее символ из ЧУЖОГО проекта или из стандартной библиотеки, не должно считаться мёртвой ссылкой — иначе гейт станет шумом и его отключат; (б) удаление символа при сохранившемся упоминании обязано ронять гейт, и тест обязан подать именно этот вход.
