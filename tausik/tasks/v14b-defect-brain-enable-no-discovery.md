## Goal

find_workspace_brain_databases() в scripts/brain_init.py обнаруживает БД ТОЛЬКО по exact title match с DB_TITLES ('Brain · Decisions' и т.д.). Если БД в Notion переименованы (даже добавление emoji) или созданы вне нашего wizard'а с category-only названиями (как у пользователя сейчас: 'decisions'/'patterns'/'web_cache'/'gotchas') — discovery возвращает 0, и сообщение об ошибке вводит в заблуждение ('integration не shared'). Добавить schema-based fallback: если title-match нашёл <4, проверить ВСЕ visible БД через databases_retrieve и сматчить по обязательным properties из db_schema(category). Title-match сохранить как первичный (стабильность). Также улучшить error: при discovered=0 с visible>0 перечислить найденные БД и предложить explicit IDs.

## Acceptance Criteria

AC1 (schema-based fallback). find_workspace_brain_databases(client) возвращает {category: db_id} следующим алгоритмом:
  - Этап 1: search() с filter object=database, без query (убрать query='Brain' — он сужает результаты до title-match-only). Перебор всех visible БД.
  - Этап 2 (title-match): для каждой visible БД — exact match title → DB_TITLES → assign category. Если все 4 категории матчнулись по title → return (zero schema calls, дешёвый happy path).
  - Этап 3 (schema-fallback): для категорий, которые НЕ матчнулись по title — для каждой нерезерванной visible БД через client.databases_retrieve(db_id) проверить наличие обязательных properties из новой helper-функции _required_props(category). Match → assign.
  - Конфликты (1 БД матчит >1 категории, или 2 БД матчат одну категорию по schema) НЕ затереть тихо — записать в structured warning, который Branch A может вывести в error message.
  - Backward compat: существующие тесты (test_run_wizard_join_existing*) продолжают работать без изменений.
