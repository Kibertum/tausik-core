## Goal

ЗАМЕР, смена #277. Аудит доказательств разрешает путь цитаты БУКВАЛЬНО. Цитата, написанная голым именем файла — «test_brain_config.py» вместо «tests/test_brain_config.py», — не совпадает ни с одним путём в истории git и получает вердикт never_existed, то есть «git НИКОГДА этого не имел». Проверено: tests/test_brain_config.py существовал и удалён коммитом 77703c4a (отказ от Notion). Из 39 таких находок 27 относились к файлам, которые git имел.

ПОЧЕМУ ЭТО ХУДШАЯ СТОРОНА ОШИБКИ. Вердикт never_existed есть обвинение прошлого закрытия в ФАБРИКАЦИИ доказательства. Ошибиться в эту сторону дороже, чем пропустить настоящую выдумку: незаслуженное обвинение обесценивает весь регистр, и читатель начинает пролистывать его целиком — ровно тот механизм, из-за которого в этом релизе пришлось объявлять остаток вместо вечного HIGH.

ЧТО НАДО ПРОВЕРИТЬ ПЕРЕД ПРАВКОЙ, а не принять: сколько цитат в дереве написаны голым именем файла. Если много — разрешение пути надо расширять; если единицы и все из одной эпохи — дешевле поправить сами цитаты. Числом решается, где правка.

ЧЕГО НЕЛЬЗЯ: молча искать имя файла где угодно в дереве. Два файла с одним именем в разных каталогах — обычное дело, и «нашлось похожее» вместо «совпало» превратит проверку доказательств в угадывание.

## Acceptance Criteria

AC-1 ЗАМЕР ПЕРВЫМ: названо числом, сколько цитат в дереве написаны голым именем файла и из каких эпох. Число решает, править разрешение пути или сами цитаты. AC-2 Цитата голым именем, чей файл git имел под tests/, больше НЕ получает вердикт never_existed. AC-3 НЕГАТИВ, главный: настоящая выдумка ПО-ПРЕЖНЕМУ ловится — имя, которого git не имел ни под каким каталогом, остаётся never_existed. AC-4 НЕГАТИВ второй: двусмысленность не выдаётся за совпадение — если имя встречается в двух каталогах, вердикт говорит об этом, а не выбирает один. AC-5 Разобранные в смене #277 поправки не переписываются: журнал append-only, и 27 записей EVIDENCE-RETIRED остаются как есть.
