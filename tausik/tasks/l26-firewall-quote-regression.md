## Goal

ДЕФЕКТ МОЕГО ЖЕ ФИКСА fc89495, найден adversarial-ревью и подтверждён эмпирически 2026-07-18. Эвристика гашения кавычек в _scan_target неверна в основании: кавычки НЕ означают что текст инертен. Подтверждённые обходы, каждый ПРОХОДИТ сейчас и БЛОКИРОВАЛСЯ до фикса: (1) rm -rf в кавычках вокруг слеша — аргумент гасится, остаётся rm -rf без цели, паттерн не матчится; (2) git push с флагом force в кавычках — флаг гасится до применения regex; (3) timeout 10 bash -c с опасной командой в кавычках, а также exec и nice — обёртка стоит в позиции команды, не входит в список интерпретаторов, поэтому настоящий интерпретатор двумя токенами дальше не проверяется. Верный дискриминатор не кавычки, а ГРАНИЦЫ ТОКЕНОВ: у реальной команды слова это ОТДЕЛЬНЫЕ токены, у прозы в кавычках они внутри ОДНОГО токена. Плюс поиск интерпретатора должен идти по ВСЕМ токенам, а не только в позиции команды.

## Acceptance Criteria

1. Все три подтверждённых обхода снова блокируются: rm -rf с закавыченным слешем, git push с закавыченным флагом force, обёртки timeout/exec/nice перед bash -c с опасной командой. 2. Исходный false-positive остаётся исправленным: tausik task log с опасной SQL-фразой в тексте проходит. 3. Дискриминатор — границы токенов, а не кавычки: токен, содержащий пробелы, считается полезной нагрузкой и заменяется placeholder-ом; однословные токены сохраняются как есть. 4. Интерпретатор ищется по ВСЕМ токенам, а не только в позиции команды, чтобы обёртка его не скрывала; список пополнен Windows-оболочками (cmd, powershell, pwsh, wsl). 5. НЕГАТИВНЫЙ КЕЙС: sqlite3 с SQL в кавычках блокируется (интерпретатор), а echo с той же фразой не блокируется. 6. НЕГАТИВНЫЙ КЕЙС: некорректная команда с несбалансированными кавычками сканируется целиком (консервативно). 7. Каждый из трёх обходов покрыт отдельным регресс-тестом, который падает на текущем коде. 8. Все прежние тесты TestBashFirewall зелёные; ruff чист; 3.11 и 3.13.
