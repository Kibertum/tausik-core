## Goal

Ревью L3 (шесть агентов, review #41) вернуло FAIL по коммиту 4896bbf. Два критических подтверждены лично, оба — регрессии, внесённые этим коммитом.

БЛОКЕР 1. skills_official_count выводится из skills-official/registry.json, а каталог skills-official/ стоит в .gitignore:53 и в индексе git его НЕТ (git ls-files даёт 0 файлов). В отслеживаемый constants.json записано 20. На чистом клоне count_official_skills возвращает 0, gen_doc_constants.py --check сравнивает точным равенством и падает. CI выполняет ровно эту команду (.github/workflows/tests.yml:78 и :128). Сверх того count_official_skills глотает OSError/JSONDecodeError и отдаёт 0 — а автофиксер переписывает по константе, то есть сломанный registry.json тихо превращает «20 official skills» в «0 official skills» в README и AGENTS.md. Ровно та тихая ошибка, против которой писан весь коммит, только на стороне счётчика.

БЛОКЕР 2. Задача закрыта, ROADMAP.md не перевыпущен: tests/test_release_roadmap.py::test_the_committed_map_is_not_stale красный на закоммиченном дереве. Мой полный прогон был снят ДО task done, поэтому заявление в сообщении коммита «полный прогон 9389 passed» для закоммиченного дерева неверно.

ГЛАВНОЕ ПО СУЩЕСТВУ. Тезис коммита воспроизведён внутри самого коммита на уровень выше: реестр субъектов объявляет шесть предметов, а на живом дереве находят столбец только три (mcp_main_tools, hooks_count, skills_core_count). stacks_count, roles_count и review_agents_count не совпадают НИ С ОДНИМ заголовком ни в одном из четырнадцати сканируемых файлов, но мета-тест засчитывает их привязанными, потому что спрашивает НАЛИЧИЕ КЛЮЧА в реестре, а не факт совпадения. Мутация: заменить три их регулярки на несовпадающие — все тесты зелёные. И test_the_live_tree_is_clean остаётся зелёным при ПУСТОМ реестре: «чисто» неотличимо от «ничего не искал».

ОСТАЛЬНОЕ, ПРОВЕРЯЕМОЕ: docs/en/architecture.md:109 «145 project tools + 7 brain tools = 128» — ложь на лице строки, RU-двойник говорит 152 и проверяется; AGENTS.md:111-112 внутри ``` — «12 core skill definitions», «25+ official/vendor», «5 role profiles» при 13, 20 и 6; docs/{en,ru}/mcp.md:391/389 «128 tools ~ 51/52 KB» при 152 и ~62 KB; docs/ru/agent-contract.md:220 «149 инструментов (145 project + 7 brain)»; шаблоны codebase-rag не совпадают с настоящей формулировкой mcp.md:7 («adds 7 tools», «total with it is 159 tools»), то есть причина исключения в TABLE_SUBJECT_EXEMPT частично ложна; шаблон «main N count» не заякорен и автофиксер перепишет любую чужую прозу; --skip-mcp-counts теперь молча выключает пять чужих семейств счётчиков; пять из шести заголовков реестра всё ещё сравниваются полным совпадением (^...$), то есть предок починен только для MCP; заголовок Hook/Хук цепляет 14 таблиц ИМЁН хуков; докстринги doc_drift_scanners («400-line cap», «three-module split») и doc_drift_tables («few dozen lines» при 99) говорят неправду; doc_drift_common «Covered drift classes» не обновлён, тогда как соседний обновлён; для code_counts.py тестов нет вообще.
