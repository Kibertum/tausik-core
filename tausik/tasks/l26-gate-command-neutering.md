## Goal

Остаток от l26-config-trust-tiers, обнаружен там же adversarial-прогоном. Трастовые тиры закрыли отключение гейта через enabled/severity/trigger/file_extensions, а валидация команд теперь применяется и к переопределениям дефолтных гейтов (раньше _validate_custom_gate вызывался только для имён вне DEFAULT_GATES — клон репозитория мог направить gates.ruff.command на произвольный бинарник). НО остаётся вектор: команду можно заменить на ИНЕРТНУЮ, оставаясь внутри allow-list. Пример: gates.ruff.command = "python -c pass" — python разрешён, гейт формально включён, срабатывает на своих триггерах и всегда зелёный. Так же ruff можно свести к "ruff --version". Задача: спроектировать политику для команд гейтов. Варианты к рассмотрению: (а) охранять command как «project-тир не может менять команду ДЕФОЛТНОГО гейта, только добавлять флаги» — проверять, что команда начинается с дефолтного префикса; (б) требовать, чтобы исполняемый файл в переопределении совпадал с исполняемым файлом дефолта (ruff остаётся ruff, менять можно только аргументы) — это выглядит наиболее точным и дешёвым; (в) отказаться от охраны и записать вектор в поверхность угроз честно. Решение должно сохранить легитимный кейс vendor/bin/phpstan (тот же исполняемый файл по другому пути — вариант (б) его пропускает через сравнение basename). Негативный сценарий: некорректная или пустая команда в переопределении не должна ронять загрузку гейтов.

## Acceptance Criteria

AC-1: Извлечение basename исполняемого файла (снятие пути POSIX/Windows и суффикса .exe) вынесено в ОДНУ функцию в gate_command_policy.py, которой пользуется и существующая проверка allow-list, и новый guard. Второй копии этой логики в дереве нет (проверяется grep-ом). Покрыто юнит-тестами: голое имя, POSIX-путь, Windows-путь, .exe.

AC-2: Переопределение команды ДЕФОЛТНОГО гейта, у которого basename исполняемого файла отличается от basename дефолтной команды, отвергается: гейт сохраняет дефолтную команду, в лог пишется предупреждение с именем гейта и обоими basename. Тест: gates.ruff.command = "python -c pass" даёт загруженный гейт ruff с дефолтной командой, а не с подменённой.

AC-3: Легитимный кейс vendor/bin/phpstan проходит: gates.phpstan.command = "vendor/bin/phpstan analyse --level=8" принимается целиком, потому что basename совпадает с дефолтом. Тест на этом же примере.

AC-4: Изменение аргументов при том же исполняемом файле принимается (guard ограничивает исполняемый файл, а не аргументы). Тест: gates.ruff.command = "ruff check --select=E" принимается.

AC-5 (честность, вариант «в»): Остаточный вектор — сведение гейта к инертному вызову ТОГО ЖЕ исполняемого файла ("ruff --version", "pytest --collect-only") — сравнением basename не обнаруживается принципиально и записан в поверхность угроз в docs/ru и docs/en явным текстом, а не умолчанием. Проверяется grep-ом по обоим документам.

AC-6: Кастомные гейты, чьих имён нет в DEFAULT_GATES, сохраняют текущее поведение — только allow-list, без ограничения на basename (сравнивать не с чем). Тест подтверждает, что кастомный гейт с разрешённым исполняемым файлом по-прежнему загружается.

AC-7: Переопределение, добавляющее команду встроенному гейту без дефолтной команды (например filesize), отвергается с предупреждением, а гейт остаётся встроенным.

Negative: некорректное переопределение команды НЕ должно приводить к ошибке загрузки гейтов. Пустая строка, строка из пробелов и отсутствие ключа command обрабатываются без исключения: load_gates отрабатывает до конца и возвращает полный набор гейтов с дефолтами. Отсутствие дефолтной команды у гейта тоже не должно вызывать исключение. Покрыто параметризованным тестом.
