## Goal

ЗАМЕР, сессия #178: origin (GitLab) содержит 405 коммитов и 3403 файла; github/main — 13 коммитов и 1069 файлов; git merge-base между ними пуст, то есть это ORPHAN-снимок, а не ветка общей истории. Публикация сегодня есть вычищенный снимок, накатываемый вручную, и потому GitHub систематически отстаёт — тикеты #7 и #8 заведены внешним автором против коммита 623fb4e.

ТРЕБОВАНИЕ ВЛАДЕЛЬЦА: наружу уезжает только фреймворк; GitLab становится ЗЕРКАЛОМ GitHub. Это инверсия: источником истины становится публичный репозиторий.

ГЛАВНЫЙ ВОПРОС, КОТОРЫЙ ЗАДАЧА ОБЯЗАНА ЗАДАТЬ ДО ЛЮБОЙ РАБОТЫ, а не решить молча: публикуется ли история из 405 коммитов, или публичная история начинается с нуля и приватная остаётся архивом? Первое требует полного аудита утечек по ВСЕЙ истории, а не по снимку — прежний аудит проверял именно снимок. Второе дешевле и честнее, но теряет происхождение, а происхождение мы продаём.

ЧТО ВЫЯСНЕНО И НЕ ТРЕБУЕТ РАБОТЫ: сайт из ядра уже вынесен, tausik/site есть отдельный репозиторий, остатков в core нет (проверено ls и поиском по tausik.tech). Разделение репозиториев в этой части выполнено.

ЧТО ОСТАЁТСЯ ПОМИМО ГЛАВНОГО ВОПРОСА: чем определяется, какие 1069 файлов из 3403 уезжают наружу — это правило сейчас нигде не записано как проверяемое; куда девается проекция tausik/ (сегодня на публичном зеркале лежит ровно один файл gates.json); переезжает ли сайт на GitHub тоже или остаётся только в GitLab. НЕГАТИВНОЕ: до ответа на главный вопрос не трогать remote и не переписывать историю.

## Acceptance Criteria

AC1. ГЛАВНЫЙ ВОПРОС ОТВЕЧЕН ВЛАДЕЛЬЦЕМ, решение #257: публичная история начинается ВПЕРЁД от текущей точки, 405 коммитов остаются приватным архивом на GitLab, историю НЕ переписываем. Проекция tausik/ ПУБЛИКУЕТСЯ. Три измеренные причины отказа от переписывания записаны в решении.
AC2. БАЗА ВЫЧИЩЕНА ПЕРВОЙ, а не проекция. Строки живут в .tausik/tausik.db и регенерируются в дерево первым же task log — правка одной проекции есть работа, которую фреймворк сам отменит. Вычищены: адрес внутреннего хоста, имена чужих проектов, локальные пути с именем пользователя.
AC3. ПРОЕКЦИЯ ПЕРЕСОБРАНА ИЗ ВЫЧИЩЕННОЙ БАЗЫ (state export), а не отредактирована руками. Ручная правка проекции запрещена: она разойдётся с базой при следующем экспорте.
AC4. НЕГАТИВНЫЙ СЦЕНАРИЙ: скан прогоняется ПОВТОРНО после чистки и обязан дать ноль по всем четырём классам. Скан, прогнанный только до чистки, ничего не доказывает о том, что уезжает.
AC5. НЕГАТИВНЫЙ СЦЕНАРИЙ: публикационный коммит строится ПОВЕРХ существующего GitHub main, а не вместо него. Проверяется тем, что 623fb4e остаётся достижимым, 22 тега не двигаются, PR #5 остаётся mergeable.
AC6. PUSH НЕ ДЕЛАЕТСЯ, пока владелец не увидел точный список команд и результат сухого прогона. Публикация необратима.
AC7. Правило 'что уезжает наружу' записано проверяемо. После решения #257 оно простое — всё, что в git, — и потому обязано быть закреплено тестом или гейтом, а не подразумеваться.
