## Goal

КЛЮЧЕВАЯ ЗАДАЧА 1.9 — на ней стоят P8, P9 и весь контрактный контур. RENAR §8: TC есть самостоятельный артефакт со своим жизненным циклом draft → ready → passing | failing, а не строка в коде. У него две части разной природы: НОРМАТИВНАЯ живёт в проверяемом артефакте, ИНСТРУМЕНТАЛЬНАЯ — код теста — вне эталона и пишется после нормы.

У нас есть только инструментальная половина: 5722 функции pytest, ни одна из которых не ссылается на утверждение, не знает версии требования и не имеет состояния.

ЭТО И ЕСТЬ МЕХАНИЧЕСКАЯ ПРИЧИНА РАЗМНОЖЕНИЯ ТЕСТОВ. Ключевая строка стандарта: покрытие считается ОТ УТВЕРЖДЕНИЙ АРТЕФАКТА, А НЕ ОТ ЗАДАЧ. Сегодня «больше тестов» выглядит как «больше добросовестности», и ни одно число этому не противоречит. Как только покрытие считается от утверждений, шестой тест на уже покрытое утверждение не двигает ни одну величину, по которой судят агента. Стимул исчезает сам — без запрета и без лимита.

ОБЯЗАТЕЛЬНЫЙ СОСТАВ: verifies[] на артефакт И ЕГО ВЕРСИЮ с симметричным verified-by; requirement-version, дающий ТОЧНОЕ устаревание при инкременте требования; ПАРНЫЙ НЕГАТИВНЫЙ TC на каждое покрытое утверждение, кроме случая, когда утверждение само есть негативный инвариант; закрытый список шести типов business, ux, system, contract, eval, security; automation.kind static | dynamic, где static означает, что runner есть статический анализатор; last-run пишет только runner-actor.

СЛЕДСТВИЕ, КОТОРОЕ УДЕШЕВЛЯЕТ РАБОТУ: automation.kind static легализует НАШИ ГЕЙТЫ как исполнителей TC. ruff, filesize, bootstrap_drift, memory-route — это TC типов system и security, которые никогда себя так не объявили. Переход идёт не с нуля: слой runner-ов работает, ему не хватает нормативной половины и объявления. Смыкается с senar-14-gates-declare-the-effect-they-prevent — одна работа на два стандарта.

ЧТО ДЕЛАЕТСЯ С 5722 СУЩЕСТВУЮЩИМИ: НИЧЕГО РАЗОМ. Решение принимается ПО МОДУЛЮ В МОМЕНТ КАСАНИЯ — тесты переписываемого рождаются как TC, тесты нетронутой периферии остаются регрессионной обвязкой под честным именем. Дозаполнение отвергнуто отдельно и записано тупиком: прослеживаемость, восстановленная задним числом, есть изготовленная прослеживаемость, и в масштабе 5722 она даст полную таблицу, которой нельзя верить.

НЕГАТИВНОЕ ОГРАНИЧЕНИЕ: до готовности TC НЕ ОБЪЯВЛЯТЬ публично, что старые тесты не являются доказательством. Правило «обещание не восстанавливается раньше механизма» действует зеркально — доказательство не отзывается раньше, чем построена замена.
