## Goal

ЗАМЕР #225: tests/test_push_ok_cli.py::TestCmdPushOkE2E::test_push_ok_writes_ticket_via_wrapper упал в полном прогоне с «error: cannot determine HEAD commit (no git repo or no commits yet)»; в одиночку — зелено; два соседних полных прогона на том же дереве — зелены. Отказ невоспроизводим по содержанию.  ЗАМЕР СМЕНЫ #232 ОПРОВЕРГ ПЕРВУЮ ПРАВДОПОДОБНУЮ ГИПОТЕЗУ. `_git` в scripts/cli_push_ok.py зовёт git с потолком 3 с и на TimeoutExpired возвращает None — то есть таймаут печатается тем же текстом, что и отсутствие репозитория. Гипотеза «под нагрузкой git не уложился в 3 с» проверена измерением: 60 вызовов `git rev-parse HEAD` в свежем временном репозитории во время полного прогона набора дали min 20 мс, медиану 37 мс, p95 92 мс, max 232 мс; ВЫШЕ ПОТОЛКА — 0 из 60. Запас тринадцатикратный. Таймаут причиной не является.  ЧТО ОСТАЁТСЯ ГЛАВНЫМ ДЕФЕКТОМ, И ОН НЕ ЗАВИСИТ ОТ ПРИЧИНЫ: сообщение НАЗЫВАЕТ ПРИЧИНУ, КОТОРУЮ НЕ ПРОВЕРЯЛО. Три разных события — репозитория нет, коммитов нет, git не ответил вовремя, git отказал с ошибкой — печатаются одной фразой про отсутствие репозитория. Поэтому единственное наблюдение отказа оказалось НЕДИАГНОСТИРУЕМЫМ: по сообщению нельзя отличить состояние среды от сбоя вызова. Это тот же класс, что решение #334 (неизмеренное выдаётся за измеренное), только в диагностике.  ЧТО ДЕЛАЕТСЯ: (1) тест становится ГЕРМЕТИЧНЫМ — собственный HOME и git-конфиг, ни одна унаследованная GIT_* не доезжает до подпроцесса, — что снимает весь класс средовых причин по построению, не требуя знать конкретную; (2) диагностика перестаёт врать: отказ называет, ЧТО именно произошло, включая stderr самого git и отдельный текст для таймаута.  ЗАПРЕЩЕНО ЗАДАЧЕЙ И НЕ ДЕЛАЕТСЯ: retry вокруг подпроцесса. Он скрыл бы причину и превратил тест в датчик, который больше ничего не измеряет.

## Acceptance Criteria

AC1. ОТКАЗ НАЗЫВАЕТ ТО, ЧТО ПРОИЗОШЛО. Отсутствие репозитория, отсутствие коммитов, таймаут вызова и ошибка git различимы в тексте отказа; сообщение больше не утверждает причину, которую не проверяло.

AC2. STDERR GIT ДОХОДИТ ДО ЧИТАТЕЛЯ. Когда git отказал, его собственное объяснение печатается, а не выбрасывается: следующее наблюдение обязано быть диагностируемым по логу, а не по догадке.

AC3. ТЕСТ ГЕРМЕТИЧЕН. Подпроцесс получает СОБСТВЕННЫЕ HOME и git-конфигурацию, а унаследованные GIT_* переменные не передаются. Проверяется тем, что тест зелен при враждебном GIT_DIR в окружении родителя.

AC4 (НЕГАТИВНЫЙ, ГЛАВНЫЙ). RETRY НЕ ДОБАВЛЯЕТСЯ. Тест доказывает, что вызов git делается ОДИН раз: повтор скрыл бы причину и сделал бы датчик неизмеряющим.

AC5 (НЕГАТИВНЫЙ). ТАЙМАУТ НЕ ВЫДАЁТСЯ ЗА ОТСУТСТВИЕ РЕПОЗИТОРИЯ. Тест подставляет вызов, который заведомо не укладывается в потолок, и требует, чтобы текст отказа говорил про таймаут, а не про репозиторий.

AC6. ОПРОВЕРГНУТАЯ ГИПОТЕЗА ЗАПИСАНА С ЧИСЛАМИ. Замер, снявший версию про таймаут, попадает в журнал задачи: следующий читатель не должен перепроверять то, что уже измерено.

AC7. ГРАНИЦА. Потолок в 3 секунды НЕ поднимается: замер показал тринадцатикратный запас, и подъём был бы правкой по догадке.
