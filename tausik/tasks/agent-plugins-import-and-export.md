## Goal

Формат Agent Plugins принимается и выдаётся, а наша подписная цепочка работает этажом выше него — не конкурируя с форматом, которого у него нет.

## Acceptance Criteria

1. Прочитана спецификация 1.0.0 целиком, и вывод записан решением: AP v1 — ТОЛЬКО формат пакета. Подписей нет, целостности нет, дистрибуции нет; containment-правила прямо не песочница; авторизация оставлена клиенту. Это не конкурент нашей цепочке, а этаж под ней.
2. Использована опора, которая у нас уже есть: §7.1 требует соответствия скиллов канону agentskills.io — тому самому, который валидирует scripts/skill_spec_conformance.py. Второй валидатор НЕ пишется.
3. `tausik skill install <dir>` принимает plugin-директорию: автодетект plugin.json, валидация схемы, СВЕРХУ существующая проверка подписи. Discovery учитывает, что дети skills/ берутся без рекурсии.
4. `tausik stack export --format agent-plugin` отдаёт plugin.json и mcp.json. Наш .mcp.json сегодня непереносим: в нём "command": "${CLAUDE_PROJECT_DIR:-.}/..." — проверено, три вхождения, — а AP требует command одним токеном БЕЗ плейсхолдеров, разрешая ${PLUGIN_ROOT} и ${PLUGIN_DATA} только в args, env и cwd. Экспорт обязан переписывать это, а не копировать.
5. Подпись кладётся в свою reverse-domain-директорию (io.senar.tausik или подобную) — спецификация это прямо разрешает, чужие клиенты её игнорируют, ничего не ломается.
6. НЕГАТИВНЫЙ сценарий: плагин БЕЗ подписи принимается только как явно недоверенный источник, через существующую threat-model, с громким предупреждением. Тихая установка неподписанного плагина ЗАПРЕЩЕНА — иначе мы теряем ровно то, чем ценны.
7. НЕГАТИВНЫЙ сценарий: экспортированный пакет проверяется установкой хотя бы в один ЧУЖОЙ клиент. «Соответствует схеме» без запуска — не доказательство переносимости.
8. У TSC в Future considerations заявлена возможная модель подписей в v2. Заведено наблюдение: если она появится, сводить нашу схему с их, а не поддерживать две молча.
