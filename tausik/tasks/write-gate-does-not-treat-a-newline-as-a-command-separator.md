## Goal

НАЙДЕНО ЗАМЕРОМ В #205, ВНУТРИ ЗАДАЧИ ci-does-not-run-on-the-release-branch. Гейт записи объявлен блокирующим и обходится одной пустой строкой.

КОРЕНЬ: ПЕРЕВОД СТРОКИ НЕ ЯВЛЯЕТСЯ РАЗДЕЛИТЕЛЕМ КОМАНД. Разбор bash в scripts/hooks/bash_write_parse.py делит текст по ;, &&, ||, конвейеру — но НЕ по переводу строки. Токены следующей строки достаются предыдущей команде как позиционные аргументы.

ЗАМЕР ПАРСЕРОМ write_targets, четыре формы:
  1. echo hi + перевод строки + cp a b            даёт ПУСТО. Запись невидима вовсе.
  2. cp a f.yml + перевод строки + echo done      даёт [done]. Настоящее назначение f.yml ПОТЕРЯНО, выдумано done.
  3. sed -i s/a/b/ f.yml + перевод + sed -n 1p g.yml   даёт [f.yml, sed, 1p, g.yml]. Два фантома.
  4. Те же команды по ОДНОЙ строке разбираются верно. Дефект только на многострочном тексте.

ПРОВЕРЕНО НАСТОЯЩИМ ХУКОМ, НЕ ОДНИМ ПАРСЕРОМ. Контроль: однострочная запись в .tausik/probe_gate_hole.txt вне объявленного ACL — ЗАБЛОКИРОВАНА штатно. Та же запись, которой предшествует строка echo probing, — ПРОШЛА: файл 723996 байт лёг вне объявленного объёма задачи. Пробный файл удалён сразу.

ПОЧЕМУ ЭТО НЕ ЛОЖНОЕ СРАБАТЫВАНИЕ, А ДЫРА. Опасное направление — не фантом, а ПРОПУСК. Достаточно, чтобы первой строкой шла любая команда-не-писатель с позиционными аргументами, и всякая запись на последующих строках для гейта не существует. Многострочный вызов Bash есть обычный способ работы агента, то есть обход не надо искать — в него попадают случайно.

НАПРАВЛЕНИЕ. Делить текст на команды ДО токенизации, считая перевод строки разделителем наравне с точкой с запятой, и учитывая продолжение строки обратным слэшем, кавычки и heredoc. Есть два готовых образца ХОДА в этом же каталоге: python_invocation.py (#203) и shell_redirection.py (#204) — отдельный измеримый модуль, правило вместо перечня. Повторить ХОД, а не логику построчно.

НАЧАТЬ С ЦИФРЫ, НЕ С ПОЧИНКИ. Инвентарь мест ДО оценки: сколько форм разделителей разбор знает сейчас, и матрица форм-разделителей на команды-писатели — как в #204 мерили 10 на 15. Число в этом заголовке ИЗМЕРЕННОЕ по четырём формам, а не граница: ожидается, что найдётся больше (heredoc, продолжение строки, подстановка команд).
