## Goal

НАЙДЕНО В СЕССИИ #124, побочно. Признак всплыл как падение test_mcp_integration.py:324 при двух параллельных полных прогонах: `WinError 32 ... файл занят другим процессом: .tausik\config.json.tmp -> .tausik\config.json`. Гонка за файл — это следствие; причина в том, ЧТО за файл идёт гонка.

ВОСПРОИЗВЕДЕНИЕ (проверено трижды, детерминированно). Убрать ключ `mypy` из живого `.tausik/config.json`, прогнать ОДИН тест `tests/test_mcp_integration.py -k gates_enable_valid`, перечитать конфиг: в нём появилось `"mypy": {"enabled": true}`. Тест зелёный, файл проекта изменён. Никакого следа в git status нет — `.tausik/` в .gitignore.

КОРЕНЬ. `.claude/mcp/project/handlers.py:592` — `"tausik_gates_enable": lambda svc, args: _handle_gate_toggle(args["name"], True)`. Параметр `svc` принимается и НЕ ПЕРЕДАЁТСЯ. Сам `_handle_gate_toggle` (там же, строка 1252) зовёт `load_config`/`save_config` из project_config, а те резолвят путь от корня реального проекта. То есть операция объявлена проектной, а исполняется глобальной: фикстура `svc` в тесте честно строит ProjectService на tmp_path, и это не имеет никакого значения.

ПОЧЕМУ ЭТО НАШ КЛАСС ДЕФЕКТА, А НЕ НЕУДОБСТВО ТЕСТА. Меняется НЕ произвольный файл, а состав включённых гейтов — то есть сам режим верификации. Тест молча переписывает то, чем проверяется код. Сегодня он гейт ВКЛЮЧАЕТ, и это выглядит безобидно; ровно тот же путь (`tausik_gates_disable`) гейт ВЫКЛЮЧАЕТ, и тогда проект начнёт проверять меньше, ничего об этом не сказав. Признака в выводе нет ни в том, ни в другом случае.

ОТДЕЛЬНО — УТРАЧЕННОЕ ЗНАНИЕ. Я НЕ МОГУ доказать, каким было значение `mypy` до сессии: набор тестов успел отработать раньше, чем я посмотрел, и перезаписал его. Конфиг восстановлен в наблюдавшееся состояние (`enabled: true`, что согласуется с «9 registered» у doctor), но это восстановление ПО НАБЛЮДЕНИЮ, а не по доказательству. Это и есть цена дефекта: он уничтожает свидетельство о самом себе.

ОБРАЗЕЦ ПРАВИЛЬНОГО ЕСТЬ В РЕПОЗИТОРИИ. `tests/test_gates.py::test_gates_enable_disable` делает то же самое корректно: фикстура `tausik_env` даёт tmp_path + env, и проверка читает конфиг ИЗ tmp_path. То есть вопрос не «как надо», а почему MCP-путь пошёл мимо.

## Acceptance Criteria

1. `_handle_gate_toggle` БОЛЬШЕ НЕ СОДЕРЖИТ второй формулы переключения гейта: тело сводится к делегации в канон `project_config.set_gate_enabled`. Проверка: в harness/claude/mcp/project/handlers.py нет вызовов save_config.
2. Путь конфига берётся ИЗ svc, а не из cwd: `_handle_gate_toggle` получает svc и выводит каталог из `svc.be.db_path`. Дефолт (svc=None → find_tausik_dir) сохранён для CLI-совместимости.
3. Обе точки диспетчера (tausik_gates_enable, tausik_gates_disable) передают svc — параметр больше не принимается и не игнорируется.
4. `set_gate_enabled` принимает явный каталог; при его отсутствии поведение побайтово прежнее (find_tausik_dir).
5. ИСПРАВЛЕН ВТОРОЙ ДЕФЕКТ, вскрытый при разборе: старый `_handle_gate_toggle` круглым рейсом писал ЭФФЕКТИВНЫЙ конфиг (load_config, слитый с user/managed тирами) обратно в ПРОЕКТНЫЙ файл — ровно то, от чего предостерегает докстринг load_project_config. После правки в проектный файл попадает только проектный тир.
6. ИСПРАВЛЕН ТРЕТИЙ ДЕФЕКТ: старый путь рапортовал «Gate enabled» независимо от вердикта trust-политики. После делегации отчёт выводится из ЭФФЕКТИВНОГО конфига и называет отказ поимённо (это уже реализовано в set_gate_enabled).
7. МЕХАНИЧЕСКИЙ ГЕЙТ НА КЛАСС (память #236): autouse-фикстура в tests/conftest.py снимает отпечаток живого .tausik/config.json и ПАДАЕТ, называя тест поимённо, если тот его изменил. Гейт ловит не только gate-toggle, а любую будущую утечку записи в конфиг реального проекта.
8. ГЕЙТ ПРОВЕРЕН ВНЕСЁННОЙ ПОЛОМКОЙ: временный откат правки handlers.py роняет гейт с именем теста; результат зафиксирован в журнале задачи.
9. Гейт НЕ ПАДАЕТ, когда живого .tausik/config.json нет вовсе (свежий клон, CI) — отсутствие файла не дрейф; появление файла, которого не было, — дрейф.
10. Воспроизведение из карточки закрыто: прогон `pytest tests/test_mcp_integration.py -k gates` не меняет живой .tausik/config.json (сверка sha256 до/после).
