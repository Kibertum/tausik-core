## Goal

НАЙДЕНО ЗАМЕРОМ В #205 ПРИ ИНВЕНТАРЕ МЕСТ ДЛЯ ci-does-not-run-on-the-release-branch. Гейт верификации релиза красный, и краснота никого не разбудила.

ЗАМЕР ПО API GITHUB. Лента Tests на main: три последних прогона ПОДРЯД суть failure — 32895740027, 32890507221, 32881343325, все от 2026-08-25. Последний зелёный — 2026-08-04. То есть шесть дней красноты на момент замера, и это ровно те коммиты, которыми публиковалась работа 1.9.

РАСКЛАД ПО ПОЛОСАМ, а не по впечатлению. Зелёные: lint, test-full, ubuntu 3.11/3.12/3.13, macos 3.11/3.12/3.13. Красные: windows-latest на 3.11, 3.12 и 3.13 — все три. Итог полосы: 5 failed, 7095 passed, 135 skipped, 128 deselected.

ПРИЧИНА ВИДНА В ЛОГЕ, НЕ УГАДАНА. Пять тестов tests/test_consumer_layout.py запускают subprocess.run([bash, ./_find_engine_file_probe.sh]) и полагают, что bash есть Git Bash. На образе windows-latest первым в PATH стоит System32\bash.exe — пусковая заглушка WSL. Дистрибутива в ней нет, поэтому rc=1, а stdout приходит в UTF-16 с текстом Windows Subsystem for Linux has no installed distributions. Тесты: test_the_memory_route_gate_is_reachable_in_a_plain_clone, test_the_search_does_not_step_into_the_parent_directory, test_the_engines_own_repo_prefers_its_source_over_the_deployed_copy, test_a_gate_that_cannot_find_itself_says_so, test_a_gate_switched_off_by_decision_stays_quiet.

ЭТО НЕ КЛАСС #204. four-tests-fail-in-a-bare-checkout чинил свежесть выгрузки и бил на всех платформах; здесь Linux и macOS зелёные, предмет — РАЗРЕШЕНИЕ ИМЕНИ bash на конкретном образе. Проверять отдельно и не считать закрытым тем фиксом.

ДВА ПРЕДМЕТА, И ВТОРОЙ ВАЖНЕЕ ПЕРВОГО. (1) Тесты обязаны брать ИМЕННО Git Bash, а не первое попавшееся имя bash, либо честно пропускаться, когда его нет, — но не краснеть про чужое. (2) КРАСНАЯ ЛЕНТА ШЕСТЬ ДНЕЙ НЕ ПРИВЕЛА НИ К ЧЕМУ. Гейт, чью красноту никто не читает, ничем не отличается от выключенного, и это тот же урок, что и вся история gates-declare-what-they-prevent.

НАЧАТЬ С ЦИФРЫ, НЕ С ПОЧИНКИ. Инвентарь мест: сколько ВСЕГО тестов зовут bash или иной интерпретатор по голому имени — мерить перечнем по tests/, а не по этим пяти. Число в заголовке ИЗМЕРЕННОЕ по одному прогону, а не граница.

## Acceptance Criteria

AC-0. ИНВЕНТАРЬ МЕСТ ДО ОЦЕНКИ, ПО ВЫЗОВУ. Замерено перечнем по tests/: вызовов bash в subprocess ЧЕТЫРЕ, а не пять. Два в test_consumer_layout.py (строки 270 и 383) - НЕЗАЩИЩЁННЫЕ, через них проходят пять падающих тестов. Два в test_wrapper_smoke.py (110, 126) - защищены skipif по os.name == nt, на Windows не исполняются вовсе. Прочие голые имена в тестах - git, и он заглушкой не подменяется. Число в заголовке (пять) есть число ТЕСТОВ, а мест ДВА: заголовок и инвентарь мерят разное, и это записано.

AC-1. ЗАМЕР ЛЕНТЫ ПО API ДО ПОЧИНКИ, ПЕРЕПРОВЕРЕН СЕГОДНЯ. Подтверждено вызовом gh: три последних прогона Tests на main суть failure (32895740027, 32890507221, 32881343325, все 2026-08-25), последний зелёный 2026-08-04. Красных полос ровно три - windows-latest на 3.11, 3.12, 3.13; ubuntu и macos на всех трёх версиях зелёные, как и lint и test-full. Срок красноты на СЕГОДНЯ (2026-09-03) - ДЕВЯТЬ дней, а не шесть: цифра в описании задачи устарела, и она пересчитана, а не переписана. Причина прочитана в логе: args=['bash', './_find_engine_file_probe.sh'], rc=1, stdout в UTF-16 с текстом про отсутствие дистрибутива WSL.

AC-2. ТЕСТ БЕРЁТ РАБОТАЮЩИЙ bash, А НЕ ПЕРВОЕ ИМЯ. Выбор делается ПРОБОЙ, а не списком путей: кандидат считается годным, если исполняет тривиальный скрипт и возвращает ожидаемое. Заглушка WSL пробу не проходит по построению - её не надо узнавать по имени или по тексту про дистрибутив. Если ни один кандидат не годен, тест ЧЕСТНО пропускается, а не краснеет про чужое. Проверено: подсунутая заглушка, ведущая себя как System32 bash.exe, приводит к выбору другого кандидата либо к skip, но НИКОГДА к красному.

AC-3. ХРАПОВИК ПРОТИВ ПОВТОРЕНИЯ - ПРАВИЛО, А НЕ СПИСОК ИЗ ПЯТИ. Тест запрещает вызывать интерпретатор ГОЛЫМ ИМЕНЕМ в subprocess по всему tests/, кроме объявленного baseline, который может только сокращаться. Шестой такой вызов, добавленный завтра, падает у автора, а не через девять дней на чужой полосе.

AC-4. ВТОРОЙ ПРЕДМЕТ, КОТОРЫЙ ВАЖНЕЕ ПЕРВОГО: КРАСНОТА СТАНОВИТСЯ ЧИТАЕМОЙ ТАМ, ГДЕ ОНА ВАЖНА. Гейт, чью красноту никто не читает, неотличим от выключенного. Вердикт опубликованной ленты предъявляется на ЧОКПОЙНТЕ ПУБЛИКАЦИИ - в push-ok, единственной команде, которая и так стоит перед каждым push и и так требует сети. Требования: (а) при доступном gh и сети печатается текущий вердикт последнего прогона с номером и датой; (б) недоступность gh, сети или таймаут дают ЯВНОЕ 'не проверено' с причиной, а НЕ молчаливое ОК - это тот же класс, что вся история про 'не смогло выполниться неотличимо от прошло'; (в) проверка НЕ БЛОКИРУЕТ выдачу тикета: решение о публикации остаётся за владельцем, задача проверки - показать, а не запретить; (г) таймаут жёсткий, чтобы push-ok не завис.

AC-5. МУТАЦИИ. Снятие пробы bash (возврат к голому имени) роняет храповик; снятие честного 'не проверено' в push-ok (замена на молчаливое ОК) роняет тест. Ни одна мутация не ДОБАВЛЯЕТ проверку. Красноту предъявить.

AC-6. РЕГРЕССИЙ НЕТ. Полная лента зелёная, счёт прочитан СТРОКОЙ passed/failed (память #529), mypy чисто, ruff чисто, doctor All clean, гейт размера не превышен.
