## Goal

ПОРУЧЕНИЕ ВЛАДЕЛЬЦА: построенное обязано использоваться, а не лежать. Предыдущая задача сделала маршрут ИСПОЛНИМЫМ и видимым для MCP-first; эта делает так, чтобы инструмент ВЫБИРАЛСЯ в момент, когда у агента есть альтернатива.

ЗАМЕР ПО СОБСТВЕННЫМ РАСШИФРОВКАМ (смена #233, 5966 вызовов инструментов, 735 ходов пользователя):

  dead-end          0 применений. НИ ОДНОГО. При том что тупиков в одной смене было минимум четыре, и все они ушли в журналы задач и сообщения коммитов.
  tausik symbol     2 применения против 226 обращений grep за определением — инструмент построен час назад и не выбирается.
  checkpoint        механизма нет вовсе; по правилу «каждые 30-50 вызовов» ожидалось бы около 149.
  task log          222 применения = один на 26 вызовов инструментов (правило говорит «после каждого шага»).
  memory add        104 применения.

ОБЩИЙ ПРЕДМЕТ У ЧЕТЫРЁХ ПУНКТОВ ОДИН: инструмент существует, правило его требует, и ничто не соединяет их в момент выбора. Правило, соединённое с выбором только памятью агента, исполняется настолько, насколько агент вспомнил, — и приведённые числа показывают, насколько это.

ЧТО ДЕЛАЕТСЯ, ЧЕТЫРЬМЯ МЕЛКИМИ ИЗМЕНЕНИЯМИ ОДНОЙ ФОРМЫ:
1. Закрытие задачи, у которой в журнале есть маркер опровержения («опроверг», «refuted», «не сработало», «гипотеза снята»), называет `dead-end` поимённо вместо общего «No knowledge captured». Правило не насаждается отдельным хуком — оно складывается туда, где закрытие и так проверяется.
2. Обращение grep за ОПРЕДЕЛЕНИЕМ символа получает подсказку с готовой командой `tausik symbol <имя>` — тем же хуком и с той же дисциплиной «один раз на предмет за смену», что и подсказка MCP-first.
3. Напоминание о чекпойнте выдаёт уже существующий счётчик вызовов, а не новый механизм.
4. Частичный список команд в тексте правил заменяется одной строкой с их ЧИСЛОМ и указанием `tausik --help`. Это не только честнее (18 из 52 команд агент не видел), но и КОРОЧЕ: текст правил пере-отправляется агенту каждый ход и держится в бюджете 80-180 строк.

НЕ ДЕЛАЕТСЯ: ужесточение MCP-first. Подсказка развёрнута час назад, её эффекта ещё нет ни в одном замере, и менять механизм до появления числа значило бы решать по ощущению.

## Acceptance Criteria

AC1. ЗАКРЫТИЕ НАЗЫВАЕТ `dead-end` ТОГДА, КОГДА В ЖУРНАЛЕ ЕСТЬ ОПРОВЕРЖЕНИЕ. Задача, чей журнал содержит маркер снятой гипотезы, при закрытии получает поимённое напоминание про `dead-end`, а не общее «знание не записано». Задача без такого маркера его НЕ получает.

AC2. ПОДСКАЗКА ПРО СИМВОЛ СРАБАТЫВАЕТ НА ПОИСКЕ ОПРЕДЕЛЕНИЯ И НИ НА ЧЁМ ДРУГОМ. `grep -n "def foo"` даёт готовую команду `tausik symbol foo`. Обычный поиск по тексту (grep по строке, по пути, по слову без def/class) подсказки НЕ получает.

AC3. ЧЕКПОЙНТ НАПОМИНАЕТСЯ СУЩЕСТВУЮЩИМ СЧЁТЧИКОМ. Новый механизм не заводится: счётчик вызовов уже развёрнут на обоих хостах с хуками, и порог берётся из правила.

AC4. ТЕКСТ ПРАВИЛ СТАЛ КОРОЧЕ И ЧЕСТНЕЕ. Частичный список команд заменён числом и указанием `--help`; число ВЫВОДИТСЯ из парсера, а не вписывается руками. Сгенерированный файл правил не вырос.

AC5 (НЕГАТИВНЫЙ, ГЛАВНЫЙ). НИ ОДНА ПОДСКАЗКА НЕ ПОВТОРЯЕТСЯ И НЕ БЛОКИРУЕТ. Один раз на предмет за смену; ни один вызов не отклоняется. Подсказка, которую читатель научился пропускать, отнимает внимание у следующего настоящего предупреждения.

AC6 (НЕГАТИВНЫЙ). ЛОЖНОГО СРАБАТЫВАНИЯ НА ЧУЖОМ ТЕКСТЕ НЕТ. Слово `def` внутри строки, пути или прозы не считается поиском определения; маркер опровержения внутри цитаты не считается опровержением.

AC7. ЭФФЕКТ ЗАМЕРЯЕТСЯ, А НЕ ОБЪЯВЛЯЕТСЯ. Числа этой задачи (0 dead-end, 2 против 226, отсутствие чекпойнта) записаны как БАЗА, чтобы следующая смена могла сравнить, а не поверить.

AC8. ГРАНИЦА. MCP-first не ужесточается до появления замера; новые команды и инструменты не заводятся; поведение существующих не меняется.
