## Goal

ЗАМЕР НУЖЕН, смена #275: вывод verify, task show, status и события MCP попадает в контекст целиком и пересылается на каждом следующем ходу до конца смены. Обрезание теряет данные, вставка целиком раздувает историю; правильный ответ — писать в файл и возвращать путь, размер и короткий хвост, дальше агент читает диапазон или грепает. У TAUSIK эта механика частично есть: tausik_session_open уже отдаёт ПРОЕКЦИЮ вместо полного вывода (~3 КБ вместо ~49 КБ) ровно по этой причине. Задача — распространить приём на остальные крупные ответы, начав с замера, какие именно крупные.

## Acceptance Criteria

AC-1 ЗАМЕР ПЕРВЫМ: названы инструменты, чей средний ответ превышает порог, с числами из журнала. Порог объявлен, а не подразумевается. AC-2 Крупный ответ пишется в файл и возвращает путь, размер и хвост; ОБРЕЗАНИЯ нет — названо прямо, потому что обрезание теряет данные молча. AC-3 Агент может дочитать: путь указан так, что чтение диапазона и поиск работают без догадок. AC-4 НЕГАТИВ: маленький ответ НЕ уезжает в файл — лишний ход дороже сэкономленных токенов.
