## Goal

Owner, session #263: development is turning into a hell of tests, in TAUSIK and in every project it is applied to, and this was said more than once without being written down. Measured in this session: the full 10,480-test lane was run locally four times as a search tool for bookkeeping reds; the close of a docs/measurement task printed six notes demanding test refs, a Negative: line and a Domain: line; two pages had a number retyped three times because a test re-asserted an exact count. Three fixes, in the rules and the nudges — not in the tests: (1) the shipped HARD_CONSTRAINTS (bootstrap_templates, every project's rules file) and this project's CLAUDE.md state the rule — scoped verify for the change, the full suite in CI and once at the release gate, tests on behaviour and never on a number in a document or a generated file's freshness (generated files are regenerated by the act that moves their source), one test that goes red on the defect over a suite that goes red on bookkeeping; the QG-0 line no longer demands a negative scenario for work that has no behaviour; (2) gate_ac_check.check_verification_checklist skips the four test-shaped notes (checklist-missing, test-ref, negative, domain) when every relevant file is prose — docs, notes, changelogs, plans; a code-bearing task keeps them; (3) the rule is recorded as an owner decision and a convention in memory so it is not said a fourth time.

## Acceptance Criteria

AC-1: bootstrap_templates.HARD_CONSTRAINTS carries a "Verification is proportionate" bullet and the QG-0 bullet no longer demands a negative scenario for behaviour-less work; CLAUDE.md of this project carries the same rule in one line under the 4096-byte cap (tests/test_claude_md_size.py). AC-2: gate_ac_check.check_verification_checklist returns none of the four test-shaped notes for a task whose relevant_files are all prose (.md/.txt/.rst or under docs/), and still returns them for a task with a .py in scope — tests/test_verification_is_proportionate.py, both cases. AC-3: an owner decision (tausik decide) and a convention memory record the rule with today's measurements. AC-4 (negative, by the rule itself): no new test asserts a number in a document; the change is verified by the scoped run of its own files, not by a local full lane.
