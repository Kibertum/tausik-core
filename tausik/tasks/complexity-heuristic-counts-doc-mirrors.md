## Goal

Предупреждение «declared X but touched N files — implies Y» сработало в сессиях #130-#133 подряд, и артефакт каждый раз один: обязательные по конвенции #275 CHANGELOG.md + CHANGELOG.ru.md, зеркала README.md + README.ru.md, генерируемый docs/_generated/constants.json и автообновляемый CLAUDE.md дают +6 файлов ЛЮБОЙ задаче, включая правку в одну строку. В сессии #133 задача с правкой двух функций и тестов насчитала 12 файлов и была объявлена недооценённой как 'complex'. Предупреждение при этом ЗАПИСЫВАЕТСЯ ДЛЯ АУДИТА, то есть портит метрику калибровки: сейчас в БД накапливается «систематическое занижение сложности», которого нет — есть систематический шум измерения. Задача: считать сложность по файлам, которые несут ИЗМЕНЕНИЕ ПОВЕДЕНИЯ, исключив (а) файлы, обязательные по гейтам для любой задачи (оба CHANGELOG, CLAUDE.md), (б) генерируемые артефакты (docs/_generated/**), (в) зеркала переводов, если правится и оригинал. Обязательно: пересчитать на исторических закрытиях и показать, что доля срабатываний упала, а задачи, реально бывшие complex, по-прежнему помечаются. Не понижать порог вслепую — иначе предупреждение перестанет ловить настоящие случаи, ради которых заведено.

## Acceptance Criteria

1. Счётчик считает файлы, НЕСУЩИЕ ИЗМЕНЕНИЕ ПОВЕДЕНИЯ: из набора исключаются (а) файлы, обязательные по гейтам для любой задачи (CHANGELOG.md, CHANGELOG.ru.md, CLAUDE.md), (б) генерируемые артефакты (docs/_generated/**), (в) зеркало перевода схлопывается с оригиналом (README.ru.md + README.md = один файл; docs/ru/X.md + docs/en/X.md = один). Правило вынесено в отдельную функцию с тестами на каждый пункт.
2. ОБРАТНАЯ СВЯЗЬ ПРОВЕРЕНА НА ИСТОРИИ, а не на выдумке: по закрытым задачам с непустым relevant_files посчитаны старый и новый вердикт. Показано ЧИСЛОМ, сколько срабатываний исчезло, и приведён поимённо список задач, у которых вердикт изменился.
3. Предупреждение НЕ ОСЛАБЛЕНО там, ради чего заведено: среди задач, у которых вердикт изменился, вручную проверено, что ни одна не была настоящей сложной работой с заниженным объявлением; и наоборот — предъявлена хотя бы одна историческая задача, которая по-прежнему помечается после правки. Пороги _SIMPLE_MAX_FILES/_MEDIUM_MAX_FILES НЕ понижаются и НЕ повышаются: чинится измеряемая величина, а не шкала.
4. Догфуд: на relevant_files закрытия full-pytest-hangs-while-scoped-pytest-is-green (13 файлов, объявлено medium, старое правило кричало 'implies complex') новое правило даёт 9 файлов и вердикт medium, то есть замечания нет. Проверено тестом на этом конкретном наборе.
5. НЕГАТИВНЫЕ И ГРАНИЧНЫЕ СЦЕНАРИИ (каждый — тест): пустой список и None дают 0 без исключения; задача, состоящая ТОЛЬКО из церемониальных файлов (оба CHANGELOG + CLAUDE.md), даёт 0 несущих файлов и НЕ помечается; одинокое зеркало без оригинала (правится только README.ru.md) считается как файл, а не отбрасывается — иначе правка перевода станет невидимой; путь с обратными слэшами Windows (docs\_generated\constants.json) отбрасывается наравне с прямыми; дубликаты в relevant_files не удваивают счёт; исключение внутри фильтра НЕ роняет task_done — закрытие проходит, предупреждение просто не печатается (сохранены гарантии gotcha #271 и решения #158).
6. Событие supervision по-прежнему пишется при НАСТОЯЩЕМ занижении и по-прежнему не пишется при честном объявлении.
