## Goal

Гипотеза, выведенная из memory #293, НЕ проверенная — первым шагом задачи её надо подтвердить или опровергнуть эмпирически. `scripts/hooks/bash_firewall.py` ведёт собственный разбор опасных команд (rm -rf, DROP TABLE, force push и т.д.) и имеет свой `_split_subcommands`, но нормализации подкоманды, добавленной в `bash_cmd_norm.py`, у него нет. Если предположение верно, то `sudo rm -rf /` и `bash -c 'rm -rf /'` проходят firewall так же, как `env bash -c 'echo x > f'` проходил write-гейт до фикса — то есть блокировка опасных команд обходится тем же однострочником. Проверить обязательно ОБА направления: (а) пропускает ли firewall опасную команду за префиксом/обёрткой; (б) не даст ли подключение нормализации новых false-positive, которые у firewall дороже, чем у write-гейта — он блокирует разрушительные операции, и ложный блок останавливает работу. Если гипотеза не подтвердится — закрыть won't-do с доказательством, как это сделано с hook-skip-emit-before-jurisdiction-check.

2. Направление false-positive проверено тем же способом: безопасные команды, упоминающие опасную фразу как ДАННЫЕ (tausik task add --goal "... DROP TABLE ...", git-подобное имя программы, grep-иголка), дают exit 0 — и до, и после любой правки.

4. Если гипотеза опровергнута — задача закрывается won't-do с dead-end, содержащим доказательство и критерий возврата (по образцу #290); если подтверждена — фикс + CHANGELOG [Unreleased] + зелёный tausik verify.

Якорь _CMD_START = (?:^|[\s;&|()`]) не содержит кавычки, а _OPT_PATH требует завершения на / или \ — значит перед `git` стоит `'`, и НИ ОДИН из четырёх WARN-паттернов не срабатывает. BLOCKED_PATTERNS (подстрока, без якоря) при этом срабатывают — поэтому rm -rf / во вложенной обёртке блокируется, а все git-паттерны нет. Асимметрия и объясняет, почему дыру не видели.
