## Goal

ЗАМЕР СМЕНЫ #233 ПО ЖИВЫМ УДАЛЁННЫМ РЕПОЗИТОРИЯМ (ls-remote, не по памяти #181/#189) — и он поправляет две детали самой задачи:    публичных тегов (github): 9; приватных (origin): 17; локальных: 22   только у origin (9): v1.1.0 v1.2.0 v1.3.0 v1.3.2 v1.3.7 v1.4.0 v1.4.1 v1.4.2 v1.5.2   только у github (1): v1.5.3   общих имён: 8 — И ВСЕ ВОСЕМЬ УКАЗЫВАЮТ НА РАЗНЫЕ ОБЪЕКТЫ. Совпадающих нет НИ ОДНОГО.   локальные и origin совпадают по всем 17 общим именам полностью.  ПОПРАВКИ К ЗАДАЧЕ: (1) v1.7.0 на GitHub ЕСТЬ (bf13a09e), задача утверждала обратное; (2) расхождение не «два одноимённых», а восемь из восьми. Плюс пять локальных тегов не уехали даже в origin.  ГЛАВНЫЙ ВОПРОС ЗАДАЧИ РЕШЁН, И РЕШЁН ИНЖЕНЕРНО, А НЕ ВКУСОМ. Тег на публичной линии есть ОБЕЩАНИЕ ПОТРЕБИТЕЛЮ: README велит подключать репозиторий сабмодулем, сабмодуль пинится SHA или тегом, и молчаливое перемещение публичного тега переставляет чужой пин на другое дерево. Тем же доводом в этом проекте уже запрещён force-push, и git сам отказывается перетирать теги словами «would clobber existing tag». Считать иначе значит считать, что у нас нет потребителей, — а README утверждает обратное.  СЛЕДСТВИЕ, КОТОРОЕ И ЕСТЬ РАБОТА: существующие публичные теги НЕ двигаются никогда; тринадцать недостающих задним числом НЕ выставляются; расхождение ОБЪЯВЛЯЕТСЯ и охраняется механизмом, а начиная с 1.9 тег релиза выставляется на публичной линии как ЧАСТЬ выкладки, чтобы новые имена не расходились.

## Acceptance Criteria

AC1. ПРАВИЛО ЗАПИСАНО ТАМ, ГДЕ ЕГО ИЩУТ, В ОБЕИХ ЯЗЫКОВЫХ ВЕРСИЯХ: публичный тег — обещание, он не двигается; расхождение объявлено таблицей с измеренными объектами, а не прилагательным.

AC2. СНИМОК ПУБЛИЧНЫХ ТЕГОВ ЗАФИКСИРОВАН В РЕПОЗИТОРИИ. Девять пар «имя → объект» лежат в версионируемом файле вместе с датой и способом снятия, чтобы «тег не двигался» было проверяемым утверждением, а не воспоминанием.

AC3. ДВИЖЕНИЕ ЛЮБОГО ПУБЛИЧНОГО ТЕГА КРАСНЕЕТ. Сверка живого ls-remote с зафиксированным снимком идёт через существующую tags_unmoved; изменение, появление и исчезновение — все три считаются движением.

AC4 (НЕГАТИВНЫЙ). НЕДОСТУПНАЯ СЕТЬ ДАЁТ ЧЕСТНЫЙ ПРОПУСК, А НЕ ЗЕЛЁНОЕ. Проверка, которая при отсутствии сети молча проходит, утверждает то, чего не проверяла (решение #334). Пропуск обязан называть себя пропуском.

AC5 (НЕГАТИВНЫЙ). НИ ОДИН ТЕГ НЕ ПЕРЕВЫПУСКАЕТСЯ И НЕ УДАЛЯЕТСЯ ЭТОЙ ЗАДАЧЕЙ. Проверяется тем, что живой снимок ПОСЛЕ работы совпадает со снимком ДО неё — сравнением, а не намерением.

AC6. ПРОЦЕДУРА ВЫКЛАДКИ ДОПОЛНЕНА ШАГОМ О ТЕГЕ. Начиная с 1.9 тег релиза ставится на публичной линии как часть выкладки; иначе следующее имя разойдётся так же, как разошлись восемь предыдущих.

AC7. ГРАНИЦА. История репозиториев не трогается, публикация не производится, недостающие теги задним числом не выставляются.
