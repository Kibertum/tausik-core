## Goal

Найдено в сессии #153 при ревизии revise-kb-export-tasks-superseded, попутно к сверке карточек.

ЧТО. Текстовые поля сущностей (goal, scope_exclude, rationale, content, notes) содержат обрывки СИНТАКСИСА ВЫЗОВА ИНСТРУМЕНТА: закрывающие теги полей и открывающие теги следующих параметров. Замер по дереву tausik/: 64 файла, 147 строк — задачи 31, память 26, решения 7. Примеры: tausik/tasks/brain-decide-publishes-unclassified-rationale.md — goal обрывается на «</goal>» и следом строка «<parameter name="complexity">medium», то есть в поле goal уехал хвост собственного вызова агента вместе со значением СЛЕДУЮЩЕГО параметра. tausik/tasks/agent-units-recording.md — в scope_exclude уехали два целых блока invoke, включая последующий вызов task_start. tausik/decisions/qg-2-security-pattern-directory-anchored-only-no-bare.md — в rationale уехало шесть строк чужого вызова, включая команду Bash с task done.

ПОЧЕМУ ЭТО ДЕФЕКТ, А НЕ КОСМЕТИКА. Три следствия, каждое проверяемо. (1) Поле содержит значение, которого агент туда не клал: «complexity: medium» в теле goal — это параметр, не съеденный парсером, значит вызов был принят частично и НИКТО не заметил, что часть аргументов потеряна. Это ровно «тихая ошибка», к которой в проекте нулевая толерантность. (2) Загрязнение уезжает в git-проекцию, смысл которой — читаемость замысла в PR (эпик team-state-in-git): критерии приёмки читаются как спека, а в спеке лежит XML чужого вызова. (3) Загрязнённый текст попадает в FTS-индекс и в блок памяти, инъектируемый в контекст каждой сессии, то есть агент читает мусор как знание.

ПОЧЕМУ СЕЙЧАС. Дерево tausik/ теперь коммитится, поэтому загрязнение стало видимым в диффах и будет только накапливаться. Уборка без гарда бессмысленна — натечёт снова.

НЕ ДЕЛАТЬ: не чистить регуляркой вслепую по всему дереву. Часть совпадений может быть ЛЕГИТИМНОЙ прозой (запись памяти, намеренно цитирующая формат вызова, — например brain-init-creates-new-4-brain-dbs). Отличать по признаку «обрывок незакрытой конструкции» от «цитата в тексте», спорные случаи разбирать поштучно и называть в журнале.

## Acceptance Criteria

1. Запись с синтаксисом вызова инструмента в текстовом поле ОТВЕРГАЕТСЯ на входе сервисного слоя, а не чистится потом: попытка записать в goal, acceptance_criteria, scope, scope_exclude, notes, rationale или content значение, содержащее незакрытую конструкцию вызова, возвращает ошибку с указанием поля. Тест падает до фикса.
2. Гард стоит в ОДНОМ месте на пути записи, а не в каждом мутаторе: покрытие даётся свойством (конвенция #354), и добавление нового текстового поля не требует помнить про гард. В журнале названо, где именно проходит граница и почему она одна.
3. ТОЧНОСТЬ ГАРДА ИЗМЕРЕНА НА ЖИВЫХ ДАННЫХ ДО ВКЛЮЧЕНИЯ (конвенция #351): гард прогнан по всем 64 файлам дерева со 147 совпадениями, и в журнал выписано, сколько из них он считает порчей, а сколько — легитимной прозой. Для КАЖДОГО расхождения с ручной разметкой названа причина. Гард, дающий ложные срабатывания на цитатах формата вызова в записях памяти, к включению не принимается.
4. Уборка накопленного выполнена ПОШТУЧНО и обратимо: для каждого исправленного файла в журнале названо, что удалено и на каком основании; спорные случаи разобраны отдельно и оставлены, если это цитата в прозе. Массовой замены по регулярному выражению не производится. После уборки `tausik state export --check` зелёный, а grep по дереву даёт ноль обрывков.
5. НЕГАТИВ. (а) Легитимная проза не отвергается: запись памяти, НАМЕРЕННО цитирующая формат вызова инструмента в тексте, по-прежнему сохраняется — тест на такой записи. (б) Существующие сущности после уборки читаются и импортируются: `tausik state import --dry-run` не сообщает об ошибках разбора. (в) Гард не глотает ошибку молча — отказ виден вызывающему, а не пишется в лог.
6. Полный pytest зелёный; ruff и mypy чистые.
