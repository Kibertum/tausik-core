## Goal

НАЙДЕНО НЕМЕДЛЕННО ПОСЛЕ КОММИТА, смена #237, по предупреждению самого git.

ФАКТ. При добавлении tausik/graph-snapshots/pre-v1.9.0.json.gz git сказал: «CRLF will be replaced by LF the next time Git touches it». Проверка закоммиченного объекта: на диске 157751 байт, в коммите 157749, gzip не проходит проверку CRC — BadGzipFile. Файл выглядит сохранённым и НЕ ЧИТАЕТСЯ.

ПОЧЕМУ ЭТО ХУЖЕ ОТСУТСТВИЯ. Снимок нужен один раз — когда собирают релиз и спрашивают, что изменилось в связях. Именно тогда и выяснится, что базовый снимок нечитаем, и сравнить будет не с чем. Ни один механизм об этом не сообщит: git считает файл сохранённым, тесты его не открывают, гейты не смотрят.

ПРИЧИНА. В .gitattributes есть правила для двух производных деревьев (renar/, tausik/) с явным text eol=lf, но нет правила для двоичного. Снимок — gzip, и любое правило про переводы строк для него разрушительно.

ПРЕДМЕТ: пометить снимки двоичными, перезаписать испорченный объект и ЗАКРЫТЬ ТЕСТОМ, потому что иначе дефект вернётся с первым же новым видом двоичного артефакта.

## Acceptance Criteria

AC1. Снимок помечен двоичным в .gitattributes, и закоммиченный объект БАЙТ В БАЙТ равен файлу на диске. AC2. Испорченный объект перезаписан: git show закоммиченного снимка распаковывается без ошибки CRC. AC3. ЗАКРЫТО ТЕСТОМ, а не правилом: тест берёт каждый файл tausik/graph-snapshots/*.json.gz, читает его через gzip и требует успеха — так дефект не вернётся с новым видом двоичного артефакта. AC4. Негативная половина: тест обязан УМЕТЬ покраснеть — подаётся заведомо испорченный поток и требуется отказ, иначе проверка, всегда зелёная на пустом каталоге, ничего не утверждает.
