## Goal

Ревью caveman (первое для этой фичи) нашло 3 critical + 2 high + 2 medium. ГЛАВНОЕ: output_mode читается из config (= full_cfg['bootstrap'], вложенная секция), а дока и docstring говорят про КОРЕНЬ .tausik/config.json — как у context_tier. Воспроизведено: resolve_output_mode(full_cfg)='caveman', resolve_output_mode(config)='off'. Пользователь ставит задокументированный ключ → генераторы получают off → bootstrap печатает «Done!», exit 0, сжатия нет, предупреждения нет. ТИХИЙ NO-OP — ровно тот класс, ради которого весь релиз 1.7.0. Мой e2e-«тест» передавал output_mode прямо в генераторы, минуя проводку, поэтому ничего не поймал: доказал генераторы, а не фичу. Плюс: preserve-if-exists молча не применяет режим к уже забутстрапленному проекту; doctor-drift слеп к output_mode; doctor-caveman ложно срабатывает на подстроку 'caveman'; мой тест test_build_full_body_is_the_only_consumer — ВТОРАЯ тавтология за сессию (грепает bootstrap_generate на имена функций, живущие в project_cli_task.py, т.е. не может упасть); CHANGELOG/quickstart переобещают работающее поведение.

## Acceptance Criteria

1. output_mode резолвится из КОРНЯ конфига тем же путём, что context_tier (main() → _cfg_for_tier), и тредится через bootstrap_ide параметром; bootstrap_opencode.generate_opencode_rules получает УЖЕ отрезолвленное значение, а не редеривит из чужого словаря. Локальный _resolve_output_mode в bootstrap_opencode удалён (один канонический резолвер). 2. НЕГАТИВНЫЙ СЦЕНАРИЙ (обязателен, ловит именно этот баг): integration-тест пишет РЕАЛЬНЫЙ .tausik/config.json с корневым output_mode=caveman, гоняет НАСТОЯЩИЙ путь bootstrap_ide (не build_full_body в изоляции) и проверяет, что сгенерированный CLAUDE.md содержит директиву. ОШИБКА, если тест зелёный на текущем сломанном коде — то есть тест обязан краснеть ДО фикса. 3. preserve-if-exists больше не молчит: если output_mode=caveman, а целевой файл уже существует и директивы в нём нет — ГРОМКОЕ предупреждение с указанием, что сделать. ОШИБКА, если bootstrap печатает успех, не применив явно запрошенный режим. 4. service_doctor_drift передаёт output_mode в build_full_body и сообщает, когда режим включён, а директивы в развёрнутом файле нет. 5. doctor-caveman: не ложносрабатывает на подстроку 'caveman' в произвольном месте settings.json (парсить JSON, смотреть команды hooks). Тест с проектом, где 'caveman' встречается в невинном контексте → НЕ warn. 6. test_build_full_body_is_the_only_consumer переписан на настоящую проверку (грепать РЕАЛЬНЫЕ модули-писатели: project_cli_task.py, harness/*/mcp/project/handlers*.py) либо удалён. ОШИБКА, если тест не может упасть. 7. quickstart EN+RU: caveat про preserve-if-exists. 8. CHANGELOG не переобещает: заявление о режиме соответствует фактическому поведению после фикса. 9. Обе полосы зелёные (-m '' И дефолт); doctor чист.
