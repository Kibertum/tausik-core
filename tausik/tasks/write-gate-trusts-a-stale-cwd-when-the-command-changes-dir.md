## Goal

РЕГРЕССИЯ, ВНЕСЁННАЯ В #205 СОБСТВЕННЫМИ ПРАВКАМИ, НАЙДЕНА РЕВЬЮ #6 И ВОСПРОИЗВЕДЕНА НА ЖИВЫХ ХУКАХ.

ЧТО СЛОМАНО. Поле cwd в payload PreToolUse есть каталог ДО выполнения команды. Разбор делит текст на подкоманды, но НЕ отслеживает cd между ними. Поэтому команда, которая сама переходит в каталог проекта и затем пишет, резолвится от УСТАРЕВШЕГО каталога.

ЗАМЕР РЕВЬЮ, сквозной через bash_write_gate (активная задача, scope_paths docs/**, helper.py в проекте пишет абсолютный путь в scripts/):
  python helper.py                  cwd=проект   exit 2 БЛОК
  cd ПРОЕКТ && python helper.py     cwd=scratch  exit 0 РАЗРЕШЕНО
  cd ПРОЕКТ && python helper.py     без поля cwd exit 2 БЛОК   (это ДОПРАВОЧНОЕ поведение)
  (cd ПРОЕКТ; python helper.py)     cwd=scratch  exit 0 РАЗРЕШЕНО

ТО ЕСТЬ ДЛЯ ЭТОЙ ФОРМЫ КОМАНДЫ СТАРЫЙ КОРЕНЬ БЫЛ ВЕРНЫМ, А МОЙ СТАЛ НЕВЕРНЫМ. Это ровно то ПОД-обнаружение, которое запрещал мой же AC-4 обеих задач. Fail-soft на отсутствующем файле довершает дело молча: ни ошибки, ни события деградации, ни понижения уверенности.

ПОЧЕМУ Я ЭТОГО НЕ ПОЙМАЛ. Ни в одном моём тесте обеих задач НЕТ команды с cd внутри. Я проверял «стою в чужом дереве», но не «команда сама уходит в другое дерево». Замер покрыл то, что я вообразил, а не то, что делает оболочка.

НАПРАВЛЕНИЕ ПОЧИНКИ. Не угадывать конечный каталог, а ПАДАТЬ В СТОРОНУ БЛОКИРОВКИ: если в тексте команды есть переход каталога (cd, pushd, env -C), резолвить по ОБОИМ корням и брать объединение целей. Ложный блок дороже пропуска для контроля сдерживания, и объединение возвращает прежнее поведение там, где оно было верным, не теряя починки для обычных команд.

ОБЪЁМ ПОЧИНКИ ОГРАНИЧЕН РЕГРЕССИЕЙ по решению владельца: чиним ТОЛЬКО то, что стало ХУЖЕ, чем было. Критичное (memory_pretool_block через write_targets_with_confidence) и остальное ревью заводится отдельными задачами.

## Acceptance Criteria

1. РЕГРЕССИЯ ВОСПРОИЗВЕДЕНА МНОЮ САМИМ, а не принята со слов ревью: предъявлены три прогона живого хука — команда без cd, команда с cd, и та же команда без поля cwd (доправочное поведение). Показано, что блок превратился в разрешение.
2. ПОЧИНЕНО ПАДЕНИЕМ В СТОРОНУ БЛОКИРОВКИ: при переходе каталога внутри команды цели берутся по ОБОИМ корням (объединение), а не угадывается конечный каталог.
3. ФОРМЫ ПЕРЕХОДА ПОКРЫТЫ ПЕРЕЧНЕМ, А НЕ ОДНОЙ: cd, подоболочка со скобками, pushd, env -C. Для каждой предъявлен прогон.
4. ПОЧИНКА НЕ ВОЗВРАЩАЕТ ИСХОДНЫЙ ЛОЖНЫЙ БЛОК: команда БЕЗ перехода каталога, работающая в чужой выгрузке, по-прежнему проходит. Проверено тестом — иначе я просто откачу обе задачи смены.
5. МУТАЦИИ на свой предмет; ни одна не ДОБАВЛЯЕТ проверку (память #503).
6. Полная лента зелёная, mypy чисто, doctor All clean.
