## Goal

ОБЪЯВЛЕНО В scope_exclude ЗАДАЧИ write-gate-parses-command-text-not-writes (смена #201) И ЗАВЕДЕНО ОТТУДА, а не обнаружено само по себе. Там был закрыт канал Bash: `python [опции] скрипт.py` теперь читается, и литеральные цели записи внутри скрипта проходят то же решение ACL, что и прямая запись (bash_write_parse._script_file_writes). Канал PowerShell не трогался СОЗНАТЕЛЬНО, чтобы задача не разрослась.

ЧТО ПРОВЕРИТЬ ПЕРВЫМ ДЕЛОМ, ЗАМЕРОМ, А НЕ ЧТЕНИЕМ. Подать хуку событие с tool_name PowerShell и командой, запускающей скрипт, который пишет файл вне ACL, и прочитать код возврата. Ожидание — ноль, то есть тот же пропуск; но это ГИПОТЕЗА, и задача начинается с её проверки. Если пропуска нет, задача закрывается замером с объяснением, почему каналы разошлись.

ПОЧЕМУ ЭТО НЕ КОПИЯ ПРЕДЫДУЩЕЙ ЗАДАЧИ. PowerShell — ПЕРВИЧНАЯ оболочка этой платформы (CLAUDE.md), то есть канал, которым команда пойдёт по умолчанию. Дефект на первичном канале весит больше, чем на вторичном. Кроме того у pwsh свой диалект запуска (`python x.py`, `& python x.py`, `Start-Process`), и переиспользовать разбор Bash дословно нельзя.

ГОТОВЫЙ ПРИЁМ, НЕ ИЗОБРЕТАТЬ. bash_write_parse._script_file_writes: интерпретатор в командной позиции, скрипт первым позиционным, `-m`/`-c` файла не имеют, чтение с ограничением размера, мягкая деградация на нечитаемом файле. Узость там не вкус: первая версия читала любой аргумент на .py и заблокировала бы `python -m pytest tests/test_x.py` литералами open(..., "w") из самого тестового файла. Повторить ход, а не логику построчно: если общая часть выделяется без натяжки — выделить, иначе объяснить в коде, почему диалекты не сводятся.

ОБЯЗАТЕЛЬНО, И ЭТО ПОЛОВИНА ЗАДАЧИ. Проверить, что ОБЪЯВЛЕННЫЙ ОСТАТОК канала PowerShell (pwsh_cmd_parse.py:25 несёт ту же формулировку «you must actively obfuscate») не называет неверный разрез — ровно та ошибка, которая была найдена на канале Bash. Память #495: объявленный остаток есть утверждение о системе и проверяется замером самой ОБЫЧНОЙ команды, попадающей под него.

НЕГАТИВНЫЙ СЦЕНАРИЙ ДЛЯ AC: скрипт, пишущий вне ACL и запущенный через канал PowerShell, обязан быть отклонён ЖИВЫМ прогоном хука, а не только юнит-тестом парсера. И зелёная ветвь обязана измеряться: команда, отличающаяся ровно путём записи, обязана проходить.

## Acceptance Criteria

AC-1. ГИПОТЕЗА ПРОВЕРЕНА ЗАМЕРОМ ПЕРВЫМ ДЕЛОМ, ДО ЧТЕНИЯ КОДА И ДО ЛЮБОЙ ПРАВКИ. Живому хуку подаётся событие с tool_name PowerShell и командой, запускающей скрипт, который пишет ВНЕ ACL задачи; читается код возврата. Канал Bash подаётся КОНТРОЛЕМ с равнозначной командой, чтобы каналы СРАВНИВАЛИСЬ, а не один описывался. Матрица включает диалектные формы запуска (голый вызов, оператор &, путь с обратным слэшем) и зелёную ветвь. Итог предъявляется таблицей с кодами возврата. ЕСЛИ ПРОПУСКА НЕТ - задача закрывается этим замером и объяснением, почему каналы разошлись; починка не выдумывается.

AC-2. ОБЪЯВЛЕННЫЙ ОСТАТОК ПРОВЕРЕН, А НЕ ПРОЦИТИРОВАН. Формулировка про 'you must actively obfuscate' в разборе PowerShell есть УТВЕРЖДЕНИЕ О СИСТЕМЕ (память #495). Оно проверяется замером САМОЙ ОБЫЧНОЙ команды, которая под него попадает - запуска скрипта из файла. На канале Bash это утверждение оказалось неверным: разрез проходил не по обфускации, а по 'инлайн против файла'. Сказать, верно ли оно для PowerShell, ЦИФРОЙ; если неверно - переписать текст остатка так, чтобы он называл измеренный разрез.

AC-3. ЕСЛИ ПРОПУСК ЕСТЬ - ПОВТОРЁН ХОД, А НЕ ЛОГИКА ПОСТРОЧНО. Узость разбора Bash сохраняется как ПРАВИЛО: интерпретатор в командной позиции, скрипт первым позиционным, у -m и -c файла нет, чтение с ограничением размера, мягкая деградация на нечитаемом. Общая часть ВЫДЕЛЯЕТСЯ, если выделяется без натяжки, - и она уже выделена задачей выше в модуль python_source_writes, который отвечает 'что этот питоновский исходник открывает на запись' и не знает ни одного диалекта. Если что-то не сводится - объяснить В КОДЕ, почему диалекты не сводятся, а не умолчать.

AC-4. ПЛОМБА ПРОТИВ ПОВТОРНОГО РАСХОЖДЕНИЯ КАНАЛОВ. Дефект существует потому, что канал закрыли на одном диалекте и не закрыли на другом - ровно то же, что случилось сегодня с write_targets и его близнецом. Нужен тест, который перебирает ТАБЛИЦУ ДИАЛЕКТОВ и требует от каждого одинакового ответа на равнозначную команду, чтобы третий диалект не мог появиться с этой дырой. Правило вместо перечня.

AC-5. ЗАМЕР ПОСЛЕ, НА ЖИВОМ ХУКЕ, ОБЕ ВЕТВИ. Скрипт, пишущий вне ACL и запущенный через канал PowerShell, отклонён ЖИВЫМ прогоном хука, а не только юнит-тестом парсера. Зелёная ветвь ИЗМЕРЕНА: команда, отличающаяся ровно путём записи, проходит. Иначе починка есть новый ложный блок на первичной оболочке платформы, что хуже исходного пропуска.

AC-6. МУТАЦИИ. Снятие чтения файла скрипта на канале PowerShell роняет минимум один тест; снятие пломбы из AC-4 роняет минимум один тест. Ни одна мутация не ДОБАВЛЯЕТ проверку (память #503). Красноту предъявить.

AC-7. РЕГРЕССИЙ НЕТ. Полная лента зелёная (счёт прочитан СТРОКОЙ passed/failed - память #529), mypy чисто, ruff чисто, doctor All clean, ни один файл хуков не перешёл 500 строк.
