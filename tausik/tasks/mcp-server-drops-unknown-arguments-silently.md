## Goal

НАЙДЕНО В АУДИТЕ СЕССИИ #158, воспроизведено вживую. Схема tausik_task_show объявляет ровно одно свойство slug. Вызов с лишним story_slug прошёл успешно и вернул задачу — параметр отброшен молча. Валидации входа в сервере нет ни в каком виде: ни jsonschema, ни ручной сверки ключей.

ЦЕНА УЖЕ ЗАПЛАЧЕНА, А НЕ ГИПОТЕТИЧЕСКАЯ. У tausik_task_add свойство называется story_slug, я звал его как story: семь задач эпика artifact-graph и часть из двадцати сирот бэклога созданы без истории, невидимы для roadmap, и охват релиза считал их отсутствующими. Опечатка в имени параметра выглядит как успех.

ПОЧЕМУ ХУЖЕ ОБЫЧНОГО БАГА. MCP — основная поверхность агента, а правило проекта первым пунктом запрещает тихие ошибки. Здесь тихо отказывает не одна команда, а способ звать любую: чем реже параметр обязателен, тем дольше молчание. CLI на тот же промах отвечает громким отказом со списком опций — расхождение двух поверхностей само по себе дефект.

ЧТО СДЕЛАТЬ: сверять ключи входа со свойствами inputSchema ДО вызова обработчика, отказывать с перечислением неизвестных имён и похожих объявленных (story → story_slug). Одна общая точка в диспетчере, не по инструменту.

КРИТЕРИИ ПРИЁМКИ (переносятся в task start): 1) вызов с необъявленным параметром завершается ошибкой, называющей лишний ключ; 2) в отказе есть подсказка по близкому объявленному имени, когда такое есть; 3) НЕГАТИВНЫЙ СЦЕНАРИЙ — тест кладёт лишний параметр и падает, если вызов УСПЕШЕН, то есть краснеет именно на проглатывании; 4) проверка выведена из inputSchema, а не из повторного перечня имён; 5) все существующие вызовы проходят, ни один законный параметр не объявлен лишним.

## Acceptance Criteria

AC1. Вызов любого MCP-инструмента с НЕОБЪЯВЛЕННЫМ параметром завершается ошибкой, которая называет лишний ключ поимённо. Отказ приходит ДО обработчика: обработчик не должен успеть сделать ничего.

AC2. В отказе есть подсказка по близкому объявленному имени, когда такое есть: story → story_slug. Когда близкого нет, отказ перечисляет объявленные имена, а не молчит о них.

AC3. НЕГАТИВНЫЙ СЦЕНАРИЙ, ДВУСТОРОННИЙ. Тест кладёт лишний параметр и КРАСНЕЕТ ИМЕННО НА УСПЕХЕ вызова — то есть падает, если проглатывание вернулось. Парный тест: тот же инструмент с законными параметрами проходит. Односторонний опыт не отличает стража от заглушки, которая отказывает всему.

AC4. Проверка ВЫВЕДЕНА ИЗ inputSchema, а не из второго перечня имён. Конкретно: переиспользуется тот же разворот схемы, которым уже пользуется _usage_hint (server.py:29). Второй список имён рядом с первым есть будущее расхождение, а не проверка. Доказывается мутацией: добавление свойства в inputSchema инструмента делает это имя законным без единой правки в валидаторе.

AC5. РЕГРЕССИИ НЕТ: ни один законный параметр ни одного существующего инструмента не объявлен лишним. Доказывается прогоном всего дерева MCP-тестов, а не выборкой.

AC6. ГРАНИЦА ДЕФЕКТА НЕ РАСШИРЯЕТСЯ. ОБЪЯВЛЕННЫЕ аргументы валидируются нормально уже сегодня — замер сессии #182: task_add громко отказал на слаге длиной 70 при пределе 64 и показал usage. Задача чинит ТОЛЬКО молчание на необъявленных. Проверка типов/диапазонов объявленных свойств в объём НЕ входит.

AC7. Источник правится в harness/, генерируемые копии в .claude/ .cursor/ .kilo/ ПЕРЕСОБИРАЮТСЯ, а не редактируются. Дрейф между источником и копиями проверяется после пересборки.
