## Goal

Шаг 2 из 6 (решение #143, эпик shared-knowledge). Предпосылка для обмена знаниями и для будущего детекта устаревания. Поглощает kb-uid-model (решение #144).  Зачем. Автоинкрементный id принципиально не сливается между клонами: у двух разработчиков запись №217 это разные объекты. Git как канал обмена мы НЕ используем, поэтому слияние обязано опираться на собственную идентичность, а не на трёхстороннее слияние файлов.  Колонки: - memory.entry_uuid — UUIDv7 (время-упорядоченный), идентичность строки, не коллизирует; - memory.origin_id — стабильный идентификатор машины/разработчика, генерируется один раз в .tausik/origin; делает параллельную запись двух разработчиков в одну тему ОБНАРУЖИМОЙ, а не молчаливой перезаписью; - memory.created_at_sha — git rev-parse HEAD на момент записи.  created_at_sha добавляется СЕЙЧАС, хотя используется на шаге 5: без него проверка устаревания невозможна в малошумной форме (нужна дельта «резолвилось при записи, не резолвится на HEAD»), а ретроспективное добавление даёт всем легаси-строкам бессмысленную базу.  Backfill ЭАГЕРНЫЙ и механический, в отличие от консолидации тем: пока хотя бы одна строка без стабильной идентичности, кросс-разработческое слияние невозможно ни для одной строки.  ИЗ ПОГЛОЩЁННОЙ kb-uid-model: memory_edges ссылается на целые локальные id БЕЗ внешнего ключа. Значит при любом импорте рёбра надо перевешивать на кросс-машинные идентификаторы, а ребро на ещё неизвестную запись НЕ терять молча, а помечать отложенным. Целочисленный id остаётся локальным индексом и адресом в CLI. Делать этот шаг ПОСЛЕ первой выгрузки нельзя: первый же обмен тихо перепутает записи, и заметно станет поздно.  Критерий приёмки: у каждой строки memory непустые entry_uuid и origin_id; tausik doctor это проверяет; ни один путь экспорта не использует автоинкрементный id; рёбра memory_edges адресуются через entry_uuid, а неразрешённые рёбра видны как отложенные, а не исчезают.  Негативный сценарий: миграция не должна ломать существующие MCP-тулы памяти, которые сегодня адресуют записи по id — id остаётся, но перестаёт быть ключом обмена.

## Acceptance Criteria

1. У каждой строки memory непустые entry_uuid (UUIDv7) и origin_id; tausik doctor это проверяет.
2. Ни один путь экспорта не использует автоинкрементный id как ключ обмена (id остаётся локальным индексом и адресом в CLI).
3. Рёбра memory_edges адресуются через entry_uuid; неразрешённое ребро помечается ОТЛОЖЕННЫМ, а не исчезает молча.
4. Миграция не ломает существующие MCP-тулы памяти, адресующие записи по id.
