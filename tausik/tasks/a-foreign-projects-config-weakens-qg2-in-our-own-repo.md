## Goal

ЗАМЕР #193, ПРЯМОЙ, из `tausik doctor` и чтения ~/.tausik/config.json. Пользовательский тир — общий для ВСЕХ проектов на машине — несёт два ключа, поставленных ради ДРУГОГО проекта, и оба действуют на репозиторий самого TAUSIK:
  task_done.auto_verify = true. Смысл ключа замерен по коду: config_trust.py:86 называет его выключателем, чья БЕЗОПАСНАЯ позиция — off, а :148 говорит прямо «auto_verify closes a task on an inline run, SKIPPING THE SIGNED RECEIPT». Дефолт фреймворка False (gate_verify_first.py:300). Поставлен в сессии #11 проекта vaflower, причина записана в самом конфиге: классификатор security_pattern.py считает чувствительными /billing/, /payment/, /admin/, /auth/, и у того проекта верификация не кэшируется НИКОГДА. Причина законная — ДЛЯ ТОГО проекта. В комментарии стоит «ВНИМАНИЕ: тир общий для всех проектов».
  gates.bootstrap_drift.enabled = false. Отключён из-за misfire на layout submodule (lib_dir != project_dir), дедэнд #126. В комментарии сказано ДОСЛОВНО: «в самом репозитории TAUSIK (lib_dir == project_dir) гейт работает верно и там это отключение — ПОТЕРЯ».
ПОЧЕМУ ЭТО НЕ МЕЛОЧЬ И ПОЧЕМУ ИМЕННО СЕЙЧАС: релиз 1.9 заявлен как релиз про доказательства, а закрытия в этом репозитории идут с обойдённой подписанной квитанцией. Замер этой же сессии показывает цену вживую: bootstrap_drift, будь он включён, поймал бы устаревшие развёрнутые копии в начале #193 — они лежали без правок v48 с прошлой смены, и нашлись только потому, что я сверил файлы руками.
DOCTOR НЕ ВРЁТ, НО И НЕ НАЗЫВАЕТ ВИНОВНИКА: строка «Config trust tier: no project-scope key weakens enforcement» верна буквально — ослабление пришло НЕ из проектного тира, — и ровно поэтому читатель делает неверный вывод, что ослабления нет.

## Acceptance Criteria

AC1. Этот репозиторий возвращает себе строгость, НЕ ТРОГАЯ ЧУЖОЙ ПРОЕКТ. В .tausik/config.json проекта появляются task_done.auto_verify = false и gates.bootstrap_drift.enabled = true. ~/.tausik/config.json НЕ РЕДАКТИРУЕТСЯ ни одним байтом: причины, записанные там для vaflower, остаются в силе для vaflower.
AC2. Механизм подтверждён замером, а не докстрингом. Правило слоёв (project < user < managed, но проектное значение guarded-ключа применяется, если оно СТРОЖЕ) обязано пропустить оба ужесточения: load_config_with_rejections() возвращает auto_verify=False, bootstrap_drift.enabled=True и НОЛЬ отклонений тира. Предъявить числом.
AC3. `tausik doctor` перестаёт печатать WARN «Verify-First profile». Итог doctor — в журнал целиком, чтобы было видно, что ни одно другое предупреждение не появилось взамен.
AC4. ГЕЙТ bootstrap_drift, ВКЛЮЧИВШИСЬ, РАБОТАЕТ, А НЕ ПРОСТО ЗНАЧИТСЯ ВКЛЮЧЁННЫМ. Предъявить прогоном: на согласованном дереве он зелёный, а на искусственно рассогласованном — красный и называет файл. Иначе AC1 включил бы декорацию.
AC5. КАЖДЫЙ КЛЮЧ ОБЪЯСНЁН В САМОМ КОНФИГЕ. Рядом с обоими значениями — поле с причиной: почему этот проект строже пользовательского тира и при каком условии ужесточение снимается. Конфиг без объяснения через две смены неотличим от случайного, и именно так возникли те два ключа, которые чинит эта задача.
AC6. НЕГАТИВНЫЙ СЦЕНАРИЙ, ДВА ОТДЕЛЬНЫХ: (а) удаление проектного auto_verify=false обязано ВЕРНУТЬ WARN doctor и вернуть эффективное значение в true — то есть ужесточение действительно держится на нашей записи, а не на случайности; (б) попытка ОСЛАБИТЬ из проектного тира (auto_verify=true при пользовательском false) обязана быть ОТКЛОНЕНА механизмом доверия с ненулевым числом отклонений. Второе доказывает, что правило асимметрично — проект может ужесточить, но не ослабить, — а не просто «проектное всегда побеждает».
AC7. Полная лента зелёная: `pytest -q` из PATH, 0 failed. Прогон НЕ .tausik/venv-питоном и НЕ с -o addopts="" (память #450).

## Rollback

Удалить два добавленных ключа из .tausik/config.json — эффективная конфигурация вернётся к сегодняшней (auto_verify=true, bootstrap_drift выключен), потому что пользовательский тир не менялся. Побайтовая копия .tausik/config.json снимается ДО правки и сверяется по sha256, git revert неприменим: .tausik/ в .gitignore. Ни схемы, ни данных, ни кода правка не трогает; ужесточение гейта не может испортить дерево — худшее, что оно делает, это отказывает в закрытии задачи, что и есть его работа.
