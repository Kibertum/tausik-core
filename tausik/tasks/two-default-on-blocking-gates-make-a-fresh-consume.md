## Goal

НАЙДЕНО СКВОЗНЫМ ПРОГОНОМ ПОТРЕБИТЕЛЬСКОГО ПУТИ, смена #240. Поднял чистый проект (git init, две функции, один тест), развернул TAUSIK, завёл задачу, написал код, verify ЗЕЛЁНЫЙ — и task done ЗАБЛОКИРОВАН двумя гейтами разом:

  [1] test_dedupe: «The test-dedupe ratchet could not be read from tausik/gates.json (node test_dedupe.baseline with integer groups and tests)». У свежего проекта файла tausik/gates.json НЕТ ВООБЩЕ.
  [2] claudemd_state_drift: «2 of 2 agent-instruction file(s) carry a DYNAMIC block with NO memory tail while this project's database…». У свежего проекта память пуста по определению.

ОБА ВКЛЮЧЕНЫ ПО УМОЛЧАНИЮ И ОБА severity=block (gate_registry_scoped.py:132-134 и 389-391). То есть НОВЫЙ ПОЛЬЗОВАТЕЛЬ НЕ МОЖЕТ ЗАКРЫТЬ НИ ОДНОЙ ЗАДАЧИ, пока не догадается либо создать храповик руками, либо выключить гейты. Ни то, ни другое нигде не сказано — quickstart ведёт ровно по этому пути.

ПОЧЕМУ ЭТО НЕ ЗАМЕТИЛИ. Оба гейта зелены на НАШЕМ дереве: у нас есть и gates.json с базой храповика, и непустая память. Гейт, работающий у автора и отказывающий у пользователя, — ровно тот класс, ради которого в 1.9 заведён cross_model_parity, только по другой оси: не хост, а ВОЗРАСТ ПРОЕКТА.

НАПРАВЛЕНИЕ ОШИБКИ: ложный блок. Чинить, не ослабляя: на дереве, где храповик ЕСТЬ, гейт обязан работать как раньше; отсутствие храповика на новом проекте — это не нарушение, а отсутствие данных.

## Acceptance Criteria

AC-1. Свежий проект закрывает первую задачу без ручных действий и без выключения гейтов. Проверяется СКВОЗНЫМ прогоном: bootstrap, задача, код, verify, task done — а не рассуждением.
AC-2. ОТСУТСТВИЕ ХРАПОВИКА — НЕ НАРУШЕНИЕ, а отсутствие данных, и это различие названо в коде. Гейт, которому нечего сравнивать, сообщает об этом и не блокирует.
AC-3. НЕГАТИВНЫЙ СЦЕНАРИЙ И ГЛАВНОЕ ОГРАНИЧЕНИЕ: на дереве, где храповик ЕСТЬ, гейт по-прежнему блокирует рост. Тест подсовывает базу с превышением и требует красного — иначе починка ложного блока стала бы дырой.
AC-4. То же для claudemd_state_drift: пустая память нового проекта не есть дрейф. Проверяется обеими сторонами — пустая база молчит, НЕПУСТАЯ база с потерянным хвостом памяти по-прежнему краснеет.
AC-5. Сквозной потребительский прогон ЗАКРЕПЛЁН тестом, а не выполнен руками один раз: иначе следующий гейт снова окажется непроверенным на новом проекте.
AC-6. Полный прогон нашего дерева зелёный: починка не смеет ослабить ни один гейт здесь.
