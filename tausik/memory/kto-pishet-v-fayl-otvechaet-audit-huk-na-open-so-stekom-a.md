ЗАДАЧА КЛАССА «файл портится, автор неизвестен». Два инструмента, оба в дереве, отвечают на РАЗНЫЕ вопросы — путать их дорого.

tests/claudemd_watch.py — ловушка по sha256 после каждого теста. Отвечает: ИЗМЕНИЛСЯ ЛИ файл. Дёшева, ставится фикстурой. НЕ НАЗЫВАЕТ АВТОРА: на настоящем разборе дала 42 события в одну секунду в 19 воркерах xdist, то есть 19 подозреваемых и ни одного обвиняемого.

tests/tools/claudemd_audit/sitecustomize.py — аудит-хук sys.addaudithook на событие 'open' с фильтром по режиму записи и по abspath цели, пишущий traceback.format_stack() строкой JSON. Отвечает: КТО ИЗМЕНИЛ. На той же полной ленте (7452 теста) дал РОВНО ДВА события со стеком и назвал путь целиком: handlers_skill.py:231-232 -> claudemd_writer.py:68.

ПОЧЕМУ ИМЕННО sitecustomize, А НЕ ФИКСТУРА. Порча приходила из ПОДПРОЦЕССА, порождённого тестом. Модуль с именем sitecustomize интерпретатор импортирует САМ, найдя его на sys.path, поэтому хук встаёт в каждом процессе, включая тех, кого никто не инструментировал. Фикстура так не умеет.

ПОЧЕМУ НЕ В КОРНЕ РЕПОЗИТОРИЯ. То же свойство: модуль с этим именем в корне затенил бы СИСТЕМНЫЙ sitecustomize для всякого процесса Python, запущенного отсюда. Живёт в своём каталоге, взводится явно:
  export PYTHONPATH="$PWD/tests/tools/claudemd_audit:$PYTHONPATH"
  export CLAUDEMD_AUDIT_ROOT="$PWD"
  export CLAUDEMD_AUDIT_LOG="$PWD/.tausik/tmp/claudemd-audit.jsonl"
Без ОБЕИХ переменных не ставится вовсе — не «ставится и молчит».

ТРИ ВЕЩИ, БЕЗ КОТОРЫХ ХУК БЕСПОЛЕЗЕН. (1) Фильтр по режиму записи: хук, пишущий на чтение, топит настоящее событие в фоне — CLAUDE.md читается на каждом старте. (2) Фильтр по abspath, а не по basename: временных проектов с файлом того же имени тесты создают десятками. (3) Слепой except внутри: хук зовётся на КАЖДОМ open(), и исключение отсюда уронит наблюдаемую программу — инструмент наблюдения не имеет права менять поведение наблюдаемого. Все три закреплены тестами tests/test_claudemd_audit_hook.py (21 шт.) и промутированы.
