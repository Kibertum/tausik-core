Дефект mcp-update-claudemd-erases-the-memory-tail жил при ПЯТИ зелёных тестах на build_compact_memory_tail. Все пять дёргали функцию напрямую через стаб бэкенда и ни один не спрашивал, КТО её вызывает. Обработчик MCP не вызывал её вообще — и стирал хвост памяти из CLAUDE.md при каждом /start, рапортуя об успешном обновлении.

ПРИЗНАК КЛАССА: у команды есть ДВЕ двери — CLI и MCP-обработчик, — и тесты стоят у общей функции, а не у дверей. Тогда дверь, которая функцию не открывает, невидима для набора.

ЧТО ДЕЛАТЬ. Когда одна операция доступна и по CLI, и по MCP, тест обязан стоять НА ПУТИ, а не на общей функции, и пришпиливать ПАРИТЕТ двух путей построчно. Тест вида 'в результате есть подстрока X' не годится: он ловит только ту потерю, о которой уже знаешь, и пропускает следующую ровно так же.
