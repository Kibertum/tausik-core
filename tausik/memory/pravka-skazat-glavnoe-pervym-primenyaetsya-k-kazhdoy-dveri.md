За одну сессию #166 один и тот же промах чинился ТРИЖДЫ, и каждый раз владелец показывал пальцем на следующую дверь:
1. страница whats-new перечисляла, что чинили В общей базе, ни разу не сказав, что она появилась
2. раздел [1.8.0] changelog открывался первой записью списка — первым впечатлением от выпуска была починка пути под Windows
3. README называл общую базу только в секции v1.8 на строке 188, ниже «Методологии»
4. и сама whats-new всё ещё открывалась словами «сначала шесть ломающих изменений», отодвигая суть на 214-ю строку

Каждый раз правка делалась ТОЧЕЧНО, по указанному месту. Это и есть промах: у релиза несколько дверей — README, changelog, whats-new, тело GitHub Release, пост в канал, — и «сказать главное первым» относится ко всем.

Проверка перед закрытием такой задачи: перечисли ВСЕ входы в релиз и прочитай первый экран каждого. Ни один гейт этого не умеет — docs_lint, audit_stale_docs и тест сходимости проверяют истинность и согласованность, но не порядок. См. конвенцию #381.
