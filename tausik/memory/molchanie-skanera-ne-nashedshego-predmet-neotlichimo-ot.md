Сканер, который ищет свой ПРЕДМЕТ и не находит, обязан отличаться от сканера, который предмет нашёл и не нашёл нарушений. Измерено в смене #224: столбцовая проверка чисел искала столбец полным совпадением ячейки-заголовка с одним написанием; заголовок «Main `tausik_*` tools (two servers)» не совпал, столбец не нашёлся, проверка вернула пустой список — тот же результат, что и у честной сверки. Четыре счётчика гнили в файлах, которые охрана обходила каждый прогон, при зелёном --check. Лечение не в добавлении ещё одного написания: любой белый список формулировок имеет невидимый край. Лечится ДВУМЯ вещами разом — опознанием предмета по ключевому слову вместо полного совпадения, и тестом, который сопоставляет ПЕРЕЧЕНЬ ВЫЧИСЛЯЕМЫХ ВЕЛИЧИН с перечнем проверок: величина без проверки обязана иметь письменное исключение с причиной, иначе тест падает. Второе важнее первого: первое чинит нынешние формулировки, второе не даёт появиться новой непроверяемой.
