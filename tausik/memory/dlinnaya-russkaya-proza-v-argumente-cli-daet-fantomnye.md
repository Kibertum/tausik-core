Попытка записать ревью командой `tausik review record --notes "<длинный текст>"` была ЗАБЛОКИРОВАНА гейтом записи с восемью целями: log, корректная, без, b, только, f, отброшен, out. Все восемь — слова, стоявшие ПОСЛЕ стрелки `->` в прозе.

ПРИЧИНА, ПРОВЕРЕННАЯ, А НЕ УГАДАННАЯ: разбор НЕ падал, доверие осталось `parsed`. shlex с punctuation_chars разбивает `->` на `-` и `>`, и `>` есть полноценный оператор перенаправления, а следующее слово — его цель. Внутри правильно закрытых кавычек этого не происходит; беда начинается, когда кавычки в тексте теряют баланс и разбор выходит из закавыченного режима.

ЛЕЧЕНИЕ, ПРОВЕРЕННОЕ. Писать текст ФАЙЛОМ и передавать как `--notes "$(cat файл)"`: токен с `$` считается неразрешимым и отбрасывается целиком, фантомов не возникает. Заодно писать текст БЕЗ угловых скобок — вместо `->` слово «даёт», вместо `2>x` описание словами. Проверка перед отправкой: `grep -c '[<>]' файл` должен дать 0.

ЧЕГО НЕ ДЕЛАТЬ. Обёртка .tausik/tausik.cmd на Windows портит кириллицу (открытая задача tausik-cli-cmd-wrapper-eats-redirect-chars). Вызов `bash .tausik/tausik` из subprocess тоже не годится: обёртка резолвит путь через /mnt/d и падает с «can't open file D:\mnt\d\...».

СВЯЗЬ: это ТРЕТЬЕ семейство ложных блоков гейта записи за две смены — после литерала open() из строки или комментария и номера дескриптора. Общий корень один: гейт разбирает ТЕКСТ как команду там, где текст командой не является.
