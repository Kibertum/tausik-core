Принцип пережил отмену git как канала обмена и всплывёт при ЛЮБОМ экспорте — бэкапе общей базы, публикации в Notion, передаче коллеге.

ПРАВИЛО: один файл на сущность со стабильным (детерминированным) порядком полей. Тогда диффы минимальны, а конфликт человекочитаем. Один большой JSONL превращает любой мерж и любой ревью в мучение.

Для задач предпочтителен markdown с фронтматтером, и не только из-за диффов: задача, лежащая текстом, читается в PR как спека, из-за чего КРИТЕРИИ ПРИЁМКИ начинают ревьюиться как код вместо того, чтобы быть запертыми в бинарнике БД. Этот выигрыш НЕ зависит от git как канала синхронизации — он держится на git как поверхности ревью, поэтому отмена обмена через git его не убивает.

Разделение при выгрузке: выгружается ЗАМЫСЕЛ (заголовок, цель, критерии, план, scope, rollback, статус, журнал), НЕ выгружаются ДОКАЗАТЕЛЬСТВА (результаты гейтов, receipt, подписи) — иначе доказательство становится редактируемым текстом.

Источник: задачи kb-export-tasks / kb-import-tasks (сессия #117), удалены после отмены git-обмена владельцем.
