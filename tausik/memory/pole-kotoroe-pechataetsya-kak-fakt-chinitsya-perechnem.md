attempts-counter-never-increments (#207): описание задачи говорило «счётчик не двигается никогда», а инкремент при task start был с v1.0.0 — механизм назван неверно (память #530). Настоящий перечень событий «повторная попытка» снялся только инвентарём по ВЫЗОВУ: task_start (считал), task_unblock (не считал), красная верификация через единственную точку записи verification_runs (не считала). Правило: у поля, которое CLI печатает как факт и метрика читает как правду, перечислить все события, обязанные его менять, найти их по вызовам сервиса, и на каждое — тест; старый тест может ЗАКРЕПЛЯТЬ дефект (test_multiple_attempts ожидал 2) — читай его ожидания как утверждение о поведении, а не как истину.
