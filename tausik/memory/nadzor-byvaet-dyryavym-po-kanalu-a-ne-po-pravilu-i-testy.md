Найдено на powershell-tool-bypasses-bash-firewall (сессия #134). Все PreToolUse-гейты были зарегистрированы с matcher "Bash". На win32 — первичной платформе — агенту доступен ВТОРОЙ инструмент-оболочка PowerShell, не матчившийся ничем. Ничего не падало: правила верны, 5655 тестов зелёные, гейты просто не вызывались для большой доли реально исполняемых команд.

ПОЧЕМУ НЕ ЗАМЕТИЛИ: каждый тест тоже писал литерал "Bash". Тест, который САМ перечисляет множество, не может обнаружить, что множество выросло — он проверяет своё представление о мире, а не мир.

ПРАВИЛО. Когда гейт судит вход, приходящий по нескольким КАНАЛАМ (инструменты, транспорты, IDE, точки входа):
1. Множество каналов производит ОДИН модуль (здесь shell_channel.SHELL_TOOLS). Никакой потребитель его не перечисляет — ни хук, ни конфиг, ни тест.
2. Регистрация (matcher) выводится из этого множества и сверяется с ним тестом. Канал, получивший парсер без матчера, роняет тест, а не уходит без надзора.
3. Тест НЕ хранит ожидаемый список литералом — он его ВЫЧИСЛЯЕТ у производителя. Проверяемый на новизну факт нельзя брать из того же места, что и проверяющий.
4. Сужающие пред-фильтры (клауза "if": "Bash(git push *)") — вторая копия решения, которое гейт принимает сам, и она всегда называет один канал. Снимать, а не дублировать.

СИМПТОМ ДЛЯ ПОИСКА: literal сравнение с именем инструмента (`tool_name != "Bash"`) или имя канала в строке matcher'а, повторённое более чем в одном файле. В этом репозитории таких мест было семь.
