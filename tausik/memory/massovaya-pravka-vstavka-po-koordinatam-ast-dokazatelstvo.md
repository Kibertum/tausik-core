Регулярка по телу вызова дважды съедала код ([[225]]). Способ, который этого не может сделать в принципе, и как ДОКАЗАТЬ, что не съел.

ПРАВКА. Не искать текст шаблоном. Разобрать файл в AST, найти узел, взять у него end_lineno/end_col_offset и вставить строку по КООРДИНАТЕ. Правки применять с конца файла к началу, иначе смещения поедут. Регулярка при этом не участвует вовсе, а значит и съесть ничего не может: вставка идёт в точку, а не вместо диапазона.

ДОКАЗАТЕЛЬСТВО ЦЕЛОСТНОСТИ, два независимых счётчика против HEAD по КАЖДОМУ файлу:
  git show HEAD:<path> | grep -cE "^\s*def test_"   vs   рабочее дерево
  git show HEAD:<path> | wc -l                      vs   рабочее дерево
Совпадение ЧИСЛА СТРОК доказывает, что правка была строго внутристрочной — при таком совпадении удаление кода невозможно арифметически. Это сильнее, чем «тесты прошли»: тесты могли пройти и на съеденном файле, ровно так дефект #225 и уцелел (слияние двух тестов в один поймал RUFF, а не тесты).

ДЛЯ ВСТАВКИ ЦЕЛЫХ БЛОКОВ (число строк меняется) остаётся счётчик def — плюс compileall и ruff.

ПОРЯДОК: правка -> счётчики против HEAD -> ruff -> compileall -> тесты. Тесты последними: они самое слабое звено этой цепочки, а не самое сильное.

Применено: 11 хуков (вставка блока) и 59 вызовов в 36 тест-файлах (внутристрочно) в hook-stderr-encoding-locale-dependent.
