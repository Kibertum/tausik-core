Указание владельца, смена #225: хардкод по моделям не нравится, цены выносятся в конфиг.

ПОРЯДОК РАЗРЕШЕНИЯ (cost_pricing.get_pricing): сначала `llm_pricing_usd_per_million` из .tausik/config.json, потом встроенная таблица. Встроенная таблица — ПОСЕВ по умолчанию, а не авторитет. Прежний порядок был обратным, и из-за этого протухшая строка (claude-sonnet-5 стоял по $3/$15, тогда как его тариф $2/$10) не поддавалась исправлению иначе как правкой Python. Авторитетность помодельная: назначив цену одной модели, проект не обнуляет поставляемые ставки остальных.

ФОРМА ЦЕНЫ: {"input": x, "output": y}. Голое число тоже принимается и означает «обе стороны по этой ставке», но это НЕ тариф — реальных тарифов с равной ценой входа и выхода не бывает, поэтому каждая модель, оценённая числом, оценена неверно по построению и в невидимую сторону. Половина тарифа (только input или только output) отбрасывается с предупреждением.

АЛИАСЫ-РАНГИ (`opus`, `sonnet`, `haiku`, `fable`) стоят столько, во сколько обходится идентификатор, КУДА ОНИ МАРШРУТИЗИРУЮТСЯ по model_profiles.DEFAULT_FAMILIES, а не сколько стоит новейшая модель этого имени. Иначе счётчик расходится с маршрутизатором. Поймано существующим тестом test_short_alias_matches_canonical на моей же правке.

ОТСУТСТВИЕ ЦЕНЫ НЕ ЕСТЬ НОЛЬ (решение #334): `tausik metrics` НАЗЫВАЕТ модель, для которой несёт токены, но не может её оценить, вместо печати $0.00. Столбец cost_usd в БД NOT NULL, поэтому в данных ноль неотличим от «бесплатно» — различить можно только на выводе, где таблица цен ещё доступна.
