СВОДНАЯ ТЕМА. Заменяет [[#224]], [[#225]], [[#227]] — три записи об одном. Новые случаи дописывать СЮДА разделом, а не новым номером.

## 1. Полная линия обязательна при миграциях (из #224)

Список «затронутых файлов» при добавлении миграции бесполезен по построению. Миграционные тесты собирают синтетическую БД на версии N и зовут run_migrations(conn, N), который идёт до ТЕКУЩЕЙ версии схемы. Любая новая миграция исполняется во всех таких тестах, и ALTER по таблице, которой в синтетической фикстуре нет, роняет тест, ничего не знающий о правке. Связь не через импорт, а через «доходит до головы» — статическому анализу затронутости не видна.

Сессия #114: девять «затронутых» модулей дали 309 зелёных и полную уверенность; полная линия дала ПЯТЬ падений.

Чинить фикстуры, не миграцию: в реальной БД таблица есть с базовой схемы. Литерал версии в тесте (assert SCHEMA_VERSION == 37) — мина на один релиз; правильная форма >= N уже была в репозитории.

Обе линии обязательны всегда: pytest tests/ И pytest tests/ -m slow (addopts = -m 'not slow').

## 2. Дифф ДО тестов после машинной правки (из #225)

После любой правки нескольких файлов скриптом или регуляркой: git diff ПЕРЕД запуском тестов. Отдельно сверить счётчик изменений с ожиданием — несоответствие «сколько думал» и «сколько получилось» самый дешёвый детектор.

Сессия #114: регулярка по verification_runs\s*\( зацепила INSERT INTO помимо CREATE TABLE и порвала строковые литералы. Сигналом было «patched 11 DDL block(s)» — столько CREATE TABLE в одном файле быть не могло.

## 3. Мутационная проверка и БЕЗОПАСНЫЙ откат (из #227)

Зелёный тест ничего не доказывает, пока не показано, что он умеет краснеть. Мутируй код в no-op, прогоняй, откатывай.

ОТКАТ ТОЛЬКО ИЗ КОПИИ, СНЯТОЙ ПЕРЕД МУТАЦИЕЙ: cp file /tmp/f.bak до, cp /tmp/f.bak file после. Проверить восстановление диффстатом (должен совпасть с домутационным) и прогоном; бэкап перед восстановлением проверить на отсутствие маркера мутации.

ПРОТИВОРЕЧИЕ, ВСКРЫТОЕ СВОДКОЙ: раздел 2 (из #225) утверждает «git checkout -- tests/ — правки незакоммичены, откат бесплатен». Это верно ТОЛЬКО когда правки, которые надо сохранить, уже в HEAD. В сессии #115 тот же приём на файле с незакоммиченной работой задачи снёс 28 вставок: git checkout возвращает к HEAD, а не к состоянию до мутации, и git diff --stat показывает пустоту, что читается как «успешно откатил». Верная формулировка: git checkout/restore применим к файлу, чьи нужные правки уже закоммичены; во всех остальных случаях — только копия.

## 4. Прочее, подтверждённое на практике

- Проверяй премису задачи grep-ом ДО работы: в #114 обе премисы задачи оказались неточны, в #115 премиса подтвердилась и сразу дала точку вмешательства.
- Прогон целевой выборки вместо полной линии допустим ТОЛЬКО для правки, не меняющей код (комментарий, форматирование), и это надо писать в evidence прямо, а не умалчивать.
- Зеркала IDE (.claude, .cursor, .kilo, .opencode, .qwen) отстают молча: правь scripts/, затем bootstrap --no-detect --ide all, затем проверяй grep-ом.
