get_gates_for_trigger научили исключать фазу post_scope — правильно для раннера гейтов, который иначе вызвал бы гейт с чужой сигнатурой. Но ту же функцию читал gate_activity_summary как источник списка ИЗВЕСТНЫХ гейтов, и сужение молча выкинуло два QG-2 гейта из метрик: строки, которые они уже записали, оставались (приходят из таблицы), а гейт с нулём строк исчезал целиком — то есть «эта охрана не срабатывала ни разу» рендерилось тишиной (конвенция #226).

Дефект коварен тем, что НИ ОДИН тест не покраснел: сужение корректно для того call-site, ради которого делалось, а второй потребитель просто стал отвечать беднее. Поймано только сквозной проверкой «а видно ли результат снаружи», уже после закрытия задачи.

Правило: меняя семантику функции, у которой больше одного вызывающего, грепнуть ВСЕ call-sites и вынести явное решение по каждому — прежде чем менять. Молчаливое «для остальных тоже сойдёт» — это и есть регрессия. Если у потребителей расходятся потребности, сужение должно быть параметром или отдельной функцией, а не новым поведением общей.
