Python-скрипт, переданный в Bash-инструмент через одинарно-кавыченный heredoc (<<'PYEOF'), ДОЛЖЕН был бы дойти байт в байт. На практике обратные слэши в нём раскрываются: литерал 'print(f"\\n  sha256' доходит до Python как строка с НАСТОЯЩИМ переводом строки, а не с двумя символами \ и n. Поэтому якорь не находит ничего в файле, где лежит буквальное \n.

ЗАМЕР #198: s.count(anchor) вернул 0 при заведомо присутствующей строке; probe.py напечатал repr кандидата и repr файла рядом — repr якоря показал реальный перевод строки, repr файла показал '\\n'. Только это и вскрыло причину; сам по себе провал выглядел как «якоря нет в файле».

ПРАВИЛО: якорь для patch-скрипта выбирай БЕЗ escape-последовательностей — кусок текста из букв и пробелов ('sha256 ADR-020'), а не фрагмент с \n, \t, \\. Если якорь неизбежно содержит слэш — собирай его через chr(92) или ищи по строке-контейнеру: [l for l in s.split("\n") if "маркер" in l].

ПОЧЕМУ ЭТО НЕ СТОИЛО СМЕНЫ: якорь стоял под assert count == 1 (память #457), и харнесс упал отдельным исходом SETUP-FAIL до всякой записи в файл. Без этого assert замена бы просто не произошла молча, а прогон дальше показал бы старое поведение и был бы засчитан.
