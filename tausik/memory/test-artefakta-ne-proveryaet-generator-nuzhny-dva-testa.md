Тест, читающий СГЕНЕРИРОВАННЫЙ АРТЕФАКТ, проверяет не генератор, а факт перевыпуска артефакта. Пока файл перевыпускают вручную рядом с правкой, эти два утверждения совпадают — и расхождение не наблюдается ни одним тестом. Замерено мутацией в #200: подмена ветви в renar_measurer_caveats.header_lines() (шапка продолжает заявлять незаслуженные подтверждения при ПУСТОМ реестре) ВЫЖИЛА, потому что единственный тест шапки открывал закоммиченный RENAR-CONFORMANCE.yaml, а тот был перевыпущен минутой раньше и содержал верный текст. Убито добавлением теста, вызывающего header_lines() НАПРЯМУЮ.
ПРАВИЛО: на каждый производный артефакт нужны ДВА теста, и они проверяют РАЗНОЕ. (1) Тест ГЕНЕРАТОРА — вызывает функцию и сверяет вывод с состоянием входа; ловит логику. (2) Тест СВЕЖЕСТИ — сверяет закоммиченный файл с тем, что генератор даёт сегодня; ловит забытый перевыпуск. Один без другого оставляет дыру: без (1) логика не проверена вовсе, без (2) артефакт тихо устаревает.
РОДСТВЕННАЯ ДЫРА ИЗ ТОЙ ЖЕ СЕРИИ: негативный сценарий проверялся на СВЕЖЕЙ схеме, тогда как чинилась МИГРАЦИЯ. Свежая база миграцию не прогоняет, поэтому CHECK, который пишет миграция, ни одним тестом не трогался — замена его на голое `type TEXT NOT NULL` не уронила ничего. Тот же корень: тест шёл по пути, которого починка не касалась.
