Функция, которая сужает область проверки по внешнему источнику (git-индекс, API, конфиг), при недоступности источника ОБЯЗАНА возвращать признак «неизвестно» (None), а не пустой результат.

Пустое множество семантически означает «источник ответил: ничего нет» и приводит к максимально широкому или максимально узкому выводу вместо честного отказа. В audit_tracked_files пустое множество заставило бы каждый аудит объявить ВСЁ дерево неотслеживаемым при первом же сбое git — то есть отчёт, где каждый файл ложный кандидат.

Вызывающий обязан различать три состояния: «источник ответил, элемент есть», «источник ответил, элемента нет», «источник не ответил». На «не ответил» — деградировать до прежнего поведения И печатать предупреждение, чтобы деградация была видима, а не молчалива.

Родственно #221 (гейт, не сумевший вычислиться, обязан блокировать) и трёхзначному declared_scope_status из l26-verify-git-diff-wire: там же отвергнут булев признак, склеивающий «проверено и полно» с «проверить не удалось».
