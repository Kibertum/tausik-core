Bash-инструмент здесь — Git Bash, и его /tmp живёт в MSYS-префиксе. Python, запущенный из того же места, разрешает '/tmp/x' как ДРАЙВ-ОТНОСИТЕЛЬНЫЙ путь текущего диска — то есть в каталог tmp в корне того же диска, где лежит проект. На этой машине такой каталог существует и объявлен рабочим: в нём лежат файлы других проектов.

КАК ЭТО ПРОЯВИЛОСЬ (смена #238). Записал acceptance_criteria во временный файл через bash-heredoc, применил CLI — сработало. Через несколько шагов прочитал ТОТ ЖЕ путь из питоновского скрипта, чтобы поправить два числа, и получил файл ДРУГОГО проекта (AC про redis setex). Замены не совпали, содержимое ушло в CLI как есть, и задача senar-14 получила чужие критерии приёмки. Ни одна проверка этого не видит: строка непустая, команда успешна, CLI печатает 'updated'. Нашлось только чтением показанного результата.

ПРАВИЛО: временные файлы — только по АБСОЛЮТНОМУ пути в scratchpad-каталоге сессии, и записывать их тем же инструментом, которым потом читаешь. Никаких '/tmp' в питоновском коде на Windows вообще.

Родня: конвенция про вложенные кавычки в Windows-командах — тот же корень, оболочка и интерпретатор понимают одну строку по-разному.
