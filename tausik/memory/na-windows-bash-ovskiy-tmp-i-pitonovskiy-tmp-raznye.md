Bash-инструмент здесь — Git Bash, и его /tmp живёт в MSYS-префиксе. Python, запущенный из того же места, разрешает '/tmp/x' как ДРАЙВ-ОТНОСИТЕЛЬНЫЙ путь текущего диска: из d:/Work/... это D:\tmp\x. У этой машины D:\tmp существует и объявлен рабочим каталогом — в нём лежат файлы других проектов.

КАК ЭТО ПРОЯВИЛОСЬ (смена #238). Записал acceptance_criteria в /tmp/ac.txt через bash-heredoc, применил CLI — сработало. Через несколько шагов прочитал тот же '/tmp/ac.txt' из питоновского скрипта, чтобы поправить два числа, и получил ФАЙЛ ДРУГОГО ПРОЕКТА (AC про redis setex). Замены не совпали, файл ушёл в CLI как есть, и задача senar-14 получила чужие критерии приёмки. Ни одна проверка этого не видит: строка непустая, команда успешна, CLI печатает 'updated'.

ПРАВИЛО: временные файлы — только по АБСОЛЮТНОМУ пути в scratchpad-каталоге сессии, и записывать их тем же инструментом, которым потом читаешь. Никаких '/tmp' в питоновском коде на Windows вообще.

Родня: конвенция про вложенные кавычки в Windows-командах — тот же корень, оболочка и интерпретатор понимают путь по-разному.
