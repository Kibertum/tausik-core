Любой слой графа, который делает рёбра ПОПАРНО из множества (файлы одного коммита, файлы одной задачи, элементы одного объявления), обязан отбрасывать группы больше порога. Большая группа связывает свои элементы С ГРУППОЙ, а не друг с другом, и попарное раскрытие превращает это в квадратичный шум.

Замер, смена #222 (ag-artifacts-and-edges-with-provenance): слой объявленных рёбер без ограничения дал 65 318 рёбер на этом репозитории — тридцатифайловая задача порождает 435 пар, и получалось «CHANGELOG.md ссылается на .gitattributes». После ограничения (25) стало 23 358. Слой со-изменения по git такое ограничение имел с самого начала, слой объявлений — нет; лечится оно одной общей константой, а не двумя.

Смежная ошибка того же замера: ОТНОШЕНИЕ. «Автор сгруппировал эти файлы» — это co_changes, а не references: объявление не утверждает, что один файл ссылается на другой. Неверное имя отношения кладёт в граф утверждение, которого никто не делал.

И третье, тоже из замера: симметричное отношение, хранимое ОДНОСТОРОННЕ (на алфавитно первом элементе пары), делает запрос по второму элементу пустым. neighbours_of самого изменяемого модуля вернул НОЛЬ соседей. Запрос обязан смотреть в обе стороны, направление при этом сохранять в ответе — для несимметричных отношений (covers, documents) стрелка несёт смысл.

Как применять: (1) порог общий для всех слоёв, собирающих пары из множества; (2) имя отношения проверяй вопросом «кто именно это утверждал и в каких словах»; (3) сразу после первой сборки — ПРОГОН НА НАСТОЯЩЕМ репозитории и взгляд на число рёбер и на топ соседей самого частого файла: и взрыв, и односторонность видны только там, на фикстурах оба невидимы.
