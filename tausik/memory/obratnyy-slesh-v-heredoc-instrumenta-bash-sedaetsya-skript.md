Конструкция python - <<'PYEOF' ... PYEOF через инструмент Bash теряет один уровень обратных слэшей, несмотря на закавыченный разделитель. Питон получает однослэшевую версию вместо двуслэшевой и подставляет в файл НАСТОЯЩИЙ нулевой байт вместо текста из четырёх знаков. Симптом отложенный и уводит в сторону: правка проходит без ошибки, а падает следующий импорт — ValueError: source code string cannot contain null bytes — причём из совсем другого модуля, чем тот, который правили.

Хуже того, починка тем же способом бесполезна: строка-замена в чинящем скрипте страдает ровно тем же искажением, поэтому bad и good становятся одинаковыми, а replace тихо превращается в тождественную операцию и рапортует об успехе. Ассерт «нулевых байтов не осталось» ПОСЛЕ замены — единственное, что это ловит.

Передача через cat в файл с закавыченным разделителем работает: там нет второго разбора строкового литерала. Ломается именно связка heredoc плюс повторный разбор питоном.

ПРАВИЛО: скрипт, содержащий экранирование, пишется ФАЙЛОМ инструментом Write в scratchpad и запускается по имени. Однострочник и heredoc — только для текста без обратных слэшей. Тот же класс, что и конвенция про вложенные кавычки на Windows.

ПРОВЕРКА ПОСЛЕ ЛЮБОЙ ПРАВКИ ИСХОДНИКА СКРИПТОМ: посчитать нулевые байты в результате и убедиться, что их ноль.
