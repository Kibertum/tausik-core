Два правила, оплаченные дефектом mcp-deprecation-gate-false-positives (найден состязательным ревью в аудите #122, починен в #124).

ПРАВИЛО 1. Если докстринг формулирует ПРИНЦИП, он выполняется всеми ветками файла, а не той, ради которой писался.

Гейт депрекаций MCP обещал «документации МОЖНО упоминать депрекируемые примитивы, коду запрещено ими ПОЛЬЗОВАТЬСЯ» и реализовал это ДВУМЯ разными примитивами: AST для обращений к API и поиск подстроки для литералов протокола. Второй принципа не держал — честный комментарий `# older clients still send "roots/list"` ронял сборку. Одно обещание, две несогласованные реализации; расхождение обнаружилось только состязательным ревью.

Признак для поиска такого же: файл, где рядом живут «разбор» и «поиск по тексту» для ОДНОГО правила. Дешёвая половина всегда та, что нарушает.

ПРАВИЛО 2. Всякое СУЖЕНИЕ проверки закрывать ПАРНЫМ тестом на то, что настоящее нарушение по-прежнему ловится.

Второй дефект чинился сужением с ast.Name до ast.Attribute. Само по себе это сужение открывало дыру ровно того размера, который закрывало: `from mcp.server.session import list_roots` доступа к атрибуту не содержит. Пришлось добавить ветку на прямой импорт.

Проверка «ложных падений стало меньше» БЕЗ парной «настоящее нарушение ещё ловится» прошла бы и на функции, всегда возвращающей пустой список. Это обмен шумного гейта на слепой — тот же дефект с другим знаком, и он опаснее, потому что выглядит починкой.

ПОЧЕМУ ЛОЖНОЕ ПАДЕНИЕ — НЕ МЕЛОЧЬ. Гейт, ругающийся на честный текст, отключают. Отключённый гейт хуже отсутствующего: он выглядит защитой. Поэтому ложное срабатывание в гейте — дефект той же тяжести, что и пропуск, а не косметика.
