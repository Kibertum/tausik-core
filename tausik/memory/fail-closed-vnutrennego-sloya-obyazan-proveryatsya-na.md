gate_run_record был сделан fail-closed намеренно и писал об этом в докстринге: «запись, которая не может произойти, поднимает исключение… прогон, который выглядит записанным, но не записан, обходится дорого». Уровнем выше стоял except Exception -> logging.warning -> return None, который ловил ровно то исключение, из которого гарантия состояла. Гарантия была аннулирована, а докстринг продолжал её обещать.

ПРАВИЛО: заявленный в докстринге fail-closed не является свойством модуля — он является свойством ЦЕПОЧКИ. Один общий except у любого вызывающего сводит его к нулю, и никакой тест этого модуля этого не покажет, потому что модуль ведёт себя правильно.

КАК ПРОВЕРЯТЬ: grep по except вокруг каждого вызова функции, которая обещает поднимать. Дешевле, чем звучит — вызывающих обычно единицы.

ПОЧЕМУ ЭТО ДЕФЕКТ, А НЕ СТИЛИСТИКА: код противоречит собственному документированному контракту. Читатель докстринга принимает решения, опираясь на обещание, которого нет.

Смежно: [[221]] (гейт, который не смог вычислиться, обязан блокировать), [[242]] (блокирующий вердикт обязан записываться), [[226]] (неизвестно ≠ пусто).
