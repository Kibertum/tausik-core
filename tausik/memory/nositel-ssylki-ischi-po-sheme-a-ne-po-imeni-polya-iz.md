Задача check-adapt-supersession четыре смены считалась невыполнимой: её заголовок называл носителем ссылки SPEC.source_adapt, колонки такой нет и по решению #307 не будет, значит гейт был бы вырожденным контролем. Инвентарь ПО СХЕМЕ (PRAGMA foreign_key_list по всем таблицам) дал ПЯТЬ внешних ключей на adapts.slug, из них четыре — дети адаптации, а пятый, adapts.parent_adapt, есть ссылка ОДНОЙ адаптации на ДРУГУЮ, то есть ровно delta-ADAPT на родителя. Предмет был, просто не там, где написано в заголовке.

ПРАВИЛО: прежде чем объявить у охраны отсутствие предмета, перечисли носителей ЗАПРОСОМ К СХЕМЕ, а не грепом по имени поля из формулировки. Заголовок задачи — измеренное когда-то наблюдение, а не граница возможного.

ВТОРОЕ ПРАВИЛО, ИЗ ТОГО ЖЕ ЗАМЕРА: НОЛЬ СТРОК НЕ ЕСТЬ ОТСУТСТВИЕ ПРЕДМЕТА. Колонку, которая существует, завтра заполнят; колонку, которой нет, заполнить нельзя. Поэтому храповик премисы у объявления неприменимости должен следить за ПОЯВЛЕНИЕМ КОЛОНКИ, а не за появлением строк.

ТРЕТЬЕ: берясь за охрану, снимай инвентарь СУЩЕСТВУЮЩИХ гарантий и не дублируй их. Здесь НЕ проверяется несуществующий родитель: PRAGMA foreign_keys=ON стоит на рабочем соединении (project_backend), и проверка сирот по PRAGMA foreign_key_list уже есть на пути импорта состояния. Причина невключения записана В ДОКСТРИНГЕ, иначе следующий читатель примет её за недосмотр и заведёт второй источник истины.
