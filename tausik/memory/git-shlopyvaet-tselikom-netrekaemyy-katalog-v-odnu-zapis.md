`git status --porcelain` в режиме по умолчанию (`--untracked-files=normal`) отдаёт для полностью нетрекаемого каталога ОДНУ строку `?? .cursor/`, а не файлы внутри него. Любой потребитель, спрашивающий «был ли тронут файл под <каталогом>?», получает `.cursor/` и отвечает «нет».

Это не косметика: для гейта memory_route это означало, что ПЕРВАЯ запись в свежесозданный каталог-сток — самая вероятная форма дефекта — прошла бы мимо. Поймано собственным тестом гейта, не ревью.

Лечение: `--untracked-files=all`. Но добавлять его в общую `uncommitted_changes` как смену поведения НЕЛЬЗЯ — это меняет вопрос для КАЖДОГО потребителя (см. [[конвенция-сужение-общей-функции-запроса]] / memory #286). Правильно: новый параметр `untracked=` со значением по умолчанию `normal`, новый режим включается явно тем, кому он нужен.

Проверять при написании любого нового сканера рабочего дерева: сначала тест «новый файл в НОВОМ каталоге», только потом «новый файл в существующем».
