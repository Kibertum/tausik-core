Сессия #114. Нужно было добавить две колонки в семь тестовых файлов, объявляющих схему verification_runs вручную. Написал скрипт, матчивший «verification_runs\s*\(» с балансировкой скобок. Скрипт отчитался «patched 11 DDL block(s)» — и это был сигнал тревоги, а не успеха: в одном файле столько CREATE TABLE быть не могло.

Что он сделал. Матч зацепил не только CREATE TABLE, но и INSERT INTO verification_runs (task_slug, scope, ...) — и вписал туда «declared_scope_status TEXT, undeclared_files TEXT» посреди списка колонок INSERT, порвав при этом строковые литералы Python (вставка с переводом строки внутри "..."). Файлы перестали быть валидным Python.

Поймано только диффом. ruff бы поймал синтаксис, но я мог сначала запустить тесты и потратить минуты на диагностику «почему падает всё».

Правило: после любой машинной правки нескольких файлов — git diff ПЕРЕД запуском тестов, и отдельно проверить, что счётчик изменений совпадает с ожиданием. Несоответствие числа «сколько думал» и «сколько получилось» — первый и самый дешёвый детектор.

Починка: git checkout -- tests/ (правки были незакоммичены, откат бесплатен), затем регулярка с якорем на CREATE\s+TABLE\s+(IF\s+NOT\s+EXISTS\s+)?verification_runs, и проверка «git diff | grep -c INSERT INTO» == 0 как явное доказательство, что INSERT не задет.

Это подтверждение памяти [[#216]] в новой форме: не «закрыт ли случай X», а «сколькими способами шаблон совпадает с текстом» — и проверять исполняемым способом, а не рассуждением.
