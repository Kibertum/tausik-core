В #193 гейт имел ДВА одинаковых fail-open блока. Мутация, переворачивающая их по одному, показала: site 2 красит набор (3 failed), а site 1 — ЗЕЛЁНО, 25 passed. То есть более ранний except не покрывался ничем и правка там была НЕ доказана, хотя код выглядел симметрично и «очевидно» покрытым. Чтением глазами это не находилось; нашла мутация.

Правило: если правка трогает N мест, мутаций тоже N, каждая по отдельности, при остальных исправленных. Одна мутация «на файл» доказывает покрытие самого заметного места и молча подписывает остальные.

Оснастка (harness пишется во временный каталог, не в дерево): читать файл БАЙТАМИ, split по якорю, собирать обратно подменяя только i-е вхождение, гонять pytest, восстанавливать из побайтовой копии в finally, сверять sha256 до/после. git checkout запрещён — он доказывает индекс, а не файл. Якоря писать под РЕАЛЬНЫЕ байты: scripts/ в этом дереве LF-only, вариант с \r\n не совпадает ни разу и молча даёт 0 сайтов (harness обязан на этом ПАДАТЬ, а не продолжать).
