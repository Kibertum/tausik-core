В батнике set "X=%CMDCMDLINE%" САМ является той ошибкой, ради ловли которой пишется. Значение CMDCMDLINE содержит кавычки; они закрывают защитную пару кавычек команды set раньше времени, и знак больше внутри значения перенаправляет уже строку set. Замер #209: здоровый аргумент SCHEMA 48->49 next сохранялся как SCHEMA 48- next, страж целостности отвергал ТРИ ЗДОРОВЫХ вызова из девяти, и на строке set рождался посторонний файл. Лечение: setlocal EnableDelayedExpansion + set "X=!CMDCMDLINE!" — подстановка идёт ПОСЛЕ разбора строки на операторы; затем setlocal DisableDelayedExpansion (он наследует переменную), иначе оставленное включённым отложенное раскрытие съест восклицательный знак в %*. Проверено: 10 форм с !PATH!, процентом, скобками, кириллицей доезжают дословно. Общее правило: любое значение с кавычками и операторами, проходящее через set в cmd.exe, требует отложенного раскрытия — ложное срабатывание охраны неотличимо от дефекта, который она ловит.
