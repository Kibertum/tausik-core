Раннер мутаций восстанавливает ФАЙЛ, который мутировал. Если убийство мутанта требует ПЕРЕСБОРКИ производного артефакта (перегенерировать манифест, перезапустить экспорт, пересобрать снапшот), мутация уезжает в этот артефакт — и остаётся там после «успешного» возврата, потому что раннер про него не знает.
ПОЙМАНО В #199: мутация M11 снимала строку из шапки генератора манифеста; чтобы она дошла до проверки, скрипт перегенерировал RENAR-CONFORMANCE.yaml. Возврат вернул scripts/renar_conformance.py и отрапортовал RESTORE-FAIL 0 — а в манифесте осталась мутированная шапка И подставной assessor id "a". Нашлось git diff, НЕ раннером.
ПРАВИЛО: если сценарий мутации ПИШЕТ куда-то помимо мутируемого файла, список восстановления обязан включать И эти цели, и проверка возврата — сверять их тоже. Дешёвая универсальная страховка: после прогона всех мутаций сверить git status/git diff --stat по всему дереву с состоянием ДО прогона, а не только по мутируемым путям.
ПОЧЕМУ ЭТО ОПАСНО ТИХО: испорченный производный артефакт валиден по форме и проходит собственные тесты (они сверяют его с генератором, а генератор уже возвращён) — расхождение видно только диффом.
