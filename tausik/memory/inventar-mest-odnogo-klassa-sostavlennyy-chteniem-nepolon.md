Решение #283 (вычитать собственный экспорт задачи из покрытия). Разбор #193 утверждал ТРИ точки правки. Сессия #194, правя их, нашла ПЯТЬ — две невидимые первому чтению. Сессия #195 не искала вовсе: verify её собственной закрываемой задачи (#1892) напечатал NOTE про недекларированный файл, и этим файлом оказался СОБСТВЕННЫЙ экспорт задачи — шестое место, describe_declared_scope в verify_scope_honesty.py. Исправлено в #196.

ЧТО ОБОБЩАЕТСЯ. Чтение находит места, ПОХОЖИЕ на уже найденное: тот же вызов, то же имя, тот же файл. Оно системно пропускает места, где класс проявляется в ДРУГОЙ форме — здесь хеш покрытия (три места #194) против текстового множества repo-путей (это). Grep по coverage_files не нашёл бы его никогда: там не было ни этого имени, ни импорта.

ПРАВИЛО. Закрывая класс, не объявляй инвентарь полным по итогам чтения. Назови НАБЛЮДАЕМЫЙ след класса (здесь: слово under-declared в выводе на заведомо честной области) и прогони систему живьём. Оставшиеся места предъявляют себя сами. Прогон дешевле ещё одного чтения и, в отличие от него, может ОПРОВЕРГНУТЬ полноту.
