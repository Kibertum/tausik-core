Источник: standards/renar-standart @ 9b72835 (экспорт на GitHub Kibertum/RENAR 3a003bd), руководство по миграции guide/12-migration-v11.md (20 правок), переоценка всех заявлений по §13.7.3. TAUSIK уже несёт renar-version 1.1 (решение #364, §13.3.8 vacuous, уровень null по §1.5.4). Что важно для нас: (1) §1.4.4 подтверждение первой стороной — новый вид применимости для внутреннего продукта: вход — замороженный письменный концепт (V6 автор + время) вместо ТЗ, ACTZ и релизный гейт AT беспредметны, состязательный обзор обязателен без исключений, манифест confirmation: first-party; это единственный выход из декларации несоответствия §1.5.4 и он требует концепта и подписи владельца; (2) SPEC-UC двенадцатый тип (§8.5.12, role human|agent, шаг ссылается на утверждение адресом id#n) — детектор дрейфа на верном корпусе показывает 12 против наших 11; (3) ломающие: комплект описания и set-version N.M (у BR/SR/SPEC/TC снимаются status/version, QG-0/1/2 по объектам комплекта, манифест set-version), automation.status из двух значений — по природе кандидат в 2.0 с явной декларацией неприменимости в 1.10; (4) добавляющие: MW запись ручного прохода, реестр экранов, SPEC-ARCH/SEC обязательны на уровне system, компонент с uses[], AR фиксирует primary-модель, глава 15 язык описания обязательна с RENAR-2. План 1.10 G: детектор смотрит в источник, SPEC-UC, first-party по решению владельца, остальное — декларации с храповиком.
