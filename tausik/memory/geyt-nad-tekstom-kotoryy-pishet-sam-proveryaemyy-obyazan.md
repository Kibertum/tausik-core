Предикат надзора, читающий поле, которое заполняет проверяемый агент (task notes, commit message, PR description), проверяет НЕ работу, а способность агента написать нужную строку. Разница видна только на цифрах, поэтому её не замечают годами.

Замер по TAUSIK (сессия #133): гейт Rule 5 снимался вхождением слова из таблицы («scope», «secret», «phantom»). На 851 закрытой задаче с AC словарный вердикт расходился со структурным на 380 (44.7%): 320 прошли на одном слове без единого реального доказательства, 60 получали ругань при настоящих доказательствах. При этом для тиров substantial/deep это был ХАРД-БЛОК — то есть условием завершения самых дорогих задач было наличие пароля в тексте.

Правило: в таком гейте засчитывается только то, что агент не может изготовить текстом. Практическая иерархия силы доказательства (от слабого к сильному):
1. слово из словаря — не считается вообще;
2. галочка «✓» — утверждение, что верификация была, то есть ровно предмет проверки; не считается;
3. название деятельности («manual run», «review») — считается для ПРЕДУПРЕЖДЕНИЯ, не для блока;
4. ссылка на артефакт, СУЩЕСТВОВАНИЕ которого проверяется независимо (файл теста на диске) — считается для блока.
Нерезолвимая ссылка трактуется fail-closed: выдуманная и опечатанная ссылки — одна и та же строка.

Диагностический признак, что гейт выродился в театр: его предупреждение игнорируется каждым закрытием и НЕТ честного действия, которое его снимает. Прежде чем «начать выполнять» такое требование, проверь, что выполнение вообще определено — иначе чинить надо гейт.

Побочный урок: замена одного предиката другим не завершена, пока старые ТЕСТЫ не переписаны. Здесь два теста утверждали, что 'scope clean, no secret leak' — валидный чеклист; пока они зелёные, дефект закреплён, а не устранён.
