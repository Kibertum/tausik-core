Стек, объявляющий extensions, обязан иметь хотя бы один ДОСТИЖИМЫЙ для его файлов гейт — свой или родительский. Гейт: tests/test_stack_gate_coverage.py.

ПОЧЕМУ ЭТО ОТДЕЛЬНЫЙ КЛАСС, А НЕ «НЕТ ФИЧИ». Пропущенный гейт хотя бы честно помечается skipped. НЕОБЪЯВЛЕННЫЙ не оставляет в выводе следа вовсе: отличить «проверено» от «проверять было нечем» нельзя ни по одному признаку. Flutter и Swift были объявлены стеками — расширения, сигнатура обнаружения, гайд с чеклистом ревью — и ни один гейт их не называл; task done по дартовым файлам рапортовал зелено, не запустив ничего.

ТРИ ПРАВИЛА, БЕЗ КОТОРЫХ ТАКОЙ ГЕЙТ НЕ ЖИВЁТ:

1. Достижимость считать ПРОДОВЫМ кодом (gate_applies_to), а не второй реализацией правила. Две копии разъезжаются в обе стороны (конвенция #249), и разъедется именно проверка, потому что её никто не перечитывает.

2. Учитывать НАСЛЕДОВАНИЕ. Требовать собственных гейтов у каждого стека — значит заказать девять бессмысленных правок (django/fastapi/flask покрыты pytest из python, react/next/nuxt/vue/svelte — eslint/tsc, laravel — php, blade — через отображение .blade.php) и сделать гейт первым, что отключат. Проверять надо ДОСТИЖИМОСТЬ, а не место объявления.

3. Новые гейты объявлять enabled=false, если тулчейна нет на машине сборки. Включённый по умолчанию flutter test уронил бы всех и был бы отключён в первый день — то есть заменил бы молчаливую дыру шумным враньём.

ПОПУТНО ВСКРЫЛОСЬ: `tausik stack lint` проверяет ТОЛЬКО пользовательские переопределения в .tausik/stacks/. Встроенные объявления против stacks/_schema.json не валидировались нигде — на чистой машине команда печатает «nothing to lint», а невалидную декларацию StackRegistry молча пропустила бы при загрузке. Добавлена проверка на весь набор встроенных.

СВЕРКА С КАРТОЧКОЙ: разведка задачи называла 26 каталогов stacks/, фактически их 25. Сироты те же две, но число было неверным — перемеряй, не переноси.
