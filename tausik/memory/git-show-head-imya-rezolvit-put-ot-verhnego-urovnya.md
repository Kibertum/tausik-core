Замер на этом репозитории, git печатает подсказку сам. Из каталога scripts: git show HEAD:CHANGELOG.md отдаёт файл ИЗ КОРНЯ (rc=0), а git show HEAD:project.py падает с fatal: path scripts/project.py exists, but not project.py и hint: Did you mean HEAD:./project.py. Форма с ./ резолвится ОТ CWD и верна в обеих раскладках.

ПОЧЕМУ ЭТО НЕ МЕЛОЧЬ. cwd=root заставляет git найти НУЖНЫЙ репозиторий, но путь после двоеточия к cwd отношения не имеет. Если корень проекта не совпадает с верхним уровнем worktree (пакет в монорепозитории — штатная раскладка для фреймворка, который ставится в чужие проекты), то: свой закоммиченный файл НЕ находится, а если наверху лежит одноимённый ЧУЖОЙ — читается он, и ссылка получается корректной по форме и указывающей в чужой журнал. Второе хуже первого.

ПАРНАЯ ЛОВУШКА, ЗАМЕРЕНА ТАМ ЖЕ: exit code у git show НЕ различает «пути нет в HEAD» и «объект нечитаем» — оба 128. Спрашивай отсутствие ОТДЕЛЬНЫМ вопросом с однозначным ответом: git ls-tree --name-only HEAD -- ИМЯ даёт rc=0 и ПУСТОЙ вывод при отсутствии, rc=0 и строку при наличии, rc=128 при ошибке. Pathspec у ls-tree УЖЕ относителен cwd.

ТЕСТ, КОТОРЫЙ ЭТО ЛОВИТ, ОБЯЗАН КЛАСТЬ КОРЕНЬ ПРОЕКТА В ПОДКАТАЛОГ git init. Фикстура, делающая git init прямо в корне проекта, структурно не может увидеть дефект — у меня таких было шесть, все зелёные. И нужен отдельный случай «свой манифест есть И чужой наверху есть»: без него мутант на потерю ./ ВЫЖИВАЕТ, потому что проба ls-tree обрывает путь до чтения.
