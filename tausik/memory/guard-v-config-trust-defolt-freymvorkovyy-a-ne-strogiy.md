Добавляя Guard на выключатель гейта (пример #213: task_done.changelog_gate.enabled, найдено L3 #38), проверяй ТРИ ветви тестами: (1) ужесточение проходит, (2) ослабление под доверенным/закоммиченным строгим значением отклоняется с именем ключа, (3) проект, у которого никто выше не включал гейт, МОЖЕТ держать его на дефолте без отклонений. Без (3) мутация default False→True выживает, а охрана превращается в принудительное включение opt-in гейта у всех проектов без доверенного тира. Охраняй ПУТЬ, который читает резолвер гейта (gate_changelog читает task_done.changelog_gate), а не переноси выключатель на gates.<name>.enabled — второе место для одного выключателя есть второй источник истины.
