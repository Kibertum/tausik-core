Все виртуальные таблицы FTS5 создаются без параметра tokenize — значит unicode61, стемминга нет ни для русского, ни для английского. Токен сопоставляется точно: запись, где написано 'гейтов', не находится запросом 'гейт'.

У FTS5 для этого есть штатный приём — префиксный поиск 'гейт*'. У нас он НЕДОСТУПЕН: _sanitize_fts5 в scripts/backend_queries.py вырезает звёздочку вместе с прочими операторами (regex по классу ["()*:^]). То есть граница есть, а обходного пути к ней нет.

Почему это важнее, чем кажется: весь наш корпус памяти, задач и решений — по-русски, а русский язык словоизменительный. Английский корпус потерял бы на этом множественное число, наш теряет шесть падежей.

Найдено сравнением с kaeru (LamantinAI), у которого ровно та же граница НАЗВАНА в агентском скилле вместе с приёмом. Задача: search-has-no-morphology-and-strips-the-wildcard. Решение #246.

Пока не починено: искать корнем без окончания бесполезно (точное сопоставление), помогает подбирать реально встречающуюся словоформу.
