НАЙДЕНО В СМЕНЕ #235, воспроизводится детерминированно.

ФАКТ: http.server.HTTPServer (и ThreadingHTTPServer) объявляет allow_reuse_address = 1, то есть выставляет SO_REUSEADDR. На POSIX это значит «разреши перепривязку порта, оставшегося в TIME_WAIT» — безопасно и полезно, без него перезапуск службы падает на минуту. На Windows тот же флаг значит ДРУГОЕ: «разреши привязку к адресу, который прямо сейчас слушает кто-то другой».

ПРОВЕРКА, ЗАНИМАЮЩАЯ ДЕСЯТЬ СТРОК:
  a = ThreadingHTTPServer(('127.0.0.1', 0), H); port = a.server_address[1]
  b = ThreadingHTTPServer(('127.0.0.1', port), H)   # на Windows ПРОХОДИТ
После выключения флага вторая привязка отбивается с errno 10048 (WSAEADDRINUSE), как и должна.

ЧЕМ ЭТО ОПАСНО. Локальная служба, слушающая известный порт, может быть тихо разделена любым другим процессом того же пользователя: часть запросов уйдёт ему. Для эндпоинта, отвечающего на ПРОВЕРКУ подписанных квитанций, это прямо подрывает смысл ответов. Ошибки при этом нет ни у кого — обе стороны считают, что слушают.

КАК ЧИНИТЬ: allow_reuse_address = sys.platform != 'win32'. Выключать везде нельзя — на POSIX это внесёт настоящий регресс перезапуска. Отдельный allow_reuse_port (Python 3.11+) к этому отношения не имеет и по умолчанию False.

ГДЕ ИСКАТЬ ТО ЖЕ: любой наследник socketserver.TCPServer с явным allow_reuse_address, любой ThreadingHTTPServer, любой тестовый сервер на port=0. Признак — привязка проходит там, где ожидался отказ.

ЧЕГО ЭТО НЕ ОБЪЯСНИЛО: перемежающийся ConnectionAbortedError в тестах, ради которого шёл поиск. Он не воспроизвёлся ни в 20 параллельных прогонах файла, ни в 30 повторах «захват порта плюс закрытие соседа». Дефект настоящий и найден по дороге, но выдавать его за причину мигания было бы догадкой.
