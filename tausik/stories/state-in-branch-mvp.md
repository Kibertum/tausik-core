Минимально жизнеспособный durable-этаж. По завершении story два инженера на разных ветках могут вести задачи/решения/память своего функционала, и git merge сводит их состояния так же, как код — без затирания, с локализацией конфликтов в отдельную сущность.  Порядок задач по зависимости: 1. state-git-spec — контракт: раскладка файлов, формат, round-trip, границы объёма (СНАЧАЛА, всё downstream зависит от формата). 2. state-git-stable-ids — стабильная идентичность решениям и памяти + миграция (НЕСУЩЕЕ). 3. state-git-export — сериализатор БД → файлы. 4. state-git-import — идемпотентная пересборка БД ← файлы (tausik sync). 5. state-git-triggers — экспорт при записи (хуки), импорт при старте. 6. state-git-roundtrip-gate — разгитигнорить tausik/, гейт round-trip (файлы == БД).  Задачи 1–4 дают рабочий ручной цикл (export/import руками); 5–6 автоматизируют и защищают от дрейфа.
