## Decision

Против тихого проглатывания кода возврата subprocess — УЗКИЙ инвариант, не общий. Общее правило ('if rc!=0: continue' запрещено) отвергнуто: AST-обход показал, что оно шумит (метрики, форматтеры, фоновый rebuild, опциональный init законно игнорируют исход). Закреплено: отброшенный (statement) subprocess.run обязан передать check= ЯВНО. Голый run с отброшенным результатом = молчаливый дефолт = глоток. Popen освобождён, check_output/check_call сами бросают. По образцу BLE001: решение видимо, а не запрещено.

## Rationale

Гейт с ложными срабатываниями это инверсия мока, который он заменяет (урок дня, дважды). Обход 15 вызовов: под общим правилом 5 совпадений, ВСЕ законные — шумит. Под узким два, оба auto_format best-effort, им добавлен явный check=False с комментарием (маркер, как noqa BLE001). Улов класса: skill_git::pin_eol_config звал subprocess.run(git config) без check и отбрасывал результат — латентный баг в моём CRLF-коде: при неудаче пина следующий git pull переконвертирует байты, подписи ломаются молча (git config в не-репо даёт rc=128). Починено: результат проверяется, печатается предупреждение. Тест на AST, проба стережётся known-bogus кейсом.
