## Decision

МОДЕЛЬ ПУБЛИКАЦИИ 1.9 УТОЧНЕНА ВЛАДЕЛЬЦЕМ, смена #251. (1) Сайт tausik.tech живёт ТОЛЬКО в отдельном репозитории GitLab (tausik/site); в core и github/main следов сайта нет — проверяется замером, удерживается тестом-храповиком. (2) В GitHub едет чистое дерево: публичный снимок НЕ содержит проекцию бухгалтерии tausik/{tasks,stories,epics,decisions,memory,graph-snapshots} (3075 файлов, 70% дерева), TODO.md, TAUSIK-plan-1.9.md, .gitlab-ci.yml; храповики tausik/*.json остаются — их читают гейты и тесты. Фильтр — код с тестом; снимок проходит собственный полный прогон до выкладки. (3) GitLab хранит всю историю; в GitHub отгружается только тег финальной версии — сплющенный снимок отфильтрованного дерева fast-forward-ребёнком поверх публичной головы (#260, #267: дерево, а не коммит; force запрещён). «GitLab идентичен GitHub» = снимок равен отфильтрованному дереву тега байт в байт, проверяется машиной. Посылка «публикуется всё дерево, включая tausik/» для GitHub отменена; state-in-branch на GitLab остаётся.

## Rationale

Замер смены #251: github/main несёт 2438 файлов tausik/ из 3576 — потребитель получает чужую бухгалтерию вместо фреймворка, а классы утечки (пути среды разработки, внутренний хост) живут именно в ней. Сайт уже вынесен (истории extract-site-gitlab и core-github-cleanup закрыты) — остаётся зафиксировать отсутствие следов. Отгрузка «только тегом» делает публичную линию тем, чем она объявлена: зеркалом релизов, а не второй историей.
