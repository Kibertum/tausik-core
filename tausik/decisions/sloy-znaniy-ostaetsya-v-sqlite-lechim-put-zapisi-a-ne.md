## Decision

Слой знаний остаётся в SQLite; лечим путь ЗАПИСИ, а не хранилище: знание компаундится в страницу-тему через upsert вместо накопления нумерованных записей. Git как канал обмена знаниями НЕ используется — обмен идёт через Shared Brain и системное окружение, поэтому kb-uid-model остаётся полноценным блокером выгрузки. Всё делается в релизе 1.8.

## Rationale

Владелец выбрал «взять дешёвое, не мигрируя» после разбора паттерна LLM-wiki Карпати (gist 442a6bf5). Миграция 227 записей в markdown отвергнута: цена реальна (записи, decisions, ~20 MCP-тулов, скиллы), а источник истины у нас сам код в git, тогда как паттерн рассчитан на внешние неизменяемые источники.

ОГРАНИЧЕНИЕ, ЗАДАННОЕ ВЛАДЕЛЬЦЕМ: git как shared brain не используем. Из паттерна Карпати это исключает главный аргумент в пользу файлов («вики это git-репозиторий, слияние достаётся бесплатно»). Следствие, зафиксированное честно: ранее высказанный вывод, будто slug темы делает kb-uid-model почти ненужным, ОТОЗВАН. Без git-слияния идентичность при синхронизации нужна настоящая, обмен идёт через Shared Brain (Notion) и системное окружение, схлопывание по имени само не происходит. kb-uid-model остаётся блокером до первой выгрузки.

ДИАГНОЗ УТОЧНЁН В ХОДЕ РАБОТЫ. Проблема формулировалась как дисциплина агента, но при попытке применить новую дисциплину выяснилось: в API памяти ОТСУТСТВУЕТ ОПЕРАЦИЯ UPDATE. Есть add, delete, archive (только по возрасту), link, dedupe, compact, lint — переписать запись нельзя. Единственный технически доступный способ зафиксировать новое знание по существующей теме это завести ещё один номер. Накопление структурно предопределено API, никакая дисциплина его не обходит. Поэтому memory_update/upsert — первая задача, а не вопрос договорённости.

Подтверждающие симптомы: дедуп O(n^2) на SequenceMatcher (l26-memory-dedupe-perf) и планируемое забывание/консолидация (l26-memory-decay) лечат следствие; инъекция памяти режет записи посередине слова.

Демонстрация на живом примере: #224, #225, #227 — одна тема, сведены в #228. Сводка немедленно вскрыла ПРОТИВОРЕЧИЕ, невидимое в отдельных записях: #225 утверждает «git checkout -- откат бесплатен, правки незакоммичены», а #227 описывает, как тот же приём снёс 28 незакоммиченных вставок. На одной странице конфликт виден и разрешён, тремя строками нет.

Проектные решения, делегированные мне: (1) topic обязателен на ВХОДЕ, колонка nullable ради 227 легаси, легаси получает тему лениво при касании, миграция не проектом; (2) lint-гейт гибридный: block СРАЗУ на дубль темы (легаси-долга у этой проверки нет по построению, две записи с одной темой всегда свежая ошибка), warn на записи без темы и устаревшие ссылки до схождения долга; (3) детект устаревания начинать с backtick-ссылок на файлы и символы, отсутствующие в дереве.

Преимущество над гистом: Карпати пишет, что lint обязателен, а руками — гарантированный дрейф, и предлагает максимум таймер. У нас есть машина гейтов с триггерами и severity, поэтому lint как гейт строго сильнее.

Открытые вопросы (ключевание тем, надёжность детекта устаревания, идентичность при обмене, антипаттерны) вынесены в исследование роем; последовательность задач собирается по его отчёту.
