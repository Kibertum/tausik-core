## Decision

Sibling-MCP развилка (AC1): выбран REPORT + жёсткое пороговое предупреждение при sibling_count>N, БЕЗ авто-реапинга внутри фреймворка. Фреймворк НИКОГДА не убивает процессы; оператор судит и убивает вручную по OS. AC3 сводится к TTL-кэшу энумерации.

## Rationale

Свежая форензика (2026-07-18, Win11 26200): осиротевших MCP НЕТ — все 'сиблинги' это ЖИВЫЕ server.py под ЖИВЫМИ claude.exe одного окна Code.exe; протухшую-но-живую сессию нельзя отличить от активной по дереву процессов. Поэтому ЛЮБОЙ авто-killer = риск потери данных (убьёт живую сиблинг-сессию, оборвёт WAL-коннект и in-flight работу). Единственный безопасный контракт — сообщать и предупреждать, не убивать. Это делает инвариант 'живые сиблинги не убиваются' истинным по построению, без dead-code киллера. Реальная боль (/start похож на зависание) — не в отсутствии реапинга, а в том, что _enumerate_sibling_mcps поднимает свежий powershell Get-CimInstance на КАЖДЫЙ вызов (wmic удалён из Win11 26200 образа); TTL-кэш процесс-скоупа устраняет это.
