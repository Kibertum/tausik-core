## Decision

harness/claude/mcp — ЕДИНСТВЕННОЕ каноническое дерево MCP. Зеркало harness/cursor/mcp (19 файлов) удалено, а не синхронизировано хелпером. Каждая IDE получает канон через существующий фолбэк copy_mcp: `if not isdir(harness/<ide>/mcp): use harness/claude/mcp`. Так уже жили kilo, qwen и opencode — cursor был единственным исключением.

## Rationale

Ревьюер предложил вынести дублирующиеся заглушки list_prompts/list_resources в общий хелпер (шесть дословных копий). Это лечило симптом. Померил причину: harness/cursor/mcp побайтово равен harness/claude/mcp — 19 файлов, diff -r даёт РОВНО ОДНО различие, слово в докстринге («cursor sibling» вместо «claude sibling»). То есть дублировались не заглушки, а всё дерево целиком.

Хелпер оставил бы 19 копий на месте и добавил бы к ним ещё один тест на синхронность — то есть узаконил бы ручную синхронизацию как норму (память #146 буквально предписывала «синхронизировать 3 зеркала» при добавлении MCP-тула). Опасность не в дублировании как таковом, а в ПРИОРИТЕТЕ: copy_mcp предпочитает harness/<ide>/mcp канону, поэтому в день, когда кто-то поправит только claude-копию, пользователи Cursor молча продолжат получать старый сервер — и ни один тест этого не заметит, потому что каждое зеркало по отдельности проходит свои проверки.

Проверено: copy_mcp для cursor/qwen/kilo/opencode/claude во временных каталогах отдаёт по 3 server.py — все пять IDE получают канон. Ноль поведенческих различий, минус 19 файлов, минус целый класс дрейфа.

Гард tests/test_mcp_single_canonical_tree.py не даёт зеркалу отрасти обратно: ни один файл в harness/<ide>/mcp не смеет быть побайтовой копией файла из harness/claude/mcp. IDE, которой ДЕЙСТВИТЕЛЬНО нужен свой сервер, может его завезти — но не копию нашего. Идентичность содержимого и есть подпись неуправляемого зеркала. Негативный тест сажает подсунутую копию — гард краснеет.
