## Decision

ПОЛНОТА ТЕЛА SPEC ПРОВЕРЯЕТСЯ ПО ПЕРЕЧИСЛИМОМУ ПРЕДМЕТУ, А НЕ ПО ЛЕКСИКЕ; ОХВАТ ЧЕСТНО ОБЪЯВЛЕН ДЕВЯТЬЮ ТИПАМИ ИЗ ОДИННАДЦАТИ

## Rationale

ADR-023 §5 вводит §8.4.1 без оговорки об уровне RENAR, то есть обязывает нас. Замер: SPEC трогают ровно два гейта, оба warn, оба про другое (схема и свежесть связей); renar_drift.py:91 сверяет ТИП. §4 того же ADR отвергает чёрный список прилагательных: те же слова законны, когда называют свойство предмета, и незаконны, когда сужают охват, — значит реализация через лексику критерию не удовлетворяет, даже поймав все сегодняшние случаи. Поэтому SPEC объявляет в закоммиченном tausik/spec_coverage.json ПЕРЕЧИСЛИМОЕ множество своего предмета и enumerator, читающий его по ЖИВОМУ коду (config_trust.GUARDS, state_serialize.ENTITY_DIRS). Прилагательное не убирает члена: тело вправе звать элемент «самым критическим» и быть зелёным. Семейный ключ gates.*.enabled сопоставляется через один сегмент пути — проза пишет плейсхолдер как gates.<имя>, и требовать звёздочку буквально значило бы проверять типографику. Отчёт — имя SPEC и имя элемента, никогда процент. Охват 9 из 11.
