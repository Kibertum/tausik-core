# TAUSIK

**AI-агенты, которые не соврут «готово» *незаметно*.**

TAUSIK — это discipline-слой для AI-кодинг-агентов. Он превращает слова агента — «тесты прошли», «задача готова» — в то, что вы можете проверить. Планировать перед кодом, выпускать с доказательством, помнить каждое решение. Не рекомендации, которые агент волен игнорировать, а дисциплинарный рельс: он отказывает в лёгком срезе угла, а те, что не может отклонить, делает видимыми и записанными — с tamper-evidence против внешних правок, а не firewall, обещающий остановить целеустремлённого агента.

## Без TAUSIK / С TAUSIK

| Что делает агент | Что делает TAUSIK |
|---|---|
| Говорит «сейчас по-быстрому отрефакторю» и правит 30 файлов | **Нет активной задачи → BLOCKED.** Без открытой задачи редактировать код нельзя. |
| Объявляет «готово», не показав ничего | **QG-2 блокирует закрытие.** Под каждый критерий приёмки нужны доказательства. |
| Рапортует зелёную сборку, в которую остаётся просто поверить | **ed25519-receipt с подписью.** Зелёное криптографически привязано к гейту и коммиту — внешняя правка базы не подделает и не переиграет его. |
| Третий раз подряд пробует один и тот же сломанный подход | **Память проекта.** Неудачные подходы записаны — агент видит, что не сработало. |
| Молча пропускает прогон тестов и линтера | **Отдельный шаг `verify`.** Тяжёлые гейты идут своим триггером и кэшируются — пропуск виден, а не происходит втихую. |

Разница в одном слове: **доказательство.**

## Попробовать за 30 секунд

Скажите агенту:

```
Добавь https://github.com/Kibertum/tausik-core как git submodule в .tausik-lib,
запусти python .tausik-lib/bootstrap/bootstrap.py --init,
добавь .tausik/ в .gitignore
```

Он выполнит все три шага. Перезапустите IDE, чтобы поднялись MCP-серверы, — готово. Дальше весь инженерный цикл — в три сообщения:

```
начинай работу
```
```
исправь баг — кнопка не работает на мобильной версии
```
```
готово, отправляй
```

Агент откроет сессию, заведёт задачу с критериями приёмки, напишет код, прогонит тесты и ревью, проверит каждый критерий по доказательствам, закоммитит и предложит запушить. Вы сказали, что хотите, — фреймворк заставил пройти шаги, которые пропускаешь, когда слишком доверяешь агенту.

## Проверяемое доверие

Именно это отличает TAUSIK от любого набора правил на промптах.

- **`tausik verify` выпускает ed25519-receipt с подписью** (`tausik-signed/v1`), привязанный к точной сигнатуре гейта и sha коммита HEAD.
- **`task done` проверяет этот receipt, прежде чем дать закрыть задачу.** Зелёное, которого на самом деле не было — или которое было для другого коммита, — проверку не пройдёт.
- **Receipt'ы переносимы.** Экспортируйте один и проверьте офлайн без SDK — через stateless HTTP-эндпоинт или пример без зависимостей.
- **Релизы скиллов и стеков тоже подписаны** — установка проверяет подпись до того, как что-либо запишется на диск.

**Что это значит для вас:** когда агент говорит, что сборка зелёная, верить на слово не нужно. У вас есть подписанный receipt, который это доказывает — или доказывает, что агент соврал.

**[Как работают подписанные receipt'ы →](docs/ru/receipts.md)**

## Как это работает

**Планирование перед кодом.** `/plan` начинается с интервью — агент уточняет поведение, граничные случаи и ограничения, затем заводит задачи с критериями приёмки. Никакого кода, пока не определено «готово».

**Выпуск с доказательством.** `/ship` запускает параллельное код-ревью, тесты, проверяет каждый критерий по доказательствам, коммитит и предлагает запушить — одна команда, весь пайплайн и подписанный receipt в конце.

**Помнит всё.** Решения, паттерны, соглашения и тупики живут в локальной SQLite + FTS5 и подгружаются при старте сессии. Новая сессия — тот же контекст, без пересказа проекта заново.

**Дисциплина, а не советы.** Два quality gate и набор real-time хуков отклоняют частые срезы угла (нет кода без задачи, нет закрытия без доказательства) и делают те, что не могут отклонить, видимыми и записанными. Никакого `--force`, никаких «не забудь, пожалуйста, прогнать тесты». Модель угроз — тихий дрейф честного агента, а не целеустремлённый обход рельса.

## Два гейта

**QG-0 — до начала работы.** Нет цели и критериев приёмки → задачу не стартовать.

```
$ tausik task start fix-mobile-button
BLOCKED (QG-0): у задачи нет критериев приёмки.
Определи, что значит «готово», до написания кода.
```

**QG-2 — до закрытия задачи.** Нет verify-доказательств → задачу не закрыть.

```
$ tausik task done fix-mobile-button --ac-verified
BLOCKED (QG-2): нет валидного verification-receipt для HEAD a1b2c3d.
Сначала запусти `tausik verify --task fix-mobile-button`.
```

Оба гейта fail-closed: гейт, который не может вынести вердикт, блокирует, а не пропускает задачу.

## Proof: TAUSIK собран на TAUSIK

TAUSIK создавался самим TAUSIK — каждая фича, рефакторинг и фикс прошли через гейты, которые поставляются в коробке. Не ради красивой цифры, а как самая жёсткая проверка контракта:

- **Каждая задача закрыта с целью + критериями приёмки.** Ни одна не закрыта без verify-доказательств.
- **10146 тестов** — ядро дисциплины покрыто тестами плотнее всего.
- **0 зависимостей в ядре** — только stdlib Python 3.11+; MCP-зависимости живут в изолированном `.tausik/venv/`.
- **0 обращений наружу** — всё работает и остаётся на вашей машине.

## Почему не .cursorrules / AGENTS.md?

Это **рекомендации** — текст, который агент читает и волен проигнорировать, как только это становится неудобно. TAUSIK — это **жёсткие блоки**: хуки перехватывают правки, гейты отказываются закрываться, receipt'ы доказывают зелёное. Свод правил превращается в рельсы.

## Что внутри

- **Жизненный цикл и гейты** — Epic → Story → Task со state machine; QG-0 на старте, QG-2 на закрытии, оба fail-closed.
- **Проверяемое доверие** — ed25519-receipt'ы с подписью, проверяемые офлайн, плюс supply-chain-подпись скиллов и стеков.
- **Память проекта** — хранилище SQLite + FTS5 решений, паттернов, соглашений и тупиков, подгружаемое каждую сессию.
- **Общая база знаний** — один файл на человека, а не на проект. `--global` кладёт паттерн или тупик туда, где его найдёт СЛЕДУЮЩИЙ проект; поиск читает оба хранилища. Машину она не покидает, и бэкап остаётся здесь же. **[Чем отличается от проектной →](docs/ru/knowledge-store.md)**
- **Real-time-рельсы дисциплины** — хуки для гейта «нет кода без задачи», bash-firewall, одноразовый push-тикет и auto-format.
- **Метрики и роутинг** — throughput, first-pass success, defect-escape и lead time считаются автоматически; бюджеты $/токенов на задачу; роутинг модели по сложности в рамках семейства вендора (Claude и [z.ai GLM](docs/ru/kilo-zai.md), как данные — без правки кода).

## Установка

```bash
cd your-project
git submodule add https://github.com/Kibertum/tausik-core .tausik-lib
python .tausik-lib/bootstrap/bootstrap.py --init
```

Bootstrap сам определит ваш стек и включит подходящие гейты; имя проекта берётся из папки. После установки перезапустите IDE, чтобы поднялись MCP-серверы. Конкретный хост — через `--ide claude|cursor|qwen|kilo|opencode|codex` (или `--ide all`; например, `--ide kilo` для [Kilo Code + z.ai GLM](docs/ru/kilo-zai.md), `--ide codex` для Codex CLI).

**[Полный быстрый старт →](docs/ru/quickstart.md)** · **[Быстрый старт для агента →](docs/ru/agent-quickstart.md)** (для ИИ-агента: подключение на своём хосте и цикл точными вызовами)

## Методология

TAUSIK — это эталонная реализация [SENAR v1.3 Core](https://senar.tech) ([GitHub](https://github.com/Kibertum/SENAR)), открытого инженерного стандарта для разработки с ИИ. Гейты, сессии, метрики и чеклисты верификации — всё из спецификации; чтобы пользоваться фреймворком, читать её не нужно.

**TAUSIK заявляет SENAR v1.3 Core** — эту редакцию и никакую другую. Более поздние редакции готовятся и не заявляются ни здесь, ни где-либо ещё в проекте: заявление о соответствии стандарту, который ещё движется, — ровно тот класс утверждений, который этот фреймворк и создан отклонять. Каждое место, называющее редакцию, сверяется с одной константой тестом `tests/test_senar_version_claim.py`.

**[Подробнее о SENAR →](docs/ru/senar.md)**

## v1.9 — релиз, переставший верить себе на слово

1.8 отвечала на вопрос «принуждает ли фреймворк к дисциплине». 1.9 делает два
утверждения о продукте и требует, чтобы каждое было измерено. Одно из двух пока
не измерено, и эта страница говорит об этом сама, а не оставляет на обнаружение.

**Граф артефактов стал механикой фреймворка, а не таблицей в нашей базе.**
`tausik graph` отвечает, что прочитать, чтобы изменить файл, и что изменение
сломает, — из трёх видов свидетельств, которые не смешиваются: что git видел
меняющимся вместе, что объявила задача и куда прогон теста реально дошёл. Корни
берутся У ПРОЕКТА, а не предполагаются по нашей раскладке, поэтому чужой проект
индексируется как он сам. Замерено: неранжированный список соседей стоит 2881 КБ
чтения, ранжированный ответ — 927 байт.
**[Граф →](docs/ru/graph.md)**

**Доказательство перестало быть утверждением о самом себе.** Гейт теперь
объявляет, КАКОЕ ИЗМЕНЕНИЕ не происходит, пока его вердикт отрицателен, и у
каждого блокирующего гейта есть тест, подсовывающий ему нарушение и требующий
красного. Тест, ни разу не бывший красным, не показал, что умеет падать, — и эта
история теперь записывается. Чек говорит, КТО прогнал проверку, поэтому
разделение обязанностей стало проверяемым свойством, а не фразой в документации;
первое, что оно показало, — на пути verify разделения нет: из 29 задач с
известными стартовой и закрывающей моделью не различается ни одна.

**Величина, которую нельзя получить, ОТСУТСТВУЕТ, а не равна нулю.** Звучит как
мелочь, пока не посмотреть на числа: телеметрия 55 471 раз утверждала, что работа
стоила $0.00, а пиннинг модели не срабатывал ни разу за 231 смену. Оба дефекта
выглядели ровно как «функция никому не нужна».

**Число экономии токенов ИЗМЕРЕНО ОДИН РАЗ, и на этой паре экономии нет.**
Телеметрия числа не производит (из 57 251 строки входные токены несут 233, базы
«без TAUSIK» нет ни одной); его дал парный replay на фиксированном корпусе
([протокол, §7](docs/ru/research/rag-nudge-replay-protocol.md)): с rag-first
подсказками 198 848 против 195 055 токенов (+1,9 %), 326 323 против 292 715
байт результатов исследования (+11,5 %), а `search_code` не вызван ни разу ни
с ними, ни без них. Один отсчёт на одном корпусе — как факт публикуется только
он.

**[Что изменилось в 1.9 →](docs/ru/whats-new-1.9.md)**
([English](docs/en/whats-new-1.9.md)) — включая ломающие изменения и миграции к
ним. Прошлые релизы: **[1.8 →](docs/ru/whats-new-1.8.md)**.

v1.9 продолжает hardening на пути к 2.0: подписанные чеки, fail-closed гейты,
внешнее состязательное ревью для закрытий с тонким доказательством, оценка риска
закрытия, структурный root cause и цепочка поставки навыков, проверяемая
одинаково на любой платформе.

Через правки этого релиза проходит одна тема, и её стоит назвать прямо: механизм,
который работает и которого никто не зовёт, неотличим от неработающего. Граф был
построен и содержал ноль строк. Таблица схемы, добавленная одной лишь миграцией,
отсутствовала у каждой свежей установки и отказывала молча. Детектор выдуманных
цитат закрытия существовал, и никто его не звал. У всех трёх теперь есть
вызывающий и тест, краснеющий без него. Что доказывает рельс — ограничено
намеренно: это свидетельство неподделанности против правок извне, а не аттестация
против агента, держащего ключ ([чеки](docs/ru/receipts.md)). На нечастых путях
всё ещё возможно расхождение документации с поведением — если встретите,
[заведите issue](https://github.com/Kibertum/tausik-core/issues), и мы сведём это
до 2.0.
