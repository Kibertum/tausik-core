# TAUSIK

**ИИ-агенты, которые не могут *тихо* соврать «готово».**

TAUSIK встаёт поверх ИИ-агента, которым вы уже пользуетесь — Claude Code, Cursor, Codex и других, — и проверяет его работу. Прежде чем править код, агент обязан открыть задачу с определением «готово», а прежде чем закрыть её — показать пройденные проверки. Каждое решение и каждый провальный подход запоминаются для следующей сессии. Для разработчиков, которые не хотят верить «тесты проходят» на слово.

**Где это стоит.** Поле называет эту дисциплину *harness engineering*: харнесс — это цикл агента, интерфейс инструментов, управление контекстом и механизмы контроля. TAUSIK — не харнесс: цикл и инструменты принадлежат Claude Code, Cursor, Codex и другим. Это слой проверки и контроля поверх них, и его отличие в том, что без доказательства ничто не считается сделанным.

## Посмотрите, как он ловит ложь

Это настоящий вывод `tausik demo` (около 10 секунд, без сети и без ключа LLM, в одноразовой песочнице):

```
== The agent says "tests pass" without running them, and tries to close.
   Error: QG-2 Implementation Gate failed: verify-first — QG-2: task 'fix-add' declares no relevant_files, so no verify run can certify it...

== The real check runs. The claim was false.
   FAILED tests/test_calc.py::test_add - assert 0 == 4
   1 failed in 0.09s
   Receipt: signed (run #2, key bacfee7a6aef38ea).

== The agent actually fixes the bug. Now the close goes through, with a receipt.
   Receipt: signed (run #3, key bacfee7a6aef38ea).
   Task 'fix-add' completed.
```

Агент говорит «тесты прошли», не запуская их, и пытается закрыть задачу — отказ; настоящая проверка красная; закрытие проходит только после реальной правки. Запустите сами после установки: `.tausik/tausik demo`.

## Установка

Нужны Python 3.11+ и git. По умолчанию bootstrap настраивает Claude Code; для другого хоста добавьте ко второй команде `--ide claude|cursor|qwen|kilo|opencode|codex` (или `--ide all`). Запустить его позже ещё раз с другим `--ide` безопасно. В своём проекте:

```bash
git submodule add https://github.com/Kibertum/tausik-core .tausik-lib
python .tausik-lib/bootstrap/bootstrap.py --init
echo ".tausik/" >> .gitignore
```

Затем **перезапустите IDE**. IDE общается с TAUSIK через MCP (Model Context Protocol — стандартный способ, которым ИИ-агент вызывает внешние инструменты), а новые MCP-серверы подхватывает только при запуске.

Bootstrap сам определит стек и включит подходящие проверки.

## Проверить, что заработало

```bash
.tausik/tausik status          # macOS, Linux, Git Bash
.tausik\tausik.cmd status      # Windows cmd или PowerShell
```

Должно появиться `Tasks: 0/0 done`. Если команда не найдена — bootstrap не завершился: запустите его ещё раз и прочитайте последние строки вывода.

## Первая задача

Скажите агенту три фразы:

```
начинаем работу
```
```
исправь баг — кнопка не работает на мобильном
```
```
отправляй
```

Агент открывает сессию, пишет задачу с критериями приёмки (список, который определяет «готово»), вносит правку, прогоняет тесты и ревью, проверяет каждый критерий и делает коммит. Вы описываете результат; TAUSIK заставляет агента пройти шаги, которые он иначе пропустил бы.

**[Полный быстрый старт →](docs/ru/quickstart.md)** · **[Быстрый старт для агента →](docs/ru/agent-quickstart.md)** (написан для самого ИИ-агента)

## Что меняется для вас

| Ваш агент делает так | TAUSIK делает так |
|---|---|
| «Сейчас быстро отрефакторю» — и правит 30 файлов | **Отказ.** Никаких правок кода, пока не открыта задача. |
| Объявляет «готово», не показав ничего | **Отказ.** Задача не закроется, пока у каждого критерия приёмки нет доказательства. |
| Сообщает о зелёной сборке, которой приходится верить на слово | **Подписанная квитанция.** Результат подписан и привязан к конкретному коммиту: его нельзя взять из старого прогона или поправить задним числом. |
| В третий раз пробует тот же сломанный подход | **Память проекта.** Провальные подходы записаны; агент видит, что не сработало. |
| Тихо пропускает тесты | **Отдельный шаг проверки.** Пропуск виден, а не тих. |

Разница в одном слове: **доказательство.**

## Две контрольные точки

**Перед началом работы:** нет цели или критериев приёмки → задачу нельзя начать.

```
$ .tausik/tausik task start fix-mobile-button
BLOCKED (QG-0): task has no acceptance criteria.
Define what "done" means before writing code.
```

**Перед закрытием:** нет пройденной проверки для текущего коммита → задачу нельзя закрыть.

```
$ .tausik/tausik task done fix-mobile-button --ac-verified
BLOCKED (QG-2): no valid verification receipt for HEAD a1b2c3d.
Run `tausik verify --task fix-mobile-button` first.
```

В сообщениях они называются QG-0 и QG-2 (quality gates, контрольные точки качества). Если точка не может принять решение, она отказывает, а не пропускает задачу.

**Чего это не обещает.** TAUSIK удерживает честного агента от сползания. Это не песочница против агента, который намеренно её обходит: такие попытки становятся видимыми и записанными. Экономию токенов TAUSIK тоже не обещает: единственный замер (в 1.9) показал, что на этой паре (одни и те же задачи с измеряемой функцией и без неё) экономии нет — 198 848 против 195 055 токенов (+1,9%), 326 323 против 292 715 байт, прочитанных при исследовании (+11,5%), а инструмент поиска по коду (`search_code`) не был вызван ни разу. Полный список — в **[Известных ограничениях →](docs/ru/known-limitations.md)**.

## Подписанные квитанции

`tausik verify` прогоняет ваши проверки и подписывает результат ключом ed25519 с привязкой к коммиту. `task done` проверяет подпись перед закрытием задачи. Квитанцию можно проверить офлайн командой `tausik receipt verify <file>`; с публичным ключом проекта (`--pub`) проверка доказывает ещё и то, кто её выдал.

**[Как устроены подписанные квитанции →](docs/ru/receipts.md)**

## Чем это не .cursorrules / AGENTS.md?

Те — **пожелания**: текст, который агент читает и волен проигнорировать, когда неудобно. TAUSIK **отказывает**: хуки (скрипты, которые IDE запускает перед каждым действием агента) не дают править без задачи, закрытие не проходит без доказательств, а квитанции подтверждают результат.

## Что внутри

- **Задачи с жизненным циклом** — Эпик → История → Задача; задачу нельзя начать без определения «готово» и закрыть без доказательств.
- **Подписанные квитанции** — проверяются офлайн; выпуски навыков и стеков тоже подписаны.
- **Память проекта** — решения, паттерны, соглашения и тупики в локальной базе SQLite, подгружаются в каждую новую сессию.
- **Общая база знаний** — одна на человека, общая для проектов, только на вашей машине. **[Чем отличается от памяти проекта →](docs/ru/knowledge-store.md)**
- **Хуки** — нет кода без задачи, защита от рискованных shell-команд, одноразовый билет на каждый push, автоформат.
- **Метрики и выбор модели** — пропускная способность, успех с первой попытки, цена задачи; для простых задач советует модель подешевле (Claude, [z.ai GLM](docs/ru/kilo-zai.md)).

## Доказательство: TAUSIK построен на TAUSIK

Каждая функция и каждое исправление TAUSIK прошли через те же контрольные точки, что поставляются в коробке.

- **Каждая задача закрыта с целью и критериями приёмки**, ни одна — без пройденной проверки.
- **13244 тестов**; **76% покрытия строк** `scripts/` (обновить: `pytest tests/ --cov=scripts --cov-report=json:coverage.json`).
- **0 зависимостей ядра** — стандартная библиотека Python 3.11+; MCP-пакеты живут в изолированном `.tausik/venv/`.
- **Одна объявленная точка проверки обновлений** — каждая попытка начать сессию отправляет анонимный GET на `api.github.com/repos/Kibertum/tausik-core/releases/latest`; более новая версия блокирует старт. Запрос не содержит имя проекта, путь, пользователя, версию схемы или установленную версию. `"updates": {"check": false}` в `.tausik/config.json` не отправляет запрос и разрешает старт с явным предупреждением о непроверенной версии. Отдельная кэшируемая проверка остаётся не чаще раза в сутки.

## Стандарт, на котором это стоит

TAUSIK conforms to SENAR v1.5 Core, self-declared, as of 2026-09-23. [SENAR](https://senar.tech) — открытый инженерный стандарт разработки с ИИ; читать его, чтобы пользоваться TAUSIK, не нужно. Раскрытие, которое стандарт требует при заявлении: Ни одно SHALL не обрабатывается по §13.5, и ни одно SHOULD заявленного объёма не оставлено невнедрённым. **[TAUSIK и SENAR →](docs/ru/senar.md)** · **[Матрица соответствия →](docs/ru/senar-compliance-matrix.md)**
